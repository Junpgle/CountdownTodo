# 第26轮方案：重复待办按范围移入回收站并保持规则稳定

日期：2026-10-20（北京时间）

状态：**已批准并实施；验收结果见 [第26轮验收报告](../reports/2026-10-20-recurring-todo-delete-scope-acceptance.md)**

## 1. 建议与收益

补齐重复待办的删除范围，让用户可以明确选择只移除本期、从本期起移除后续期次，或移除整个系列；同时修正周期维护对软删除实例的处理，避免被删除的期次重新出现，也避免删除当前规则承载项后意外停止整条系列。

这项工作承接已完成的跳过本期、编辑范围和系列编辑界面整理。普通待办仍按现有方式单条移入回收站；结束重复继续作为独立操作，含义是停止后续生成，不等同于删除当前期。

## 2. 当前源码证据

以下是对当前工作树的代码与产品规范核对，尚未声称复现了运行时故障：

| 位置 | 当前状态 |

## 3. 删除范围和规则语义

三个范围均为**移入回收站**，不物理删除；按选中期次的重复序号确定范围，锚点使用 `createdDate ?? createdAt` 的本地日历日期：

1. **仅本期**：只软删除当前期。后续重复继续生成。若当前期正承载活动规则，先把原规则及结束边界交给下一期保留记录；必要时通过现有重复生成路径建立下一期，再提交删除，确保一条系列仍只有一个活动规则。
2. **本期及以后**：软删除所选期及其后的所有未删除期次，包括已生成的完成、跳过记录；保留此前期次。活动规则收口到最后保留的期次，截止边界设为最后保留期，不再生成所选期及之后的记录。所选期之前没有保留期时，按整条系列处理。
3. **整个系列**：软删除所有未删除的已生成期次，包括历史、完成、跳过和未来期次；系列不再保留活动生成规则。已在回收站的记录不重复写入。

删除只改变软删除标记及维持重复链所必需的规则归属／结束边界；不清除标题、备注、日期、完成和跳过状态，不修改关联规划块、番茄、专注和时间日志。提醒与首页、小组件等视图在成功保存后按现有待办刷新链路更新。

“结束重复”保留独立语义：当前期和过去期保留，后续生成停止，已经物化的后续期按现有行为移入回收站。点击时补充确认文案，清楚说明当前期会保留。

## 4. 界面与操作

- 普通待办沿用当前单条滑动删除和确认文案。
- 重复待办从首页或文件夹滑动删除时，打开统一的范围选择与复核界面；默认选中低影响的“仅本期”，每个选项显示影响期数及完成、跳过数量。范围以实际记录预览，不把“未来”误解成从今天起，而是从当前选中的重复期次起。
- “整个系列”不会默认选中。用户先明确选中后，再看到独立的最终复核，列出总期数及完成／跳过数量，并说明记录会进入回收站、可逐期恢复。
- 重复待办管理入口增加独立的“删除范围”分组，复用相同选项和复核；“编辑范围”“删除范围”“系列操作”三组视觉上分开。
- 删除按钮统一称“移至回收站”；“在本期结束重复”不放进删除选项，避免把停止未来生成误认为移除当前待办。
- 保存期间禁用重复提交。取消不改数据；失败时保留原列表并说明失败原因，成功后给出本期／后续／系列范围反馈。

回收站继续按现有单条入口恢复期次；本轮不增加系列批量恢复，也不增加永久删除入口。

## 5. 持久化、并发与同步

- 复用 `is_deleted`、`recurrence_series_id`、当前 SQLite/oplog 和 Alibaba 同步能力，不新增数据库字段，不修改服务端或 Cloudflare Worker。
- 新增重复删除服务，从数据库重新读取系列成员和版本基线，按作用范围构造变更；通过 `saveTodos` 的事务、基线及系列成员校验一次提交。成员、完成/跳过状态或规则在确认后发生变化时，拒绝过期写入，不做部分删除，并提示重新载入。
- 调整重复维护器：用户明确软删除的确定性实例不能被周期维护复活；只有当前维护过程明确识别的重复数据去重墓碑可以按既有修复策略处理。维护前后保证每条仍有效系列最多一个活动规则承载项。
- 删除和规则收口一起记录 oplog；成功后触发现有跨端同步与视图刷新。旧服务端仍按现有 `is_deleted` 字段处理，不宣称未经部署的跨设备验证已经完成。
- AI 待办动作继续遵守现有限制：默认只删指定期，明确提出时最多覆盖本期及以后；不开放 AI 全系列删除。AI 文案与测试确认它不会把“结束重复”解释为删除。

## 6. 范围边界

预计触及重复删除服务、周期物化维护、首页／文件夹滑动删除、重复管理页、回收站展示反馈和相关测试。实际文件以批准后的实现调查为准。

本轮不做：

- 不永久删除记录，不改变普通单条待办的删除语义。
- 不改变跳过、完成、提醒、AI 写入确认及待办共享完成规则。
- 不删除或自动改期规划块、时间日志、番茄或专注记录。
- 不把结束重复并入删除，也不改重复规则类型、时间输入或系列编辑语义。
- 不增加系列批量恢复、跨端新能力、服务端部署或生产目录改动。

## 7. 验收计划

1. **仅本期**：删除当前规则承载期后，后续期仍按原周期恰好生成一次；强制重新载入和重复维护后，被删期仍在回收站、不自动复活；确认完成、跳过及结束日期均按原期次保留。
2. **本期及以后**：验证选择日期边界、完成／跳过统计预览、保留此前实例、删除边界及无此前实例时的整系列处理；多次运行维护不生成边界之后的期次。
3. **整个系列**：确认历史、当前、未来及已完成／跳过期都进入回收站；没有活动重复规则继续生成；记录仍可在回收站逐期恢复。
4. **维护与去重**：区分用户删除和系统重复去重；已有重复修复、跨日生成、实例去重回归仍通过；每条有效系列恰有一个活动规则承载项。
5. **并发与保存失败**：确认后若成员或版本变化，整个操作拒绝且无部分写入；本地事务失败时 UI 不先行移除；重试不会重复写入或错误改状态。
6. **入口一致性**：首页和文件夹的滑动删除、重复管理页范围选择显示相同范围与数量；一次待办仍只出现单条确认；结束重复仍单独操作并说明当前期保留。
7. **联动**：提醒、主页、搜索、小组件及同步消费删除标记；关联规划、专注和时间日志保持不变；AI 删除仍受 occurrence/future 范围约束。
8. 运行定向模型、重复生成、持久化／同步、回收站和 Widget 测试；执行相关 Dart 静态分析及 Flutter Web release 构建；提供主列表和范围复核界面的实际截图。不能获得真机或部署环境时单独说明边界。
