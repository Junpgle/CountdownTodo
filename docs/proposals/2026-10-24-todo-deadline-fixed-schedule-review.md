# 第40轮方案：待办期限调整后的关联固定日程复核

日期：2026-10-24（北京时间）

状态：**技术验收通过；等待用户验收确认**

## 1. 建议与收益

固定日程改期时，CountDownTodo 已能复核关联待办的期限；反过来，用户编辑关联待办的期限时，目前没有对应提示。比如“考前准备材料”原定在考试开始前完成，用户把期限改到考试开始之后，保存仍会直接通过，容易留下相互矛盾的安排。

建议在待办编辑器的统一保存路径增加只读复核：仅当本次保存确实改变待办期限，且改后的期限落在一个仍未开始、未取消、未删除的关联固定日程开始之后时，展示受影响的日程和待办期限前后值，供用户核对后再保存。

此提示沿用第39轮的“请核对”语义：这是关联信息，不是时间占用冲突；系统不判断期限一定错误，也不自动移动日程、规划、提醒或专注记录。

## 2. 当前实现依据

- `TodoEditScreen` 是首页、搜索、待安排清单、规划清理和冲突收件箱等多处共用的编辑器，已有统一暂存、重复范围编辑、基线并发校验和保存入口。
- 编辑器会根据“仅本期／本期及以后／整个系列”生成实际变更的待办实例，并在存储事务中核对待办版本和系列成员。
- `FixedScheduleItem.relatedTodoIds` 是现有待办—固定日程关系的唯一来源；待办详情已有反向查看关联日程的只读区段。
- `StorageService.getFixedSchedulesByRelatedTodo` 会读取当前账号数据库中的有效关联日程，并让读取／解码错误向上抛出，以区分“确实没有关系”和“暂时读不到”。
- 第39轮已在改期复核中实现关联期限的准确显示规则：定时待办比较具体截止时刻；日期待办比较本地自然日；迟于日程开始仅提示核对，不构成日历冲突。
- `TodoEditScreen._persistCurrentTodo` 当前会在最终待办快照保存前执行可选的文件夹团队同步；因此新复核必须前置到任何写入副作用之前，取消时不得留下部分保存。

## 3. 批准后的目标行为

### 触发条件

1. 仅编辑已有待办并实际改变其 `dueDate` 或日期／时刻语义后才检查；标题、备注、文件夹、提醒、完成状态等单独改变时不弹出复核。
2. 仅对所选重复编辑范围内、确实因本次编辑而改变期限的未完成、未跳过实例检查：仅本期只看本期；本期及以后和整个系列严格使用现有暂存逻辑产生的实例集合，不自行重算或扩大范围。
3. 只提示尚未开始、未取消、未删除且有明确开始时间的固定日程。已结束、正在进行、时间待定或已取消的日程不触发此复核。
4. 定时待办在改后截止时刻晚于日程开始时触发。日期待办仅当改后目标日期晚于日程自然日时触发；同一天内完成不按 `23:59` 与日程具体时刻制造假冲突。
5. 新期限为空、期限未改变，或改后期限已早于／等于日程开始（定时待办）时不弹窗。用户把原先较晚的期限提前并消除了提示条件时，也不额外打扰。
6. 仅对当前账号有权查看、且固定日程与待办团队归属一致的关系展示信息。账号切换时清空已载入的关联标题；团队不匹配的日程不显示。

### 复核界面

1. 保存按钮继续留在原编辑页；只有存在需要核对的关联项时才显示复核弹窗。
2. 每项显示待办标题、关联固定日程标题及开始时间、期限改前／改后的值，以及简短提示“期限晚于日程开始，请核对”。
3. 日期待办显示“某月某日内完成”，不显示伪造时刻；未设置期限显示为“未设置期限”。跨日和本地时区按模型中的本地日期与实际时间展示。
4. 重复待办结果按关联日程系列和标题合并，标明受影响场次数及首末时间；普通日程逐项展示。结果过多时优先显示最多五项，另标注剩余数量，并可在弹窗内继续查看。
5. 按钮为“返回修改”和“确认保存”。确认只表示用户看过提示并继续保存待办，不会自动改变关联固定日程或其它数据。
6. 点“返回修改”只关闭弹窗，保留编辑器中的所有输入；不写待办、文件夹、操作日志、提醒或同步队列。

### 保存与并发保护

1. 复核使用编辑器已经生成的 `changedTodos` 和对应基线，不另行推断重复范围。
2. 复核前批量读取这些待办关联的固定日程。账号读取失败、数据解码失败或无法确定团队可见范围时，不把错误当成空列表；保留全部输入，提示重试或返回编辑。
3. 展示复核后再次读取关联固定日程，并在同一个本地数据库保存事务中比较这批日程的 UUID、版本、更新时间、团队归属、状态、删除标记、开始时间及关联待办 ID。若它们已变化，拒绝沿用旧复核结果，重新展示更新后的结果；连续变化时停止保存并提示用户重试。
4. 待办基线和重复系列成员仍由现有事务校验；两个校验任一失败都不写入本次待办。复核通过后才执行“同步文件夹到团队”等现有写入副作用。
5. 正常保存仍调用现有 `TodoEditorSaveService`／`StorageService.saveTodos` 路径。只有用户编辑器中原有的待办字段会改变；其他事项沿用原同步、提醒和数据刷新流程。

## 4. 数据、安全与兼容边界

- 继续使用固定日程 `relatedTodoIds` 作为唯一关联来源，不增加待办外键、业务字段、迁移、服务端接口或同步协议。
- 为避免对重复系列逐项查询，增加账号作用域的批量关联日程读取；数据库候选读取后仍精确过滤完整 UUID、排除已删除日程，并复用现有团队 UUID 归一化规则。不得用未转义的 UUID 子串命中关系。
- 在现有待办保存事务中加入可选的“关联固定日程快照”期望值校验；普通待办编辑、不触发复核的保存路径保持兼容。
- 期限不参与日历占用、忙闲推荐或硬／软冲突计算。UI 不使用“冲突”“不可安排”等表述。
- 用户确认后不改期限以外的待办属性，不更新固定日程、规划块、提醒配置、专注记录、时间日志或关系。
- 不扩大当前 `TodoEditScreen` 的可见范围；个人与团队数据不跨范围展示，已删除或不可见对象标题不泄露。
- 第39轮 Android 到课提醒工作区改动保持原状；不暂存、不提交、不覆盖。

## 5. 预计实施范围

- `lib/widgets/todo_edit_screen.dart`：从统一待办暂存保存路径接入复核，确保在团队文件夹同步等副作用之前完成，并保留取消后的草稿。
- `lib/services/`：新增待办期限—固定日程复核汇总器，统一处理期限语义、日程有效状态、团队可见性、重复期次汇总和展示排序。
- `lib/widgets/`：新增紧凑、可滚动的复核弹窗，遵循 Material 3 主题，兼容窄屏、深色模式和大字号。
- `lib/storage_service_fixed.dart` 及存储契约：增加批量读取关联日程的严格接口；复用或扩展现有日程事务能力以验证关系快照。
- `lib/storage_service_todos.dart`、`lib/storage_service.dart` 和 `lib/services/todo_editor_save_service.dart`：在现有待办并发保存路径中承载可选日程快照校验；不改变没有快照参数的其它调用者语义。
- `test/services/`、`test/widgets/`：添加纯逻辑、存储并发、共用编辑器保存与布局测试；更新 `docs/features/todo-semantics.md` 和验收报告。
- 验收时运行变更文件格式检查、定向测试、静态分析、`git diff --check` 与 Flutter Web release 构建；生成手机截图并检查窄屏、深色、大字号。

## 6. 验收标准

1. 修改待办标题、备注、文件夹或提醒而不改变期限时，不出现固定日程复核；保存内容与原功能一致。
2. 定时待办新期限晚于关联未来日程开始时，复核准确展示改前／改后期限与日程时间；提前到日程开始前则不显示风险提示。
3. 日期待办使用本地自然日比较；同一日不因内部 `23:59` 产生假提示，目标日期晚于日程日期时才提示。
4. 已完成、已跳过、已删除待办不显示不适用的活动提醒；已结束、进行中、取消、删除和时间待定日程不进入风险项。
5. 仅本期、本期及以后、整个系列均只纳入现有保存逻辑实际会改动期限的实例；系列摘要的数量、首末日期准确。
6. 个人／团队边界正确，团队 UUID 空白规范化一致；账号切换和关系读取失败不会泄露旧数据或伪装成“无关联”。
7. 用户返回修改或读取失败时，待办输入完整保留；复核取消不写待办、文件夹、日志或同步队列。
8. 确认保存后沿用原保存服务；待办版本、系列成员或关联日程快照任一发生变化，事务拒绝提交并保留编辑输入。
9. 文件夹团队同步不会在用户拒绝复核或复核数据不可用时提前写入；正常确认时只执行一次。
10. 窄屏、深色、大字号布局可读，弹窗内容可滚动且操作按钮始终可触达；截图与报告说明截图来源。
11. 定向测试、变更文件静态分析、Web release 构建、格式和差异检查均通过；报告明确列出未覆盖的真机、在线服务和跨设备验证。
