# 第十二轮方案：完成待办后的剩余规划收尾

日期：2026-10-11（北京时间）。第十一轮「长任务分段规划」用户已确认通过。本轮已实施，用户于2026-10-12回复「通过」，**用户验收通过**。交付记录见[第十二轮验收报告](../reports/2026-10-12-completed-todo-plan-cleanup.md)及[浏览器与相关回归补充验收](../reports/2026-10-12-plan-cleanup-browser-acceptance.md)。多设备和原生提醒尚未实机验证的边界仍保留。

## 1. 问题与收益

待办提前完成后，之前为它安排的未来规划仍可能占着时段、继续提醒。第十一轮支持多天分段后，一个待办有多段后续安排更常见，逐日寻找和逐条处理会很繁琐。

建议增加「剩余规划收尾」：查看已完成待办的未来安排，预览要处理的具体条目，一次将选中的未开始规划标记为「已取消」。完成待办本身仍保持原来的操作；用户主动收尾，不在完成时强制弹窗或自动批量改数据。

例子：为“准备演讲”安排了今天、明天、后天各45分钟，今天已经完成任务。在待办的「计划安排」中点「处理剩余规划」，核对明后天两条后点「取消选中2段」。两条变成已取消，应用内腾出对应时段；今天的执行记录、实际专注和待办完成状态保留。

## 2. 当前项目依据

此次检查覆盖待办完成保存、专注结束、待规划清单、分段规划、忙闲计算、统计、提醒及手机日历导出。以下是源码现状，不是新功能的运行证据：

| 位置 | 现状与可复用能力 |
| --- | --- |
| `home_dashboard_persistence.dart` | 完成状态持久化及提醒刷新已有流程，没有同待办未来规划的收尾操作 |
| `PomodoroControlService.stop` | 可标记绑定待办完成，仍未批量取消后续规划 |
| `TodoEditScreen` | 已有具体待办的「计划安排」和关联规划列表，适合增加轻量入口 |
| `PlanBacklogRepository` | 只选未完成待办，已完成任务不会在现有待安排／已有安排列表中出现 |
| `TodoPlanBlock` | 已有 `cancelled` 状态、独立UUID、实际投入和日历ID，不需要新状态或分段组ID |
| `PlanAvailabilityRepository`／`PlanReviewRepository` | 取消规划不进入有效占用／执行预算，历史记录可继续展示 |
| `ReminderScheduleService` | 取消状态不生成规划提醒，可提交后强制刷新本调度来源；番茄与习惯来源独立 |
| `CalendarSyncService` | 导出候选已排除取消规划，但系统日历写入是独立设置页操作，不能把本地状态变化宣称为手机事件已删除 |
| `PlanTodoIdentity`及条件写入 | 可复用身份检查与事务守卫；普通批量replace保存不足以保护这次审阅后的批量取消 |

该功能贯通已有规划链路，复用既有模型与同步，不引入远程AI调用。

## 3. 入口、布局与操作

### 两个入口

1. 待办编辑页「计划安排」：具体待办已持久化完成且有剩余安排时，显示「处理剩余规划 · N段」。未保存的完成勾选不触发处理，需先保存待办。入口查询失败显示重试，不冒充0段。
2. 「待规划」页的更多菜单：新增「已完成待办的剩余规划」，打开独立清单。这样从手机、其他设备或专注入口完成的任务也能主动找到；不依赖一次性消息提示。

不在24小时时间轴新增工具栏、滚动容器或改变拖动新建手势。

### 总清单

- 显示有未结束有效规划的已完成具体待办；按最早剩余安排排序，支持标题搜索和文件夹筛选。
- 每行展示标题、剩余段数、最早日期和可处理段数；不可处理的显示具体原因。点击进入该待办的收尾页。
- 首屏最多50个待办，手动加载更多；同名不同UUID及重复待办不同期次独立展示，不按标题或系列合并。
- 个人待办允许本轮批量取消。关联团队待办的剩余规划提供只读核对和原待办入口，明确显示「关联团队待办的剩余规划暂不支持批量处理，请逐条核对」；模型没有规划成员所有权，不根据某一成员完成推断可以取消其他人的安排。

### 单个待办收尾页

采用标准整页路由，顶部显示「待办已完成」，列表按日期分组，每条显示日期、起止、分钟数、状态、提醒与已有投入说明。设置不再铺成长表单。

```text
剩余规划收尾                              返回
准备演讲 · 已完成
可处理2段 · 共90分钟

明天
[✓] 10:00–10:45 · 45分钟 · 待执行
    提前5分钟提醒
后天
[✓] 15:00–15:45 · 45分钟 · 待执行
    提前5分钟提醒

已选2段 · 90分钟               取消选中2段
```

- 每页最多50条规划。首次仅默认选中当前已加载且合格的条目，后来加载的条目不自动选中；选择上限50条，明确展示「已加载X／总计Y」。全选仅作用于已加载合格条目，不能处理未展示记录。
- 可逐条取消勾选；禁用条目保留具体原因和查看入口。底栏固定，显示选中数及分钟数，未选择时按钮禁用。
- 点击取消后，确认框展示条数、分钟数和日期范围；可「返回核对」或「确认取消」。不称作完成规划，也不删除规划。
- 返回／取消确认零写入。成功显示「已取消N段，应用内释放M分钟规划时段」，刷新关联列表、时间轴和忙闲推荐。重叠时段的M取所取消区间并集，不把重复分钟相加；仍有其他占用时明确说明“实际可用以重新查找为准”。
- 常规手机布局紧凑，宽屏限制内容宽度；窄屏和大字体文字换行，选框及按钮可点击。主题色、深色／玻璃及减少动画设置沿用项目规则。

## 4. 哪些能取消

| 条件 | 本轮处理规则 |
| --- | --- |
| 具体待办 | 当前账号内、已完成、未删除、无同步冲突的个人待办；保存前复核数据库真实状态 |
| 时间／状态 | 真实数据库规划，合法正整数时长，`startTime > 当前时刻`，状态为 `planned/reminded/delayed` |
| 已开始或历史 | 起点等于现在也不批量取消；正在执行、暂停、已结束、漏做、跳过、完成及已取消项只能查看 |
| 已有投入 | 实际累计非零、有明确关联专注记录或关联记录ID列表时不纳入；零秒记录也不能当作从未执行 |
| 无法确认投入 | 坏数据、悬空／矛盾关联、记录读取失败或同步冲突标为待核对，禁止批量写入，不按标题猜测关联 |
| 当前专注 | 同待办正专注或暂停，整页处理按钮暂时禁用；提供查看当前专注。运行状态读取失败同样不能当空闲 |
| 重复与分段 | 只处理当前具体待办UUID的选中规划，覆盖手工、AI及分段生成的真实规划；不扩散到其他期次或“同组”未选段 |
| 外部内容 | 不处理课程、固定日程、手机事件、虚拟映射或旧式待办执行区间 |

待办重新变为未完成时，页面说明状态变化并停止收尾。已取消的规划不会因重新打开待办自动复活；仍可通过原规划流程重新安排。

## 5. 保存、并发与失败

增加专门的「条件批量取消」存储方法，每次仅处理一个具体待办、1–50个已展示UUID。读取、确认与提交携带账号／成员、待办及安排集合指纹、各规划版本和完整必要字段。

同一SQLite事务中：

1. 检查账号／成员、待办已完成及个人属性、删除／冲突、当前专注与关联记录资格。
2. 按提交时当前时刻重新检查起点和状态；等待确认时跨过开始时间也拒绝。
3. 比对已审阅的安排集合、选中规划内容／版本及投入。新增、改期、删除、记录变化或完成状态撤回均拒绝整批，展示「安排已变化，请核对后再试」，不偷偷扩大或缩小所选集合。
4. 从数据库最新原记录复制，仅更改状态及既有版本／同步元数据；保留UUID、待办关联、时段、备注、番茄、提醒配置、实际投入、记录ID与日历ID。
5. 每条取消与其既有UPSERT oplog一并写入。任意一条或oplog失败，整批回滚。

提交后只触发一次规划刷新和同步请求。按钮在提交时禁用，关闭页面与重复点击不会重入。对响应丢失后的同一请求，只在全部目标已是本次取消结果、版本与内容匹配且待办条件仍成立时识别已成功，不再递增版本／重复oplog；部分已取消、远端又改动等情况要求重读核对，不据此补写其他条目。

列表采用同一读取事务的稀疏投影、分页及指纹，不加载全部待办或完整番茄历史，不逐条N+1读取。存在读取错误时显示失败，不返回空清单。前台恢复、存储刷新、专注变化及下一规划开始边界触发重读；后台／离页停止计时，无后台轮询。条件变化丢弃旧选择，旧异步响应不能覆盖新账号／筛选。

## 6. 提醒、日历、统计及草稿

- **提醒**：数据库提交后，使用账号检查和 `force:true` 刷新 `reminder_schedule` 来源，撤下已取消规划的待发提醒；保持番茄／习惯来源不受影响。失败显示「规划已取消，提醒更新失败」与「重试更新提醒」，重试只做后续处理，不重复取消。系统已经展示的通知不承诺从通知中心消失。
- **手机日历**：本轮不新增原生事件删除接口。若选中规划有 `calendarEventId`，确认前及结果中显示「手机日历副本不会随本次操作删除」，支持进入既有「日历同步」设置核对。后续导出按既有规则排除已取消规划；保留旧ID，不自动清空整本日历。手机副本仍可能被忙闲读取计作占用，因此只报告应用内取消，不承诺该时间已成为最终可用推荐。
- **复盘**：沿用取消项单列、不计执行预算的口径，不伪造完成率、实际专注或时间日志；历史投入和原始记录保留。
- **草稿**：本轮不批量删除或改写规划草稿。草稿恢复／保存沿用既有待办资格检查，已完成任务不能由旧草稿重复创建新规划。
- **同步**：使用既有规划UPSERT及多设备刷新，离线时显示本地成功；不宣称其他设备或其系统提醒已即时撤销。

## 8. 验收标准

| 场景 | 必须观察到的结果 |
| --- | --- |
| 完成首段后收尾未来两段 | 只取消选中未来段，原已执行段和投入不变；忙闲在应用占用来源中释放相应区间 |
| 两条同名待办／重复期次 | 只修改具体UUID的选中规划，无跨待办／跨期次处理 |
| 部分选择、加载更多 | 只取消明确展示并选中的条目；不会自动选中新页或未加载记录，最多50条 |
| 团队与独立成员完成 | 只读核对，不能因某成员完成取消共享规划；切换身份不沿用旧页 |
| 历史／正在专注／曾有投入 | 不可批量取消；零秒、悬空关联和读取失败均不能绕过 |
| 确认期间起点到达／新增规划／修改投入／撤回完成 | 整批拒绝、数据与oplog零变化，保留核对上下文并允许重读 |
| 第2条写入或oplog异常 | 全部回滚，没有第一条已取消而第二条保留的半成功 |
| 连点／响应丢失重试 | 一次提交；匹配整批已成功时无重复版本和oplog；部分或变化要求核对 |
| 提醒更新失败后重试 | 如实显示已取消，重试不再写规划；其他提醒来源保持原样 |
| 手机日历有导出副本 | 提交前后都说明副本处理边界；不把本地成功显示成手机日历已删除 |
| 返回／取消／筛选／翻页 | 只读零业务写入；错误态、无数据和筛选为空分别展示 |
| 页面离开、午夜及开始边界 | 数据正确刷新，不残留旧账号响应、计时器或旧选择 |
| UI | 390×844手机、1280×900桌面、320宽1.8倍字体深色检查完整文案、底栏、禁用原因与按钮；全天时间轴仍可拖动新建 |
