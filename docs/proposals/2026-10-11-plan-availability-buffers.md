# 第十轮方案：找可用时段支持前后缓冲

日期：2026-10-11（北京时间）。第九轮已由用户回复“通过，准备第十轮方案”验收通过。本轮状态：**方案待审批，尚未实施**。

## 1. 建议与当前依据

给“找可用时段”增加可记忆的任务开始前、结束后缓冲，适合下课后的通勤、会议间切换、专注前准备和结束整理。推荐的仍是实际任务时段，缓冲只参与空闲计算。

例如课程到10:00结束、下一安排11:00开始，要安排30分钟任务。设置“开始前10分钟、结束后5分钟”后，这段空闲内可安排范围为10:10–10:55，首个建议为10:10–10:40。不会推荐紧贴10:00开始，也不会把30分钟任务保存为45分钟。

结合项目现有待办、课程表、固定日程、手机日历、番茄与复盘，这一项能同时改善多个安排来源之间的衔接，复用现有查找流程。实现范围集中在可用时段模型、计算、设置及保存校验。

当前源码核查：

| 位置 | 已有能力与缺口 |
| --- | --- |
| `PlanAvailabilityQuery` | 有日期、时长、窗口、避让及推荐数量，没有前后缓冲字段 |
| `PlanAvailabilityService.find/accepts` | 已统一寻找和校验；当前按真实占用边界计算，允许紧贴上一项结束或下一项开始 |

## 2. 用户界面和操作

### 设置放在哪里

普通整页新建规划仍只展示推荐结果与“自定义寻找时段”。进入自定义弹窗后，在现有时间范围附近增加一组控件：

```text
安排衔接（可选）
开始前留空  [10 分钟 ▾]    结束后留空  [5 分钟 ▾]
用于与课程、日程和其他规划保持间隔。
```

- 两侧分别选择0／5／10／15／30分钟，也支持自定义整数0–120分钟；0显示“不留空”。
- 首次使用两侧均为0，保持现有推荐结果；一侧可单独开启。
- 控件宽度够时并排，小屏大字体换行；不增加新建页内嵌长表单，不新增常驻面板或顶栏按钮。
- 已有规划“找可用时间”展开面板使用同一组控件和规则，沿用现有展开动画与减少动画设置。
- 非零时，在推荐区加一行简短说明，如“已按开始前10分钟、结束后5分钟查找”。原来源覆盖说明保留。

### 记忆、取消与重查

- 沿用避让设置的本机账号记忆习惯，修改后主动记住；下次自动两条推荐和自定义查找都先恢复设置再计算。不同账号独立，普通成员不新增另一套设置口径。
- 修改缓冲立即使旧候选失效，旧异步响应不能覆盖新条件；当前已填入的起止时间和其他表单字段保留。
- 关闭自定义弹窗不会替用户选择新时段。若期间改变了已记住的设置，返回后按新条件刷新推荐；原已选推荐需重新核对，不能仍标为有效。
- 设置保存失败明确提示“本次查找已使用，默认设置未能记住”，当前显示的参数仍用于本次查找，不宣称下次一定恢复。
- 无结果时说明当前缓冲条件；提供显式的“本次不留缓冲再查找”。该操作只改变本次查询，界面标明“本次未留缓冲”，不改账号默认值、不自动采用结果。用户也可调整时长、范围或日期。不会后台逐步缩小缓冲后冒充原条件的推荐。

## 3. 计算规则

### 间隔定义

设任务时段为`[s,e)`，开始前留空B分钟、结束后留空A分钟。任务必须满足：

- 上一个真实占用结束到`s`至少B分钟。
- `e`到下一个真实占用开始至少A分钟。
- 刚好满足间隔允许通过，延续半开区间，不额外多扣1分钟。

等价地，真实占用`[u,v)`在本次计算中扩为`[u-A,v+B)`。寻找和提交校验共用同一辅助方法，避免前后方向写反或重复扩张。B与A都是针对正在安排的任务，不为已有每一项再累加一层设置。

| 情况 | 规则 |
| --- | --- |
| 课程、固定日程、有效规划、兼容旧式执行区间、同日有时刻手机事件 | 先依现有规则确定真实占用，再应用缓冲 |
| 午休／午餐／晚餐／自定义避让 | 按用户原区间避开，不额外扩张；需要更长午休由用户修改区间 |
| 全天或原本跨日期的手机日历事项 | 继续不占时间，不因缓冲变成占用；先按原事件判定，不能先扩张再分类 |
| 专注记录、时间日志 | 保持只读展示与复盘口径，不变为预约或缓冲来源 |
| 已完成／取消／跳过／漏做规划 | 沿用当前不占空闲的状态规则；focusing仍占用 |
| 正在编辑的规划自身 | 只排除该具体UUID；其他同待办规划仍参与缓冲 |

合并重叠缓冲后再求空隙，原始事件及占用快照仍保留真实时间。占用详情展示真实区间并附缓冲规则，不能把扩张后的时间伪装成课程或日历原时间。列表中的多个推荐是互为替代的方案，彼此不再额外预留缓冲。

### 时间范围、截止与午夜

- 用户设置的查找窗口、今天的当前时刻、待办截止约束实际任务起止时间；不凭空在窗口边界、当前时刻或截止前扣缓冲。附近确有其他占用时才需要间隔。
- 当天00:00结束的上一日安排，若B=10，当天00:00–00:10不可用；次日00:00开始的安排，若A=5，当天任务最晚23:55结束。
- 读取与计算需覆盖目标日起点之前B分钟、终点之后A分钟相关来源，再按扩张后的区间判断是否影响目标日。不能先按未扩张区间裁掉邻日安排。
- 同日手机事件23:50–23:59可能因缓冲影响次日，仍应计入；原本23:50到次日00:10的跨日期手机事件继续按已批准规则忽略。两者分别测试。
- 自然日用当地日期构造，间隔用分钟计算；测试时区及夏令时边界，不能假设每个自然日都是固定24小时。

## 4. 保存、草稿和一致性

1. 查询、候选和选中结果携带B／A；更改日期、时长、时间范围、避让、缓冲或账号后按既有方式作废旧结果。
2. 采用推荐后保存，沿用强制刷新日历及事务内复核本地来源。事务中的判断应用同一缓冲；他端新增不重叠但侵入缓冲的安排也须拒绝，原输入保留且不启动专注。
3. 手机日历读取失败继续要求用户显式选择仅检查应用内日程。降级只改变覆盖来源，不丢失缓冲；不会把失败当作没有占用。
4. 恢复本机草稿时，继续保留原时段和设置，使用当前账号的查找偏好重新检查。缓冲是查找默认值，不加入草稿正式字段或预留UUID的业务一致性比较，不需要草稿格式／schema迁移。
5. 冲突调整和漏做重排的查询重建、手动时段检查及保存后启动专注的二次检查，携带该次可见查询的缓冲；沿用它们原来的源规划版本、追加与身份校验。
6. 其他窗口修改默认设置时，重新打开／回到前台读取后使旧推荐失效并说明条件变化。明确选了“本次不留缓冲”的查询仍按可见的0／0提交，不被账号默认值悄悄覆盖。异步偏好写入和恢复需有序。
7. 时间轴直接拖动新建、移动、缩放和撤销保持现有软冲突语义。普通手动编辑离开推荐路径时，缓冲不升级为全局禁止保存规则；恢复草稿、冲突改期和漏做重排的既有强制检查继续执行，并在需要时显示具体违反条件。

“保存并开始专注”仅检查是否与其他安排满足间隔，不把B分钟自动变成倒计时等待，也不缩短专注时长。没有修改原专注启动、暂停或实际秒数逻辑。
