# 第38轮方案：待办详情反向查看关联固定日程

日期：2026-10-24（北京时间）

状态：**用户验收通过；本轮提交进行中**

## 1. 建议与收益

第37轮已经在固定日程详情展示关联待办，并允许从日程进入准备任务。但关系目前只能从固定日程一侧查看。用户从首页、搜索或规划块进入“准备答辩材料”等待办时，仍看不到它关联的答辩、考试、预约或会议，也不能直接返回对应日程。

本轮建议在待办详情增加“关联固定日程”只读区域，补齐从准备任务回到真实事件的上下文入口。用户可查看关联的单次日程或重复系列、下一次发生时间与状态，展开系列查看各场次，点击场次打开现有固定日程详情。关系仍由固定日程的 `relatedTodoIds` 保存和编辑，不创建第二份关系数据。

## 2. 当前实现依据

- `FixedScheduleItem.relatedTodoIds` 是固定日程到待办的唯一持久化关联，重复场次会依系列生成规则保留该列表。
- 第37轮已实现固定日程详情的关联待办列表、选择页、保存前可见范围检查和重复范围编辑。
- `TodoDetailScreen` 位于 `lib/screens/course_detail_screens.dart`，已展示任务状态、协作信息、专注记录等内容，但没有关联固定日程区域。
- 固定日程按当前账号存储；`StorageService.getFixedSchedules` 可读取当前账号可见的本地日程。现有读取 API 把 SQL 错误折叠为空列表，因此本轮若复用其语义，必须新增能区分读取失败与真实空结果的查询入口。
- `StorageService.scopedDataRefreshNotifier` 和 `DataRefreshDomain.fixedSchedules` 可用于日程关系变动后刷新页面；账号通过 `StorageService.getCurrentUsername()` 解析。
- 工作区当前另有 Android 课程到达提醒改动。本轮提案、获批实现与后续提交都不应碰这些已有改动。

## 3. 批准后的目标行为

### 待办详情区域

1. 在 `TodoDetailScreen` 增加“关联固定日程”区域，放在待办时间信息之后、识别来源等辅助信息之前；桌面布局遵循现有详情页左右栏结构，手机端保持自然纵向阅读。
2. 数据从当前账号的固定日程记录按 `relatedTodoIds` 反向筛选，不增加待办字段或重复存储关系。
3. 仅显示与当前待办可见范围完全一致的日程：个人待办只匹配个人日程；团队待办只匹配相同 `teamUuid` 的日程。teamUuid 统一去空格并规范空值，不能因缺失字段或大小写／空值转换把其他范围的标题泄露出来。
4. 展示加载中、真正无关联、读取失败三种独立状态；读取失败提供重试，不能伪装成空结果。
5. 单次日程显示标题、日期与时间待定／开始结束时间、固定日程状态和地点（有值时）。已结束及已取消的场次仍可查看，以保留历史上下文；软删除日程不显示。
6. 重复日程按 `recurrenceSeriesId` 合并成系列摘要，展示标题、关联场次数及最近的未来／进行中场次；没有未来场次时展示最近一场历史记录。展开后列出各个有效关联场次，并分别标注时间和状态；单场编辑造成的标题、日期或关系差异不得误合并成一个错误时间。
7. 点击单次日程或系列中的某个场次，打开现有 `FixedScheduleDetailScreen` 对应实例；返回待办详情后重新读取关系，反映用户在另一页移除关联、取消或删除日程后的最新结果。
8. 用户完成、跳过、恢复或编辑待办时不自动改动固定日程或关联关系。当前待办已完成时仍展示历史关联。

### 刷新、隔离与性能

1. 页面首次进入时按当前登录账号读取；账号切换时立即清空上一账号的关联日程，再加载新账号内容。
2. 监听固定日程数据刷新通知，并在从固定日程详情返回、App 恢复前台时刷新。使用请求序号和账号快照丢弃过期响应，避免慢请求把旧账号或旧关系结果写回界面。
3. 查询仅读本地当前账号数据库，不额外触发网络同步。新增的存储查询要返回明确的成功／失败结果；不改变现有通用读取方法的调用语义。
4. 查询后在模型层过滤关系与团队范围，并按日期排序。避免对每个固定日程逐条查询待办或日程形成 N+1 访问。

## 4. 数据、安全与兼容边界

- 继续以 `FixedScheduleItem.relatedTodoIds` 为唯一关系来源，不增加 `TodoItem` 外键、数据库列、同步协议、服务端接口或迁移。
- 展示区域为只读入口。本轮不在待办详情编辑关联；用户仍通过固定日程编辑器选择待办，以避免双方都能写入造成竞态和同步语义不明。
- 不把个人日程标题暴露给团队待办，也不把一个团队的日程暴露给另一个团队的任务。
- 不自动移动待办期限、规划块、提醒、固定日程状态或专注记录；删除／取消日程不级联修改待办。
- 未登录、当前账号未知、读取异常、账号切换竞争和日程在读取期间被删除均应安全降级；不得显示上个账号缓存的标题。
- 不改变外部手机日历同步的所有权规则。外部日历事件只通过现有日程详情查看，不在待办详情提供修改来源事件的快捷动作。

## 5. 预计实施范围

- `lib/screens/course_detail_screens.dart`：在 `TodoDetailScreen` 集成关联固定日程加载、刷新监听、分组摘要、展开场次和详情导航；必要时拆分窄范围私有组件，避免继续膨胀通用详情实现。
- `lib/storage_service_fixed.dart`、`lib/storage_service.dart` 及契约层（若调用要求）：增加按当前账号读取关联固定日程且可明确报告失败的存储入口。
- `lib/services/`：如 UI 过滤与系列分组逻辑不适合放在详情 State 中，则添加只读关联查询／分组 helper；保持无网络、副作用和可单测。
- 新增定向存储／服务测试与待办详情 widget 测试；为关联为空、重复系列展开和窄屏情况添加可查看的手机截图证据。

## 6. 验收标准

1. 个人待办只显示其个人关联日程；团队待办只显示同一团队关联日程；跨团队及个人／团队错配结果不会出现标题或地点。
2. 单次、重复系列、重复系列中被取消／结束的场次均按规则显示；同系列多个场次不产生重复摘要，展开后可区分每一实际实例。
3. 无关联、读取失败、加载中状态清楚可辨，失败可重试；空结果和错误结果不会混淆。
4. 点击单场或展开列表里的场次后进入正确固定日程详情；返回后日程标题、状态和关联列表刷新。
5. 固定日程通知触发以及用户切换账号后能刷新或清除旧结果；慢请求不能覆盖较新的账号或日程状态。
6. 完成／跳过待办、删除或取消关联日程不会自动更改另一对象；不存在第二份待办到日程关系数据。
7. 新增存储与分组逻辑有单元测试；待办详情 Widget 测试覆盖权限过滤、重复分组、空态、错误重试、点击导航和返回刷新。
8. 定向测试、`flutter analyze`（至少覆盖改动 Dart 文件）、格式检查、`git diff --check` 通过；运行 Web release build 以覆盖主要详情布局编译。
9. 提供可直接查看的手机截图至少两张：单次关联详情和展开的重复系列；另检查窄屏、深色主题与大字布局。证据必须注明其真实来源。
10. 验收报告区分自动化测试、静态分析、构建、Widget／浏览器截图和真实设备／跨设备同步；未运行的范围明确写出。
