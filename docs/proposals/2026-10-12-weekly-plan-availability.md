# 第十三轮方案：每周可安排时间

日期：2026-10-12，北京时间。第十二轮「完成待办后的剩余规划收尾」用户已回复「通过」。本轮状态：**已实施并完成技术验收，用户于2026-10-12确认通过**。

## 1. 问题与收益

目前找可用时段会记住午休、午餐、晚餐、自定义避让和前后缓冲，但每天使用同一组避让；查找范围仍是一次查询的起止时间。工作日与周末的生活安排不同，用户容易反复调整，跨日分段也会把同一时间范围应用到每一天。

建议增加「每周可安排时间」：用户设置周一至周日哪些时间适合安排，单段推荐和长任务分段共同遵守。比如周一至周五09:00–12:00、14:00–18:00，周六10:00–12:00、15:00–18:00，周日不推荐。已有午休、用餐避让和缓冲继续叠加。

这是一组推荐条件，不代表这些时段真的空闲，也不代表真实成果进度。是否空闲仍由课程、固定日程、已有规划、旧式执行区间和手机日历等现有来源判断。

## 2. 当前项目依据

以下为本轮对当前源码的调研结论，不是新功能已经实现的证据：

| 位置 | 当前能力与缺口 |
| --- | --- |
| `PlanAvailabilityPreferences` | 账号内记忆每日避让和缓冲，没有按星期区分的可安排范围 |
| `PlanAvailabilityQuery`／`PlanAvailabilityService` | 一次查询有一组起止时间和每日避让，已有区间合并、截止裁剪及推荐校验 |
| `PlanSplitQuery.day` | 逐日本地日期构造已具备，但每天复制相同起止范围和避让 |
| `PlanAvailabilityRepository` | 单段和分段共用忙闲读取，保存前及写入守卫中复核偏好与占用，可扩展规则指纹 |
| `PlanBlockEditor`及查找弹窗 | 首页待办、待规划、冲突改期和漏做恢复可复用推荐；主页面已有两个候选，自定义查找默认五个 |
| 规划草稿 | 已有退出保护及跨时区检查；新增规则需接入恢复复核，不能把旧推荐视为当前仍有效 |

课程、固定日程、习惯和团队安排继续由各自模块维护，不从它们自动推断用户作息。本轮无需远程AI、后台学习或新增数据表。

## 3. 用户操作与界面

### 设置入口与页面

在「自定义查找时段」中增加一个紧凑入口「每周可安排时间」；「规划中心」更多菜单也提供同一入口。进入独立整页设置，不在新建规划主页面铺开七天表单。同一页面登记到现有设置目录，使全局搜索及AI设置导航卡片能定位；AI仅提供用户可点击的入口，不替用户开启或修改规则。

```text
每周可安排时间                         保存
用于推荐时段                         [开启]

周一   09:00–12:00  14:00–18:00          >
周二   09:00–12:00  14:00–18:00          >
周三   09:00–12:00  14:00–18:00          >
周四   09:00–12:00  14:00–18:00          >
周五   09:00–12:00  14:00–18:00          >
周六   10:00–12:00  15:00–18:00          >
周日   不推荐                           >

复制到其他星期        恢复每天全天
仅当前账号、本机生效
```

上图为用户配置后的示例。功能初始关闭；首次编辑默认七天均全天，不擅自启用示例作息。提供「周一至周五09–12／14–18」模板按钮，点击只填设置草稿，再由用户保存。模板中的周一至周五按星期计算，不自动识别节假日和调休。

点击某天打开紧凑的当日编辑页：选择「全天」「指定时段」「不推荐」，指定时段最多四段，起止使用时间选择器。支持把该日规则复制到用户勾选的其他星期；复制和模板均不立即持久化。保存成功才返回，未保存返回沿用退出保护。

### 推荐结果保持紧凑

新建规划继续只显示两个推荐；启用后加一行可点击摘要，例如「周二 · 按每周时间推荐」。自定义查找仍默认五个结果，分段仍最多五组方案。完整设置放在独立页面。

自定义查询增加「本次不使用每周规则」，默认关闭。这是当前查找及所采用结果的明确选择，不修改账号规则，也不关闭午休避让、缓冲或日历检查。编辑设置返回后保留待办、时长、备注和番茄设置，仅废弃需要重新核对的候选。

当日配置为「不推荐」时，显示「周日未设置可安排时间」，提供修改规则或本次不使用的操作；不冒充整天已被日程占满。其他空结果分别说明截止、占用或条件限制，不声称一定存在可行方案。

## 4. 计算与操作规则

1. **范围交集**：当天可安排区间 ∩ 本次查找范围 ∩ 现在之后 ∩ 待办截止之前，再扣除既有忙碌、避让与缓冲。每段推荐必须完整落在同一有效区间，不能跨越中间禁止的时间。
2. **同一天多段**：最多四段，分钟为整数，`0 ≤ 起点 < 终点 ≤ 1440`。结束支持24:00，开始不支持24:00。保存时排序并合并重叠／相邻段，界面展示规范化结果。空列表只在明确选「不推荐」时合法。
3. **前后缓冲**：继续用于与其他占用之间的间隔，不把可安排范围边界再扣一遍缓冲。例如09–12范围内允许09:00开始，是否被前一安排及其缓冲阻挡仍按原规则判断。
4. **跨日分段**：保留现有1–7天、总时长和最多六段等限制，按每一天实际星期解析范围。「不推荐」日不提供空档，其他日期继续查找。所有日期均无法容纳总量时提示调整条件，不自动缩短工作量、放宽作息或延长截止。
5. **手工安排**：全天时间轴拖动新建、移动、缩放和手工编辑保持自由。用户手工改了推荐的时间后，清除旧推荐引用，显示手动安排状态；原有冲突、资格和存储校验保留。每周规则不会移动、取消已有规划，也不会因设置变化修改提醒。
6. **统一入口**：首页待办进入规划、待规划清单、冲突改期、漏做重新安排及分段均通过同一解析和接受校验。它们采用推荐时遵守规则，手工路径不被误判为推荐路径。
7. **本地时间**：按目标日期当地星期与墙钟时间应用，日界线用本地年月日构造，真实持续分钟按时间戳计算，不用24小时累加推算下一日。夏令时缺失或歧义边界须明确检测和提示调整，不能静默改到另一时间；草稿跨时区保留现有重新确认保护。

例子：周五下午只允许14:00–16:00，周六上午允许10:00–12:00，周日不推荐。150分钟任务、单段最多90分钟，可在周五与周六组合；不会为了凑满总量生成周日安排或把周五16点后的时间算进来。

## 5. 保存、草稿与失败保护

### 账号设置

- 独立、版本化的小型JSON保存七天规则，最多28个区间；当前账号、本机记忆，与现有避让及缓冲键分开，不改写已有偏好。
- 页面加载与保存绑定账号和请求序号；保存前重新核对身份、配置内容和原版本。新规则整体校验后用一次偏好写入提交，写入失败保持设置草稿，不显示成功。
- 设置页同时被其他入口修改时，拒绝覆盖并要求重读，不能用旧页面覆盖刚保存的新规则。规则规范化指纹用于比较有效内容，区间排序不会伪造变化。
- 读取失败或格式损坏明确显示错误，保留原始设置，不默认为关闭或全天。用户可显式重置该规则，或明确选择本次不使用；不会顺带重置午休、缓冲和其他设置。
- 本轮沿用本机偏好口径，不承诺云同步。规则保存不写待办、规划、oplog，也不读写系统日历。

### 推荐与写入

- 查询捕获规则、账号、日期和时区上下文；规则保存、切换账号、改日期或查询条件后，旧结果失效，旧异步响应不能覆盖新结果。
- 采用推荐仅填规划草稿。真正保存单段或整组分段前重新读取规则和占用；在既有写入守卫中再次比较规则指纹。规则变化时整次拒绝，显示「每周可安排时间已变化，请重新查找」，保留输入。
- 显式「本次不使用」携带独立标志，仅豁免每周规则，不豁免占用、截止、完成状态、账号、避让或缓冲检查。
- 每周偏好为本机设置，规划SQLite事务与偏好存储不组成跨存储事务；本轮提供既有方式的保存前及写入守卫复核，不承诺不同进程修改偏好时有超出当前架构的原子锁。

### 草稿恢复

记录足够区分推荐来源、规则摘要和本次豁免的草稿元数据，兼容旧版单段及分段草稿。恢复不会覆盖已保存规则，也不把旧摘要当作当前规则。

恢复的推荐重新读取当前规则及忙闲；规则已变化时保留原时段，要求重新查找或用户明确改为手动安排。本次豁免退出后不自动延续，恢复时须再次明确选择。旧草稿缺少来源信息时不直接认定已获得豁免，保留时间供核对。手工草稿继续按既有规则保存。

## 7. 验收标准

| 场景 | 必须验证的结果 |
| --- | --- |
| 默认关闭、旧账号、旧草稿 | 原推荐能力保持；开启规则由用户明确保存 |
| 周一与周末不同范围 | 同一查询按目标星期得到不同候选 |
| 一天两段、范围交集、区间边界 | 推荐不跨禁止间隙；相邻／重叠规范化；合法24:00不变成00:00起点 |
| 午休／用餐／忙碌／缓冲／截止叠加 | 结果同时满足各条件，既有手机跨日事件处理保持 |
| 指定日期不推荐、整周不推荐 | 明确说明规则限制，不假称已被日程占满 |
| 跨星期分段 | 跳过不推荐日期，合法总量完整，不能自动扩大日期或放宽规则 |
| 手工拖动与手工编辑 | 保持24小时一屏操作，范围外手工安排仍可按既有流程保存 |
| 本次豁免 | 只豁免每周规则，其他校验不绕过，退出恢复不自动继承 |
| 保存或确认期间规则／身份／占用变化 | 废弃旧候选，拒绝旧推荐写入，保留输入；分段无半组写入 |
| 偏好读写失败、并行设置页 | 如实显示失败，不覆盖旧值、不假称已保存 |
| 草稿恢复、跨午夜及夏令时 | 日期和实际时长正确，规则／时区变化不静默改变时间或放宽条件 |
