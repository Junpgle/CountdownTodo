# 第 23 轮方案：时间日志补录保存保障与退出保护

日期：2026-10-20（北京时间）。状态：**已批准并实施，验收结果见 [验收报告](../reports/2026-10-20-time-log-editor-acceptance.md)**。

## 1. 建议与收益

给手动时间日志的新增和编辑表单补上未保存退出保护，并让表单等到本机写入结果明确后再关闭。用户通过时间轴拖动生成一条记录、调整标题／标签／时间后，如果误触返回、点遮罩或下滑关闭，可以继续编辑、放弃本次修改或保存后退出；数据库写入失败时，输入留在表单里，原记录和时间轴不显示一条“看起来已保存”的假记录。

例：用户编辑“阅读论文”的结束时间后下滑关闭。现在底部表单没有离开确认；确认框会一并消失。若用户保存后本机写入失败，当前代码已经先关闭表单并乐观更新列表，错误提示出现时输入已不在表单里。本轮让所有入口共用同一条保护与异步保存路径。

收益覆盖时间轴拖动补录、精确补录和既有手动日志编辑，也修正全量快照写回可能覆盖并发新记录的问题。它不改变规划块或真实番茄记录，也不自动生成实际时间日志。

## 2. 当前源码证据

以下为当前工作树源码核对结果，不代表已经运行过对应故障复现：

| 位置 | 当前行为与风险 |
| --- | --- |

| `lib/screens/time_log_components.dart` 的 `_openEntry` | 拖动补录路径也先关闭 `_LogEntrySheet`，再调用由父页面提供的异步保存回调；回调类型目前是 `void Function(TimeLogItem)`，无法等待提交结果。 |
| `lib/screens/time_log_components.dart` 的 `_LogEntrySheet` | 标题、标签、开始和结束时间都保存在表单局部状态，尚未提交前没有写库；但没有 `PopScope` 或等效离开守卫。 |
| `lib/utils/app_dialogs.dart` 的 `showAppModalBottomSheet` | 默认允许点击遮罩退出和拖动关闭（`isDismissible: true`、`enableDrag: true`）；仅拦系统返回不能覆盖这些关闭方式。 |

## 3. 交互方案

### 未修改的表单

- 直接返回、点遮罩或下滑关闭，不增加确认。
- 新增时以拖动得到的起止时间、预选标签和初始标题为基线；编辑时以打开记录的字段为基线。
- 用户改动字段后又恢复为原值时，视为未修改，不弹确认。

### 存在未保存修改

系统返回、路由返回、遮罩关闭或拖动关闭都进入同一确认流程；最多显示一个对话框：

```text
保留这条时间日志？
当前补录有尚未保存的修改。

继续编辑        放弃修改        保存并退出
```

- **继续编辑**：关闭确认框，保留标题、标签和日期时间，键盘及编辑位置尽量不变。点框外或按取消也等同继续编辑。
- **放弃修改**：只关闭当前表单草稿。已有日志保持打开表单前的持久化版本；新增记录不写入。
- **保存并退出**：运行与表单“保存记录”完全相同的校验、重叠确认和本机保存流程。只有本机保存已确认时才关闭。
- 如果保存中收到返回、遮罩或拖动关闭请求，不再弹第二个确认；阻止离开并让当前保存流程完成或失败返回。
- 清洁退出时保留现有拖动关闭手感；只有存在未保存修改时才拦截并询问。

## 4. 保存与数据边界

1. 将表单保存回调改成可等待的结果契约。编辑器在保存完成前保持打开并显示提交中状态，防止连点创建重复记录。
2. 保存时只把当前 `TimeLogItem` 作为单项列表传给现有 `StorageService.saveTimeLogs(username, [log], sync: true)`。存储层按 UUID 替换目标行，其他日志不从旧页面快照重新写入。
3. 本机写入确认后，再更新页面内存状态并触发刷新；本机事务明确失败时，不更新列表、不关表单，保留全部输入并提示可重试。
4. SQLite 批量写入完成后，旧镜像清理仍可能失败而让 API 返回异常。捕获异常后按稳定 UUID 读取回数据库：内容、版本和更新时间一致则识别为“本机已保存”，避免把已落库误报为未保存；无法读回或状态不一致时保留表单并说明状态待核对。
5. 新增记录在第一次提交前生成并保留 UUID；重试继续使用同一 UUID。编辑保留原 UUID 与 `createdAt`，按现有规则递增版本。这样写入结果不确定时重试也不会新增重复日志。
6. 本轮只把“本机已保存”作为表单关闭条件；不把异步 `requestSync` 当成服务端确认，也不改变现有同步协议、版本竞争规则或同步失败的全局提示方式。若本机数据已确认但后续同步状态未知，明确提示“已保存在本机”，不声称“已同步”。
7. 与时间日志重叠的返回修改仍只关闭冲突确认并回到编辑表单；它不触发离开保护，也不改变本轮刚完成的图形时间轴和重叠规则。

## 5. 实施范围与不做事项

预计涉及：

- `lib/screens/time_log_components.dart`：为新增／编辑表单加入字段基线比较、退出守卫、稳定待保存 UUID 与异步保存状态；保留输入和标签选择行为。
- `lib/screens/time_log_screen.dart`：将编辑与拖动新增接到同一个可等待的单项保存入口；改为本机保存成功后更新列表；失败保留原页面数据。
- `test/widgets/`：覆盖新增、编辑和时间轴拖动表单的退出选择、输入保留及成功后关闭。
- `test/services/`：覆盖单条写入不会覆盖其他日志、保存失败无乐观残留，以及提交后清理异常的读回判定。
- `docs/features/` 或现有时间日志说明：记录表单保存与返回语义；提交本轮验收报告和合成数据的界面证据。

明确不做：

- 不持久化自动草稿、不新建数据库表、不改 `TimeLogItem` 数据结构。
- 不改番茄钟记录、专注行为、规划块、重叠算法、复盘口径和标签管理。
- 不将离线写入描述成云端成功，不为本轮扩大到所有数据源的同步重构。
- 不修改当前工作区里已有的规划清理、手动完成及番茄结束同步改动。

## 6. 验收计划

1. 新增和编辑表单均覆盖未修改直接退出、字段修改后拦截、恢复原值后不再拦截。
2. 系统返回、框外点按、下滑关闭使用同一选择；继续编辑不丢字段，放弃修改不写入或改变旧记录。
3. 保存并退出走完整的起止校验与重叠提醒；选择返回修改后表单仍在，确认本机写入后仅关闭一次。
4. 注入 SQLite 事务失败：表单保持打开、标题／标签／时间完整、内存时间轴不出现未落库日志，重试后同一 UUID 只出现一条。
5. 注入写入后 Prefs 清理失败：读回与输入一致时准确识别本机已保存；无法判定时不生成新 UUID、不覆盖原记录，提示用户核对。
6. 编辑现有日志时 UUID、`createdAt`、备注和设备字段保留；保存单条日志不覆盖同期新增的其他日志。
7. 保存中重复点击、系统返回、冲突确认的返回／继续和页面刷新竞争均不产生双写或提前关闭。
8. 390／320 px 手机、键盘展开、横屏、桌面、深浅色及大字体下检查动作换行、拖动手势、离开确认层级和错误提示；生成报告并附合成数据界面图。
9. 运行涉及文件静态分析、时间日志存储／重叠相关回归、完整相关 widget 用例和 Web 构建。完整 Flutter 测试套件及原生真机范围按实际环境执行并如实报告。
