## 1. 建议与依据

为漏做的真实规划增加“重新安排”：打开已确认样式的共享编辑器，带入原待办和配置，查找新的可用时间，显式保存一条新规划。原漏做记录保留，便于真实复盘。

项目已具备待办／重复待办、课程／固定日程、首页今日规划、专注执行、日周月统计和 AI 操作。前两轮打通了搜索范围及本地空闲查找，本轮补齐执行后的调整操作，复用现有页面与服务。

本次当前源码核对结果：

- `PlanBlockStatsScreen._buildMissedList` 显示当前日／周／月范围的漏做项，最多十条，没有重新安排回调。
- `_buildAiSuggestionCard` 已有“漏做块较多，建议顺延未开始的规划”的规则建议，但没有直接承接的操作。
- `PlanBlockTodaySection` 展示今日规划与状态；`TodoPlanScreen` 和首页会按既有规则标记过期未执行的规划。本轮沿用状态，不扩改漏做判定。
- 统计／日历含课程和旧待办的虚拟映射项。新操作必须只针对数据库中真实的 `TodoPlanBlock`，不能把虚拟课程转换成可自由调整的规划。
- 第二轮编辑器对 `missed` 不开放推荐改期，这是保护历史记录的正确边界；新操作应新建，不将旧记录状态改回 `planned`。
- 模型已有待办关联、配置、实际专注、番茄记录 ID 与日历事件 ID；新建时须白名单继承配置，不能复制实际记录和外部事件身份。
- 可复用第二轮的强制读取、空档算法、条件 SQLite 写入和既有 oplog／同步，无须引入模型 API、后端、权限或数据库迁移。

调研只读源码和文档，没有查询个人业务记录；这些是现状依据，不是第三轮已通过的运行验证。

## 2. 用户收益与例子

昨天“复习高数”的 19:00–19:45 漏做，待办还没完成，截止是明天20:00。

1. 在漏做条目点击“重新安排”。
2. 编辑器显示原安排，默认查今天45分钟；可改为明天／其他日期、修改时长。
3. 查找并选用今天10:00–10:45。
4. 点“保存规划”，或“保存并开始专注”。

结果：昨天19:00那条仍为漏做，今天新增45分钟规划，关联同一待办。原备注、提醒和番茄配置带入可修改；待办本体、截止和重复规则保持原值。

减少重新找到待办和重新填写配置的操作，且能直接围绕当前课程、固定日程和已有规划安排下一次执行。收益以实际流程验收，不承诺耗时提升百分比。

## 3. 交互和外观

### 入口

- 首页“今日规划”的漏做条目：展开后展示“重新安排”。
- “规划统计”的漏做列表：增加行内“重新安排”；默认仍展示前十项，超过时提供“查看全部漏做”，打开仅包含当前统计范围的可滚动列表。
- 规划日视图点击漏做块：在其编辑器内提供“重新安排”入口。打开新面板前等待旧弹层彻底关闭，避免叠层或动画冲突。
- 三个入口使用同一资格检查与新建流程，按钮忙时不重复打开。

### 编辑器

复用第二轮已获认可的布局、动态取色、680宽度上限和固定操作栏，标题改为“重新安排”。顶部用一条简洁信息显示原日期和时段，不另加新看板或大面积提示。

```text
重新安排                                      关闭
复习高数
原安排：昨天 19:00–19:45 · 漏做

找可用时间
[今天] [明天] [其他日期]      需要：45 分钟
可安排范围：08:00–22:00
查找时段

10:00–10:45                         选用
10-08 · 45 分钟

备注、番茄配置、提前提醒

保存并开始专注                         保存规划
```

上述为结构示意；候选卡片及输入外观直接沿用第二轮。窄屏／大字体纵向排列，不堆叠新的胶囊操作行。

- 日期默认今天，查找区默认展开；今天／明天是快捷选择，其他日期使用共享日期选择器。跨午夜重新取得“今天”。
- 默认采用有效的原计划分钟数；缺失时取有效的原区间分钟数，仍无效时采用30分钟并提示用户检查。大于单日上限时也需修改为合法单日时长。
- 不将“原计划分钟数减实际专注”当作剩余工作量，避免把投入时间等同于完成进度；用户自己调整时长。
- 待办锁定为原关联实例；需要安排其他待办时回到普通新建流程。
- 点击查找后才加载安排、生成候选；不擅自采用第一个候选，不自动保存。
- 手动调整时间仍可用，但本流程同样复查该单日实际区间的占用与截止，不能绕过安全检查。此限制只作用于新“重新安排”路径，普通编辑保持第二轮行为。
- 取消／返回不创建规划、不重置旧状态、不启动专注。
- 保存成功明确提示“已新建……规划，原漏做记录已保留”，刷新首页、统计和日视图。历史漏做计数不被人为减少。

### 已有后续安排

一个待办允许有多个规划，不能简单以“同一待办已有规划”阻止全部操作，也不能偷偷叠加新的规划。

- 打开时若存在同一待办、尚未结束的 `planned/reminded/delayed`，先显示已有安排的日期与时段，可“查看已有规划”，或明确“仍新建一次”。
- 若同一待办正在某规划中专注，提供“查看当前专注”，本入口先不创建新规划。
- “仍新建一次”的选择仅适用于当前草稿已经展示过的安排集合。保存前若出现新的后续规划，提示用户先查看最新安排；不将新的同待办安排默认为用户已经同意。
- 没有永久“已补排”标记或一对一恢复关系：现有模型不保存父规划 ID，不能按标题／待办关联猜测哪一条新规划补的是哪一次漏做。

## 4. 状态与数据契约

| 对象 | 保存成功后的行为 |
| --- | --- |
| 原漏做规划 | UUID、状态、原时段、实际专注、番茄关联、日历身份及历史元数据均保留 |
| 新规划 | 新 UUID，状态 `planned`，来源 `manual`，使用用户确认的日期／时段／分钟数 |
| 继承内容 | 原待办 UUID、备注、提醒、番茄分钟及轮数；标题使用最新待办标题 |
| 不继承内容 | 原 UUID、实际专注、番茄记录 ID、日历事件 ID、旧版本号及旧同步标记 |
| 待办本体 | 不改完成状态、截止、文件夹、重复规则；重复待办仍关联原具体实例，不切换下一期 |
| 实际记录 | 不补造执行记录，不清空原投入时间；新规划从零实际执行开始 |
| 本地写入 | 新规划与对应 oplog 同一事务；校验失败则二者均不写 |
| 外部集成 | 沿用现有同步／提醒／日历路径，新记录不能复用旧事件身份；不直接改课程或固定日程 |

兼容旧记录时，无法沿用的提醒／番茄配置使用现有支持的默认值并告知用户；原记录不被修复性改写。

### 资格与失败处理

- 原规划必须是当前账号真实、未删除、仍为 `missed` 的记录；旧虚拟课程和旧执行区间映射不提供此操作。
- 目标待办必须仍存在、未删除、未完成且允许当前用户规划；读取真实 UUID，不按标题替换为其他任务或重复实例。
- 截止已过则显示“待办截止已过，请先调整截止后再重新安排”，提供查看待办入口；本流程不自动延长截止。日期截止仍按当天结束处理。
- 原规划被同步修改／删除、关联待办变化或账号切换时，停止当前保存并保留可核对的输入，提示重新读取；不覆盖旧记录。
- 来源读取失败停止推荐。手机日历失败仍须用户显式选择“仅按应用内安排查找”，同时显示实际覆盖范围。
- 今日起点使用当前时间向上对齐分钟。午夜、查找后时间流逝、候选被占用和日历设置变动都沿用第二轮失效与复查规则。
- 新建副作用从显式保存开始；双击只生成一条新规划，专注启动失败时复用已保存的新 UUID，启动成功但状态写入失败时只重试状态。
- 本轮是本地检查，不承诺锁住其他设备／系统日历中尚未同步的更新。
