# 第 24 轮方案：重复待办跳过本期与状态闭环

日期：2026-10-20（北京时间）

状态：**已获批准并实施完成；等待用户验收**

## 1. 建议与收益

为重复待办增加真正独立的“已跳过”状态，让用户可以明确表示“本周不交周报”，而不用删除本期、标成已完成或等它变成逾期。跳过只作用于选中的这一期，后续重复规则继续运行；复盘中分别统计已完成、逾期未完成、已跳过和待处理。

这是产品语义文档已经定义、但当前模型和同步表尚未实现的能力。它能补全重复待办从本期操作、列表呈现到历史统计的状态闭环，也避免把重复任务误当成习惯或把“不做”伪装成“已做”。

## 3. 状态与用户操作

### 状态语义

- 只允许对一个未删除、尚未完成的**重复待办具体期次**执行“跳过本期”。普通单次待办继续使用完成、改期或删除，不出现跳过操作。
- 状态只属于该期，不改变 `recurrenceSeriesId`、重复规则、结束日期或其他期次。按既有规则生成下一期，不因跳过而停掉整个系列。
- 本期状态互斥：待处理、已完成、已跳过三者不能同时成立；逾期由日期边界计算，只适用于既未完成也未跳过的期次。跳过不是软删除。
- 从跳过恢复时只清除跳过状态，不改标题、日期、备注、标签、创建时间、重复规则或关联历史。若用户后来实际完成，可通过原完成操作转为已完成并清除跳过标记。
- 已跳过的期次保留在历史和系列进度中；退出活动待办列表，退出逾期催办和提醒，仍可在重复系列历史／状态筛选与搜索详情中查看并恢复。

### 入口和反馈

- 在重复待办卡片的更多操作及重复系列历史中提供“跳过本期”／“恢复本期”。入口绑定真实期次 UUID；界面明确显示当前期次日期和“后续期次仍会继续”。
- 跳过前用确认框说明结果及其与完成、删除的区别。保存成功后给出“已跳过本期”反馈和短时撤销；恢复操作也有清晰反馈。重复点击和过期确认不得重复写入。
- 不在含未保存编辑内容的表单上直接执行跳过，避免跳过操作覆盖或丢弃编辑草稿。编辑页显示本期状态与历史记录，写操作从已保存的待办卡片／系列历史入口触发。
- 若该期已有尚未开始的规划块，确认框列出数量并说明这些规划仍保留；本轮不自动删除规划或专注历史。已跳过待办不提供新规划推荐；关联规划开始专注时明确提示“先恢复本期待办或自行处理规划”。正在专注的期次禁止跳过，要求先结束当前专注流程。

### 协作语义

跳过的作用范围沿用待办现有完成规则：个人待办与“共同完成”协作待办写入共享状态；“各自独立完成”的协作待办按当前成员写入个人状态。甲成员跳过不能改变乙成员的完成、跳过或待处理状态。成员移除、团队切换和跨端读取均按当前授权重新核对。

## 4. 数据、备份和同步

1. 客户端 SQLite schema 从 v58 升到 v59，为 `todos` 与 `todo_completions` 增加默认未跳过字段。旧数据库升级后所有已有行保持原状态；不根据删除、逾期或规划状态推断跳过。
2. 扩展 `TodoItem` JSON/SQL 序列化、克隆和合并；旧 JSON 缺少字段时默认 `false`。导出包含跳过状态，导入校验完成与跳过互斥，并能兼容旧版备份。
3. 更新 Alibaba debug 的 `todos`／`todo_completions` schema、迁移与同步读写；独立协作状态按成员隔离，完成、恢复和跳过更新使用同一成员权限及版本规则。同步响应按请求成员返回其有效状态。
4. 增加 `todo_skip_state: 1` 同步能力声明。客户端只在服务端明确支持时确认跳过状态已同步；旧服务端没有该能力时，其他待办同步照常运行，但跳过状态留在本地并显式标记待同步，不得被缺字段的旧快照覆盖或宣称已跨端同步。服务端支持后，按待办 UUID／成员作用域补传并在明确 ACK 后清除待同步标记。
5. 不改 Alibaba `math_quiz_backend/` 生产目录，不部署服务，不改变 Worker 兼容端。验收用 debug 服务协议测试及客户端旧服务端模拟，部署状态不作为本轮完成声明。

## 5. 全项目联动范围

- **待办列表、首页和小组件**：跳过项不再作为待完成任务展示，也不在完成数中冒充已完成；历史入口保留恢复操作。
- **逾期处理和提醒**：跳过项不进入逾期批量顺延，不安排该期提醒；恢复后按既有提醒边界重新判断，不补发已经过时的提醒。
- **规划与专注**：新规划待办选择器、估时推荐及开始专注守卫排除已跳过项。既有规划块、番茄和时间日志不删除、不改写；跳过期间开始专注会提示恢复待办或处理原规划。
- **重复进度和复盘**：系列详情增加清楚区分的“已跳过”节点／标签；统计增加 `skippedCount`，完成、逾期、跳过、待处理分别可对账。跳过不增加完成率分子或连续完成数；系列完成率沿用当前已解决期次口径，跳过数单独展示。
- **搜索、时间线、导出**：历史搜索结果显示跳过状态；时间线可查看跳过事件但不显示为完成事件；JSON 往返保留全局或成员级状态。
- **AI 助手**：上下文区分“已跳过”和“已完成”。新增 `skip_todo` 提议，只接受真实具体期次 UUID；默认只跳过本期，不能传系列范围。沿用现有确认卡，只有用户确认后执行；对象不唯一时先追问。恢复仍从待办界面完成，本轮不扩大为 AI 自动改写状态。

## 7. 验收计划

1. **状态机**：个人、共享协作和独立协作期次均验证待处理→跳过→恢复、跳过→完成、完成不可再跳过；任意时刻完成与跳过不同时成立。独立协作用户 A 的修改对用户 B 不可见。
2. **重复规则**：跳过当前期不变更系列 UUID、规则、截止边界或其他期次；下一期按原规则恰好生成一次。重复写入、网络重试和并发版本变化不产生重复期次或静默覆盖。
3. **持久化和备份**：构造 schema v58 数据库升级到 v59，既有记录保持未跳过；SQL／JSON／备份往返保留状态；旧 JSON 默认未跳过。
4. **兼容同步**：支持 `todo_skip_state: 1` 的 debug 服务端完成共享及独立成员 round-trip；模拟旧服务端缺少能力时，跳过仍保存在本机、保留待同步状态并忽略缺失字段，不误报成功；能力出现后按原 UUID 补传。
5. **业务筛选**：跳过记录不进入活动待办、逾期顺延、通知调度、规划建议和专注启动；恢复后重新可操作。已有规划、实际投入和时间日志保持原记录且统计不重复。
6. **统计与界面**：系列状态和统计能分别对账完成、逾期、跳过、待处理；跳过不提升完成率／连续完成期数。测试确认卡片操作、确认、撤销、历史恢复和窄屏大字布局；提供真实 widget 渲染截图，尽可能补充 Web 本机入口截图。
7. **AI 安全**：测试 `skip_todo` 文本／Function Calling 参数、模糊期次澄清、真实 UUID 绑定、确认卡片、拒绝确认不写入、重复确认幂等，以及 AI 上下文中的跳过状态。
8. 运行模型／SQLite／导入导出／待办选择／逾期／复盘／提醒相关定向 Flutter 测试，客户端静态分析与 Web 构建；运行 Alibaba `debug/` 同步协议对应 Node 测试。完整 Flutter 套件和原生真机结果按实际环境说明。
