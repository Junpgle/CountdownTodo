# 第四轮方案：规划冲突检查与快捷改期

日期：2026-10-09（北京时间）。状态：**用户暂缓，本轮不实施；先完善第三轮展开动画**。

第三轮“漏做规划重新安排”已完成本地验收，用户回复“请继续”。本轮按既定流程先提交完整方案，批准后实施及验收，再等待用户确认。

## 1. 建议与项目依据

给已经保存、尚未结束的规划增加冲突检查入口：发现其与课程、固定日程、其他规划、兼容的旧执行时段或同日定时手机日历重叠，展示具体来源，并直接打开现有编辑器查找替代时间。

前两轮解决“在哪里安排”，第三轮解决“漏做之后重新安排”；本轮解决“安排之后情况变了”。例如原本安排今天19:00–19:45复习，后来新增19:30–20:30会议，用户在执行前就能发现并调整。

此次只读源码确认：

- `ScheduleConflictService.detect` 已支持课程／固定日程与规划的冲突，但没有规划对规划检测，也没有手机日历来源；其主要调用点是固定日程编辑器保存确认。
- `TodoPlanScreen` 已有全天一屏、拖动新建、移动／缩放、实际记录与共享编辑器，但没有统一的规划冲突列表。移动／缩放仍走原保存路径。
- `PlanBlockTodaySection` 已展示今日规划，可在现有标题区域放置紧凑冲突入口。
- `PlanAvailabilityRepository` 已有严格来源读取、实际课程日期规则、跨天日历排除、占用与截止检查、保存前强制刷新及事务复查，可以复用。
- 日视图现有刷新监听包含课程／规划等，但缺少固定日程领域；需要补上，避免新增会议后提示不更新。
- 第三轮是从漏做记录新建；本轮对可调整的既有规划改时间，使用原UUID并保留实际和同步身份，两条数据路径应明确区分。

以上是当前代码调研结果，不是第四轮运行验收结果。未读取个人业务数据。

## 2. 使用流程与界面

默认检查今日；规划日视图检查所选日期。进入页面、相关数据刷新或从后台返回时重新检查。用户打开冲突列表后，可切换“今天／未来7天”，按日期分组。没有后台定时任务、系统通知或AI调用。

首页今日规划与日视图现有标题／工具区域增加一项紧凑入口：

```text
今日规划                       2条规划时间重叠 ›
```

没有发现重叠时不增加卡片；读取不完整时显示“冲突检查未完成”，可以重试，并展示已检查范围。日期、数量和列表来自同一结果，数量按真实规划UUID去重，不能把一条规划的三个冲突算成三条规划。

点击打开现有玻璃风格、最大宽度680的列表弹层，不挤占时间轴：

```text
规划时间重叠                              关闭
今天 / 未来7天

复习高数       今天19:00–19:45
与会议重叠     19:30–19:45
查看会议                          调整安排

阅读论文       明天14:00–15:00
与另一条规划重叠  14:30–15:00
查看另一规划                      调整安排
```

同一规划的多个冲突汇总到一行，展开查看各来源及实际重叠区间。列表懒构建，标题过长可截断，展开后显示完整内容。普通／玻璃、深浅色、窄屏、大字体和键盘沿用现有组件与动态颜色。

“查看来源”进入现有课程、固定日程、规划或设备日历详情；“调整安排”在旧弹层关闭后打开共享编辑器，默认展开查找。带入原待办、时长、备注、提醒和番茄配置，用户仍可改日期和时长。

保留全天24小时一屏、拖动新建和移动／缩放手势。拖动之后刷新提示；本轮不增加每次拖动后的确认弹窗，也不自动移动其他规划。并排设置、五个候选、3／5／8数量及午休／用餐／自定义避让全部保留。

## 3. 检查与展示规则

| 场景 | 规则 |
| --- | --- |
| 参与检查的规划 | 当前账号数据库真实记录，未删除、尚未结束，状态 planned／reminded／delayed／focusing；排除虚拟课程／旧待办映射 |
| 可直接改期 | 仅 planned／reminded／delayed；focusing 只提供查看当前专注 |
| 已完成／漏做／跳过／取消 | 不列入本轮待处理冲突；漏做继续使用第三轮重新安排 |
| 课程与固定日程 | 按实际日期、调休和有效定时区间检查；已取消／删除固定日程排除 |
| 规划对规划 | 两条真实规划的区间重叠即展示，各自列出相关来源；同一对去重，不把自身当占用 |
| 时间边界 | 半开区间，10:00结束与10:00开始不冲突；跨日应用内定时安排按查询日期裁剪 |
| 手机日历 | 仅已有开关开启且已授权时读取；沿用用户要求，全天及本地日期跨天事项不计占用；同日定时事项参与 |
| 旧执行时段 | 复用当前兼容规则及去重，截止点、跨天截止和创建时间不冒充连续占用 |
| 专注与时间日志 | 已发生的实际记录只展示，不作为新的预约占用，不伪造执行或转成规划 |
| 午休与用餐 | 仍是当前编辑器可选查找偏好，不把未启用、未持久化的偏好当作已保存规划的冲突来源 |
| 来源时间待定 | 明确提示该来源无法完成时段检查，不能据此宣布整个日期没有冲突 |

未来7天指今天起连续七个本地日期。过去日期不产生待改期提醒；当天尚未结束的规划即使已开始，也可展示其重叠情况。检查时使用实际当前时间，跨午夜更新日期和范围。

## 4. 改期数据与保存保护

从本轮“调整安排”进入的是受校验的既有规划编辑，待办关联锁定，不切换另一任务或另一重复实例。既有普通编辑默认行为保留。

| 对象 | 保存后的行为 |
| --- | --- |
| 原规划 | 保留UUID，只改用户确认的日期／时间／计划分钟及可编辑配置，沿用既有版本与同步机制 |
| 实际数据 | 保留实际专注、番茄记录关联、设备信息和现有日历身份，不清空投入、不生成执行记录 |
| 来源课程／固定日程／其他规划 | 不修改、不删除，不批量顺延 |
| 关联待办 | 不改完成状态、截止、分组和重复规则 |
| 已有日历事件 | 沿用现有同步更新同一事件的路径，不冒充新事件、不直接写手机读取来源 |
| 保存失败／取消 | 保留输入；无新规划、无额外oplog、无专注启动 |

保存推荐或手动改时间，均重新强制读取来源，检查真实占用、待办截止、当天时间及当前避让偏好。只排除正在编辑的原UUID，不能排除同一待办的其他规划。来源与关联待办、账号、原规划版本／更新时间／资格在写事务内复查。

如果冲突已自然消失，列表刷新即可消除提示，不写“已处理”标记。若保存前产生新占用、原规划变为专注／完成／漏做或被删除、待办失效、账号切换、截止或时间过期，则拒绝并保留输入。读取失败不当作空闲；手机日历失败只有用户显式选择“仅按应用内安排查找／检查”才降级，并持续标明覆盖范围。

提示展示、展开、查看和候选选用均只读；保存与oplog沿用现有同一事务。不会自动采用候选或自动改期。“保存并开始专注”复用第二轮的连击与分阶段重试保护。

本轮仍是本地快照检查，不保证锁住其他设备或系统日历中尚未同步的变更。

## 6. 验收标准

1. 新增／修改课程、固定日程、规划或有权限的定时手机日历后，当前可见日期正确刷新；数量与打开的列表一致。同一规划多个冲突只计一次。
2. 规划与规划、自身排除、相邻边界、跨午夜、调休、日期待定、全天／跨天手机日历排除均符合共享规则。
3. 首页与日视图真实入口可操作，未来7天范围明确，来源详情正确；专注中仅查看，虚拟与历史记录不误提供改期。
4. 查看、查找、采用候选后取消零写入；保存成功仅更新目标规划，UUID、历史实际数据及日历身份保留，其他安排和待办逐字段不变。
5. 推荐与手动时间均校验占用、截止、避让、时间流逝；同步修改／删除、状态变化、账号切换、来源失败停止保存并保留输入。
6. 新规划／固定日程变化在写事务前再次被检查；写入失败完整回滚；连击及专注重试不重复写入／启动。
7. 全天一屏、拖动新建和移动／缩放保留；并排设置、五个候选及灵活避让回归通过；320／390、桌面、横屏、大字体、键盘、深浅色与玻璃模式无溢出。

实施后执行聚焦测试、相关回归、静态分析、格式及差异检查，提供合成预览与隔离数据库证据。真机日历／通知／专注依据设备可用性单独报告，模拟桥不等同实机验收。
