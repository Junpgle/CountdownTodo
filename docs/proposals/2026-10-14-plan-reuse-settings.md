# 第十六轮方案：照此新建规划

日期：2026-10-14（北京时间）。用户已确认第十五轮通过。**用户已批准第十六轮；实施与技术验收已交付，用户于2026-10-15要求准备第十七轮。** 结果见[第十六轮验收报告](../reports/2026-10-14-plan-reuse-settings-acceptance.md)。

## 1. 建议与收益

给已有规划增加「照此新建」，沿用时长、备注、单轮番茄、轮数和提醒，进入整页新建规划，选择待办与新的可用时段，核对后保存。

例如昨天的「论文写作」安排60分钟、单轮25分钟、2轮、提前10分钟提醒。今天还要安排一次，当前需要重新填写这些设置；本轮可以直接带入，并按60分钟展示今天的两个推荐时段。也可以换成另一项未完成待办，继续沿用这组设置。

这把项目已有的待办、规划、番茄设置、空闲推荐和本机草稿连接起来，减少重复填写。新规划仍由用户明确保存，实际投入和完成状态各自独立。

## 3. 界面与操作

### 从已有规划进入

- 点击真实规划，更多菜单增加「照此新建」。课程、手机日历和映射待办沿用原详情，不提供此入口。
- 入口读取该规划最新已保存内容。正在保存或存在未保存修改时不可执行，说明「请先保存修改，或放弃修改后重新打开」，避免把编辑中的值误当成已保存设置。
- 读取失败留在原页面，显示原因及重试；连续点击只打开一个新建页。
- 新页沿用当前整页新建布局和页面过渡，顶部只加一行「沿用已有规划设置 · 60分钟」，不增加长说明卡、时间轴面板或模板管理页。

### 带入内容和选择时段

```text
新建规划
沿用已有规划设置 · 60分钟

待办            论文写作
日期            今天
推荐时段        10:00–11:00  /  15:00–16:00
                自定义查找

单轮番茄        番茄轮数        提前提醒
25分钟          2轮             10分钟前

备注            沿用原备注，可修改
                保存规划
```

示例仅说明内容关系，具体排版沿用第十四轮已验收样式。

1. 默认目标日期为原规划开始的本地日期与今天中的较晚一天。历史规划默认今天，未来规划保留其日期；用户可以在现有日期／查找控件修改。
2. 原待办按具体UUID重新读取，当前成员仍未完成且可用时选中它。已完成、删除、冲突或无法访问时不选中任何待办，说明需要选择未完成待办；不得默认改选列表第一项、同名任务或另一期重复待办。数据库／身份读取失败应报错，不能伪装成待办失效。
3. 查找使用原规划起止间隔的实际整分钟时长，不取实际投入缓存、番茄总分钟或可能过时的planned_minutes。当前支持复用1–1440整分钟的合法区间；异常、含非整分钟或更长的历史区间明确提示暂不支持，不静默截断或改成30分钟。
4. 首次直接按沿用时长读取两个推荐，找到结果后将第一个填入新建表单，用户可换第二个或自定义；没有结果时显示已有诊断和跨日入口，原日期的起止参考必须标明尚未核实，不能冒充推荐。
5. 换待办仍保留时长和番茄／提醒／备注。AI估时可作为参考，自定义查找中用户主动「采用预计用时」才改变查找时长；迟到估时不能改写已沿用或手动修改的时间。普通新建继续先按AI预测推荐，保持此前用户要求。
6. 推荐继续使用当前避让、前后缓冲、每周规则、截止及日历规则。自定义弹窗默认五个方案，支持原跨日／分段流程；不复制源规划曾经使用的旧推荐快照或查找豁免。
7. 原待办已过截止或正在专注／暂停时沿用现有明确提示，不能直接保存；用户可选择另一项可用待办。已有有效安排时先查看当前安排，并明确确认「仍追加这次规划」。

### 退出与保存

- 新页关闭后回到原规划所在页面；原日期及全天时间轴保持原状态。
- 初始带入设置与推荐也属于有内容的新草案。未保存离开提供继续编辑／保留本机草稿／放弃，不能因为用户尚未触摸表单就直接丢弃这组内容。
- 暂存按当前账号及成员保留全部用户字段与固定新规划UUID，沿用现有最多5份、主动保存、修订和重复提交保护。来源显示「沿用规划设置」，恢复无需原规划继续存在，推荐与追加确认都重新复核。
- 只有「保存规划」或「保存并开始专注」成功才新建正式规划。保存成功刷新原页面；失败保留表单与相同目标UUID，可以修正、重试，不显示成功。

## 4. 数据边界与可靠性

采用独立、不可变的设置载荷，明确白名单；不复用可变原对象、不把源块传作编辑器的block参数。

| 可以带入 | 必须重新生成或保持空值 |
| --- | --- |
| 合法区间时长、备注、提醒分钟、单轮番茄、轮数 | 新规划UUID、起止、新创建／更新时间、本机设备及同步元数据 |
| 原待办UUID作为待复核候选 | 最新选定待办标题快照；新规划planned状态与manual来源 |
| 页面内的来源提示 | actualFocusSeconds=0、空专注记录ID、空calendarEventId、未删除状态 |

- 读取源块时验证当前账号／成员、真实UUID、未删除、无同步冲突、合法状态与时间、受支持配置；读取原始行后再解码，不能靠fromJson默认值或枚举clamp掩盖坏值。读取使用现有账号数据库，不扫描全部规划或专注历史。
- 配置沿用现有可选值：番茄15／20／25／30／45／60分钟，轮数0–6，提醒0／5／10／15／30。异常旧值明确说明不能复用，不静默换成默认值。固定轮数对应时长超过时段时保留原有可见提示，允许用户主动修改。
- 原规划始终按现有状态参与占用；所有复用推荐与保存请求excludeBlockId为空，不能因“来源”跳过原块、其他同待办规划或缓冲。
- 源读取成功后的载荷是一次设置快照。之后源被改动或删除，不改写新草案，也不要求保存新草案时修改源；目标待办、占用、成员身份和已有安排在提交前重新检查。
- 不继承源的完成／漏做／取消／跳过或运行状态。合法已完成、漏做、取消、跳过的真实规划均可提供设置来源；漏做恢复入口继续保持原流程与文案。
- 复用入口在单段和分段保存中统一接入当前已有安排快照和追加确认，确认后的变化在写事务中再次检查。不把本次确认带到草稿恢复或另一个目标待办。
- 使用现有严格新建保存、事务前置守卫、推荐／手动时段检查和固定UUID重试；若保存结果不确定，先核对目标UUID，不另生成UUID重复追加。已存在但字段矛盾时提示核对，禁止覆盖。
- 新草稿来源reuse仅扩展既有字符串白名单及展示；不需要数据库字段或表迁移，旧来源和旧草稿继续可读。恢复后只需用户字段与目标身份，不持久化可用于修改源块的权限或旧占用凭证。
- 打开、读取、推荐、切换待办及放弃草案不写正式规划／oplog，不启动专注或安排提醒；主动保留仅写本机草稿。正式保存／开始专注才使用已有对应业务流程。

## 6. 验收标准

1. 使用带大量历史投入、专注ID、日历ID和完成状态的源，核对新UUID、planned／manual、零实际、空历史绑定；源行和旧专注／日志逐字段保持不变。
2. 当前待办保留具体UUID；已完成／删除／冲突不默认选中其他待办。覆盖独立成员完成、同名任务、重复系列不同期次和身份切换。
3. 查询按原60分钟，AI返回30或90分钟仍不覆盖；换待办、手动调整、采用另一推荐、迟到估时和恢复草稿都有定向断言。普通AI新建及拖动新建行为继续通过。
4. 原时段／邻近缓冲仍被占用，不存在excludeBlockId绕过；午休、用餐、周规则、截止、全天／跨天手机事件及日历读取失败仍走现有流程。
5. 无结果可以诊断／查后续7天；推荐采用后不直接保存。分段仍先审阅整组、确认追加并原子保存；固定轮数不被无提示地改写。
6. 有安排时明确追加；确认后新增安排、待办完成、删除、专注启动、成员切换均在提交前拦截，失败保留草案。
7. 无效源、已删除源、坏时间／枚举／配置、旧schema、查询失败、连续点击及页面关闭迟到均有用例。打开后源变化不污染载荷。
8. 未触摸的带入草案退出也受保护；暂存恢复字段一致、限额不变、旧草稿可读。保存后清理失败／结果不确定／重试不产生第二个新规划。
9. 通过真实菜单完成「已有规划→照此新建→换推荐→保存→回原页面」；同时检查取消零业务写入、已有源保持不变、首页概览和复盘只增加真正保存的新块。
10. 手机320／390、横屏720×360、桌面、深浅色和1.8倍字体检查；设置仍紧凑并排，新增提示不挤占全天时间轴，不增加时间轴滚动。交付本轮测试、相关静态分析、正式Web构建及截图；真机／真实日历／多设备未验证时明确列出。

## 7. 批准后的顺序

先建立字段隔离和时长防覆盖用例；接入真实菜单及整页新建；补齐源读取、追加确认、草稿和保存保护；运行相关回归、静态分析、正式Web构建及浏览器流程验收。提交本轮验收报告，等待用户确认通过后再准备第十七轮。
