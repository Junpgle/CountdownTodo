# 第33轮方案：习惯长按打卡防误触与辅助操作

日期：2026-10-22（北京时间）

状态：**实施完成；习惯定向验收通过；全量回归另有两项财务 UI 失败，待用户验收**

## 1. 建议与收益

修正习惯打卡“长按蓄力”设置与实际操作不一致的问题，并补齐这组交互的回归测试。打开“长按蓄力打卡”时，界面说明承诺长按约 0.6 秒、防止误触，但当前代码在任何松手时都会打卡；短按反而也会立即完成。用户打开防误触选项后仍可能因轻碰而记入记录。

建议将长按模式定义为：**按住达到 560 毫秒才打卡，提前松手、移出按钮或系统取消触摸都不打卡**。关闭长按模式后仍保持轻触即打卡。屏幕阅读器与键盘通过按钮的可访问操作仍可立即打卡，不要求模拟长按。

这是一项边界明确的习惯操作优化：只改习惯打卡触发组件、对应设置文案与回归覆盖，不改习惯数据模型、存储格式或同步协议。

## 3. 用户操作与触发规则

| 设置与操作 | 预期结果 |
| --- | --- |
| 关闭“长按蓄力打卡”，轻触并松开 | 打卡一次，保留现有庆祝效果。 |
| 开启“长按蓄力打卡”，按住少于 560 毫秒后松开 | 取消蓄力并恢复按钮状态；不写打卡、不触发成功震动或粒子效果。 |
| 开启长按，持续按住达到 560 毫秒 | 达到阈值时打卡一次并触发成功效果；随后松手不得重复打卡。 |
| 开启长按，在 560 毫秒前移出按钮 | 取消本次操作；随后松手不打卡。 |
| 开启长按，在 560 毫秒前收到 PointerCancel | 清除蓄力状态；不打卡。 |
| 屏幕阅读器激活或键盘激活聚焦的打卡按钮 | 立即打卡一次，不要求长按；按钮名称和操作提示说明当前模式。 |

设置副文案会说明“轻触会取消，按满约 0.6 秒才打卡”；长按关闭时仍清楚提示“轻触即发”。现有模式默认值与 SharedPreferences 键保持不变。

## 4. 实施范围

1. 调整 `HabitCelebrationTrigger` 状态机，让长按释放只负责取消未完成蓄力；达到阈值后沿用现有一次性完成路径。
2. 复核移出范围、PointerCancel、组件禁用、回调为空和手势结束等状态，确保动画控制器与下一次按压状态复位。
3. 为语义激活和键盘激活提供可访问的立即打卡操作；触控长按规则不阻断辅助技术操作，也不让操作冒泡到习惯卡片导航。
4. 更新设置说明，准确描述短按会取消蓄力。
5. 修复现有测试缺少的组件导入，保留现有断言；增加短按取消、阈值恰好触发一次、移出取消、PointerCancel、禁用态和辅助操作覆盖。若测试揭示生产组件还有状态错误，再修复该组件，不删除仍有效的测试。
6. 达标盖章动画按卡片可见性延迟播放：若习惯在切换到专注页、卡片尚未滚入视口或其 `TickerMode` 被关闭时达标，只记录一个待播放状态；卡片滚动进入可见区域且动画可运行后再播放一次。首页和专注页可能同时挂载同一习惯卡片，待播放事件按习惯 UUID 与逻辑日期共享并且只允许一个可见副本领取，避免隐藏副本先播放或切页后重复播放。卡片已经可见时仍即时播放。盖章动效对应的震动随动画一起延后，不在用户看不到卡片时提前触发。

预计修改 `lib/features/habits/widgets/habit_checkin_button.dart`、`lib/features/habits/widgets/habit_celebration_settings_dialog.dart`、`lib/features/habits/widgets/habit_card.dart` 和相关习惯 Widget 测试，必要时增加局部测试辅助代码。项目已依赖 `visibility_detector`；无需新增依赖、数据库迁移、服务端改动、权限变更或平台原生代码。

## 6. 验收标准

1. 轻触模式打卡恰好一次；长按模式下 559 毫秒松手不打卡，达到 560 毫秒打卡一次且后续松手不重复。
2. 长按未达阈值时移出按钮或收到 PointerCancel 均不打卡；之后重新按压可以正常使用。
3. `enabled: false`、无回调时不写入；父级卡片点击不被触发。
4. 屏幕阅读器语义操作和键盘激活在长按模式下仍可完成一次打卡，并有准确的按钮名称／提示。
5. 在卡片视口外或 `TickerMode` 关闭期间达标时，不启动盖章控制器，也不提前触发盖章震动；滚动进入视口后播放一次，确认后续 rebuild 不重复播放。已在视口内达标仍即时播放。
6. `flutter analyze test/features/habits/habit_celebration_test.dart`、完整 `flutter analyze`、定向习惯 Widget 测试与完整 `flutter test` 通过。若环境权限再次阻断 SDK，先复用可用 Flutter 缓存/设备路径或申请相应运行权限；不得把未执行的测试写成通过，也不得因此静默删测。
7. 提供真实界面图片证据，至少展示长按设置说明、蓄力状态和延迟盖章后的卡片；验收报告区分自动化触控测试与实际设备／浏览器操作证据。
8. 验收后只暂存本轮明确文件，检查暂存清单和 `git diff --check`，创建一个范围清晰的本地 commit；保留工作区既有 Android 修改，不推送。

## 7. 风险与回退

改变的是已开启长按模式下的短按语义，用户轻触后不会再产生打卡。该行为与设置文案“防止误触”一致；轻触打卡仍可通过关闭长按设置使用。辅助技术和键盘路径单独保留即时激活，避免把防误触变成可访问性障碍。若触控或辅助操作验收失败，本轮不提交 commit，修复后再完整复测。
