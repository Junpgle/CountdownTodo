# 首页方案：合并今日日程与今日规划

日期：2026-10-16（北京时间）。状态：待用户确认，尚未修改功能代码。

## 现状与建议

当前 `CourseSectionWidget` 的今日日程已经混排课程、固定日程、待办规划、带时间的待办和手机日历；`PlanBlockTodaySection` 又显示规划统计、规划列表和快捷操作。相同规划存在重复展示，两个模块的标题、卡片和操作入口也不统一。已检查现有源码及本地上一轮界面截图；截图是历史合成数据验收图，不作为当前运行结果。

建议合为一张「今日安排」卡片。统一展示时间顺序，保留各来源自己的业务含义、统计和详情入口。首页回答当前和接下来做什么，完整安排与复盘留给现有页面。

## 推荐视觉：统一时间线

- 只有一层外卡片，内部以时间列、细连接线和无独立边框的内容行组织，避免卡片套卡片。沿用 Material 3 动态配色和现有玻璃开关；壁纸之上仍应有足够的背景填充保证可读性。
- 标题栏为「今日安排」、统计、折叠；副标题概括当前与接下来数量。点标题或箭头收起，收起只保留标题与下一项简短摘要；仍能进入统计，按账号记忆。
- 展开后用一行可换行的「规划预算 · 有效专注」摘要代替三块大指标。完整的已结束规划完成数、专注明细、未关联记录及待核对入口放入现有复盘。窄屏或大字体时摘要收为「规划概览」。预算只计规划，不把课程、固定日程和日历时长混入，也不生成混合完成率。
- 正在所处时段使用主题浅底和明确文字「时段进行中」；仅真实番茄运行时才显示专注运行态。接下来按开始时间排序；行中固定显示来源及地点或关联待办等必要信息，标题优先。
- 默认最多五条主要事项，为漏做／需处理的规划保留一条紧凑入口，其余按当前、未来的时间顺序选取；若当前重叠多于展示上限，显示准确的「另有 N 项同时进行」入口。冲突沿用原检测结果，不仅凭时间重叠新增冲突判定。
- 已结束默认折叠为一行，不用上午的历史占满首页。时间结束与任务完成分别表述，漏做或需核对项不能只埋在已结束中。全天项单独汇总，跨午夜行标明日期。
- 今日结束时仍保留今日标题和今日统计，在底部提供「明日安排」预览入口；不自动将整卡替换为明天，避免两个日期的列表和统计混淆。

交互示意提供「统一时间线」和「当前优先」两个版式。后者将当前项做为较大的主区域，更突出单项，但在多事项同时进行时不如时间线清楚，故推荐前者。示意全部使用合成数据，不代表 Flutter 已实现。

## 交互与保留能力

1. 同一规划按 UUID 只显示一次；已关联规划的带时间待办不再额外重复。跨来源同名事项不按标题自动合并。
2. 规划行点开后保留对应规划查看／编辑、投入明细、手动完成以及已有恢复操作，按状态显示；手动完成仍经现有确认流程。课程、固定日程、待办及日历行进入各自现有详情，手机日历继续只读。
3. 底部「全部安排」进入当天的规划页面；新增固定日程和安排待办的入口收进原有操作菜单，避免标题栏拥挤。统计进入当天复盘；子操作不得触发外层导航。不再让整张卡片的空白区域隐式导航。
4. 继续保留未关联规划的专注、记录待核对、冲突及漏做入口，首页以按需出现的简短入口承载，详情在原页面查看。
5. 所有动画遵循全局设置；折叠记忆按账号隔离。适配浅色、深色、玻璃、320宽和1.8倍字体，操作能换行，页面统一滚动，无内部滚动列表。

## 接入范围与兼容

- 增加统一的首页安排组件与展示投影，接入首页；重用既有规划统计／身份校验／快捷操作，按真实发生时间与来源标识进行排序和去重。
- 课程、固定日程、手机日历和规划分别适配数据源；错误局部显示并可单独重试，日历权限关闭不影响其他来源。维持现有日历授权方式与缓存，不因合并扩大读取权限。
- 避免保留两套读取规划和漏做维护。现有日程加载含自动标记漏做，规划卡片另有维护服务：实施时统一业务维护边界与并发保护，显示、折叠、展开及局部重试不额外写业务数据，不更改漏做判定或手动完成规则。
- 保留现有有界规划展示思路；合并后再做统一的候选选择与最终展示上限，不能只合并两组各自取前五条的结果后宣称全局正确。记录实际查询及候选返回范围；不预先宣称整个首页查询已有界或性能提升比例。
- 首页布局设置合并模块入口。每个设备布局分别迁移：优先原可见「今日日程」所在位置，否则采用可见「今日规划」的位置；两个均隐藏则继续隐藏。原各来源显隐转为合并卡片的内容设置，原隐藏来源不因迁移被悄悄打开。其余模块相对顺序保持；原两项跨主页／专注页时，新卡片仅出现在选定位置。
- 变更限于首页安排、布局兼容和必要的共享展示层，不涉及后端、同步协议、业务存储格式或发布；工作区已有大量未提交修改，实施前逐路径核对并保留。
