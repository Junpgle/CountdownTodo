日期：2026-10-11（北京时间）。用户已回复“通过，请继续”，第十轮验收通过。本轮状态：**用户已批准实施；代码、相关回归、预览和正式 Web 构建已完成，验收结果见[交付报告](../reports/2026-10-11-plan-split-scheduling-acceptance.md)，等待用户验收**。

## 1. 解决什么问题

让同一个待办的一次安排，可以拆成多段可用时间，先审阅整组结果，再一次保存。

例如要安排90分钟，今天只有10:10–10:55和15:00–15:45两段可用时间。现在必须寻找连续90分钟，或者手工新建两次。本轮可以给出“45分钟＋45分钟”的完整方案。每段都避开课程、日程、既有规划及用户的休息时间，遵守第十轮的前后缓冲。

这连接了项目已有的待办估时、待规划清单、空闲查找、草稿、番茄、时间轴和真实投入复盘。同一待办已经允许多个规划块，适合补齐批量审阅与可靠保存能力。

本次源码核查：

| 位置 | 已有能力和本轮需要补齐的部分 |
| --- | --- |
| `lib/models.dart`的`TodoPlanBlock` | 每块有独立UUID，关联具体待办UUID，包含时段、提醒、番茄和实际投入；没有要求一待办只能一规划 |
| `PlanAvailabilityService.find/accepts` | 当前每条候选必须独自容纳全部`query.minutes`，返回若干单段替代项，不会组合碎片 |
| `PlanAvailabilityRepository` | 已有最新来源读取、缓冲、日历降级及单块保存守卫；范围读取最多7天，需新增有缓冲的分段范围快照 |
| `StorageService.savePlanBlockEdited` | 单块条件事务写入规划及oplog，不能循环调用来宣称整组原子保存 |
| `StorageService.savePlanBlocks` | 普通批量写入含replace行为，缺少本功能所需的整组身份、占用和新建UUID守卫，不能直接替代严格批量保存 |
| `PlanEditorDraftRepository` | 本机按账号／成员最多5份，当前格式v1仅有一个时段和目标UUID；分段需要完整载荷及多目标校验 |
| `PlanTodoGuard`／待规划 | 已有当前成员完成覆盖、专注保护、已有安排快照和追加确认，可复用到整组 |
| `PlanReviewRepository` | 按真实规划和具体待办关联投入，适合正常统计多个独立规划；不能把分段序号当新待办或额外完成次数 |

这是当前源码调研，不是新功能运行或测试结果。AI的`split_todo`会拆分待办实体，不能用来实现本方案的执行时间分段。

## 2. 使用流程和界面

### 进入分段安排

- 普通整页新建规划的推荐区增加轻量入口“分段安排”。首页待办编辑、待规划清单和时间轴新建共用该入口。
- 当连续时段无结果时，在现有提示旁提供“试试分段安排”；不会自动替用户切换，也不重新引入“AI帮我安排更多”按钮。
- 点击进入独立的“分段安排”页面。原单段时段、备注、番茄和提醒保留；返回且未采用方案时不改变原表单，不写业务数据。
- 目标待办固定为原具体UUID，只允许当前成员未完成、未删除、无冲突且不在专注／暂停的任务；重复待办绑定具体期次，不按标题或系列替换。

### 设置和完整方案

页面先显示一行当前条件与“修改条件”，下方只放推荐结果。条件表单放在弹窗内，宽度足够时并排，窄屏大字体换行；不在新建页叠加长表单，不改变24小时时间轴的拖动或高度。

默认值及范围：

| 条件 | 默认与允许范围 |
| --- | --- |
| 本次总时长 | 使用原编辑器当前时长；其初始化仍先用已有估时。用户已手改的值优先；估时未完成则等待，失败要求手填，不先按30分钟查找 |
| 总时长范围 | 30–720整数分钟；少于30分钟引导使用连续安排，不制造两条不足15分钟的规划 |
| 单段最长 | 默认45分钟，可选25／30／45／60／90／120，自定义15–120整数分钟 |
| 单段最短 | 15分钟，条件摘要明确显示；尾段不足15时调整前段分配，不生成微小尾段 |
| 日期范围 | 默认原选择的当天；可主动扩为从该日开始3天或7天，最多7个本地自然日；过去日期要求用户修改，不静默挪到今天 |
| 每日窗口 | 继承当前查找窗口，否则沿用08:00–22:00，可修改 |
| 避让及缓冲 | 先恢复当前账号设置；当前已有显式一次性无缓冲选择时予以保留并标明。条件弹窗复用第十轮控件、记忆、重置与失败提示 |
| 结果 | 默认最多5组完整方案，可能少于5组；每组2–6段，所有段合计严格等于总时长 |

示意内容（不是实际界面截图）：

```text
分段安排
90分钟 · 每段15–45分钟 · 当天 · 前10后5     修改条件

方案1    2段，共90分钟
10月12日 10:10–10:55     45分钟
10月12日 15:00–15:45     45分钟
                                采用这组
```

每组显示日期、每段起止及分钟数、总分钟数、来源覆盖及是否仅检查应用内安排。不存在把两个候选“择一”误显示成“已安排两段”的语义。

不足以组成完整方案时明确说明当前范围、总时长、最短段和最多6段等条件。提供修改条件、返回连续安排；当前缓冲非零时可显式“本次不留缓冲重试”。不偷偷少安排一部分，不自动扩天、不自动减小时长或缓冲。若展示已发现空闲作为参考，必须标明“尚不足以组成完整方案”，不能采用或提交它。

### 采用后再保存

- “采用这组”返回原整页编辑器，只填入分段草稿，不立即保存。
- 原单段开始／结束区换成“共2段 · 90分钟”和紧凑时段列表，避免把10:10–15:45整个跨度画成连续占用。可“重新选择方案”或“返回单段”。
- “调整本段”只修改该段起点并保持该段时长，复用时段选择；其他待存段作为临时占用参与检查。调整后整组失效状态需重新校验。改变各段长度通过修改条件重新生成，避免出现总量悄悄减少。
- 返回单段恢复切换前单段的时段和查询，不把整组跨度变为一条规划。备注、提醒和番茄等共同字段保留最新编辑；切换导致丢弃已改的分段内容时明确确认。
- 共同备注、单轮番茄、提醒应用于每段；番茄轮数标明“每段番茄轮数”，默认沿用原“按规划时长”。若原来手工指定固定轮数，预览明确显示每段固定轮数及其专注时长，提醒这可能长于该段，可主动改为按各段时长。切换不能静默把固定轮数倍增成“整组轮数”。
- 底部按钮改为“保存全部2段”和“保存全部并开始第1段”。后者仅在全部保存成功、重新核对首段和专注状态后，明确启动第一段；不自动串行启动后续段，不把所有分段总分钟数绑定第一段。
- 这次总时长是用户确认的“本次安排时长”，不是任务剩余用时。已有规划和历史专注不自动扣减估时；有其他安排时显示并要求明确确认追加。

## 3. 分段计算规则

1. 同一个具体待办、固定账号及成员、同一组查找条件。总时长采用整数实际分钟，所有分段大于等于15、不大于单段上限，数量2–6，总和必须严格相等。
2. 一次读取最多7天及所需邻日缓冲的来源快照，在同一版本条件下生成方案；避免逐段重复加载全部待办／规划、逐任务估时或请求远程AI。
3. 复用课程、固定日程、有效规划、兼容旧执行区间及可读取手机日历的占用规则。先用原手机事件判断全天／跨天排除，再算缓冲；专注和时间日志不变成预约。午休／用餐避让保持原区间。
4. 开始前B、结束后A沿用第十轮`[u-A,v+B)`规则。新分段也互相检查：前一段结束到后一段开始至少`max(A,B)`，因为两段共享同一段空闲间隔，不能忽略它，也不能重复扣成`A+B`。B=A=0时可贴边。
5. 每段位于某个当地自然日的有效窗口内，最晚可到次日00:00；不把一个段跨午夜拼成连续两天。截止截取沿用定时截止和日期截止的区别；日期范围用日历日期构造，不用固定24小时推算。
6. 时长以真实时间戳差计算。夏令时重复小时必须通过时区偏移／辅助说明区分，不能用同一墙钟文字去重为同一时段；缺失小时不能生成不存在的本地时间。
7. 从合并后的可用区间中进行有界组合搜索，允许调整各段分钟数，防止“45＋5不合法”时错过“35＋15”。排序先偏好更少段，再更早结束，最后按稳定起点序列；去重按全部真实起止时间。
8. 不只拿现有前5条单段推荐拼组，也不声称能给出数学上的全局最佳日程。候选搜索覆盖所声明的7天、6段和分钟界限；设置运算上限时，达到上限明确显示“搜索未完成，缩小条件后重试”，不能报告成“没有空闲”。
9. 修改任务、总时长、窗口、范围、避让、缓冲、账号／成员或来源刷新，使整组推荐失效；请求序号与生命周期保护防止旧方案覆盖新条件。前台恢复及跨过段起点时复核，不后台定时轮询。

## 4. 整组保存与失败处理

新增编辑器专用的严格批量新建路径，复用单块已有规则；不修改普通同步导入的批量replace语义。

保存前：

- 捕获账号／成员身份、具体待办UUID、当前安排快照、条件指纹、草稿修订和固定目标规划UUID列表。
- 重新读取实际待办、截止和所有范围来源；手机日历绕过旧缓存。原先计入手机日历、现读取失败时整组阻止保存，只能由用户明确改为仅检查应用内安排；覆盖说明随之更新。
- 默认设置指纹同时包含避让选项及前后缓冲；当前明确的一次性覆盖单独标记，不能借默认值校验悄悄取消覆盖。
- 有其他未来安排时，整组只确认一次已展示的追加快照；保存事务中再次变化则拒绝，不重复询问每一段。

同一个SQLite事务内：

- 复核身份、当前成员的未完成状态、删除／冲突／专注状态及截止，草稿修订、已有安排快照和所有新UUID。
- 重新核对本地课程、固定日程、有效规划与设置；所有待存分段之间也互相检查。
- 任一段非法、失效、被新增占用挤占缓冲或新UUID被占用，整组拒绝。不得先写第一段，再在第二段失败后留下半组。
- 所有段及各自正常oplog一起写入；只写实际时段与分钟数。规划、oplog、事务性审计一起回滚，不写缓冲记录，也不新增待办。
- 成功后只触发一次数据刷新／同步请求。提醒及其他既有后续处理在提交后运行；后续处理失败明确区分“规划已保存”和“处理未完成”，按现有规划UUID重试，不重复建段。

可靠重试：整组首次采用时分配稳定目标UUID，连点及响应丢失重试均复用它们。全部目标存在且与这次内容／身份相符时识别已保存；部分存在、内容变化或删除时提示核对已有规划，不能自动再生成一组或覆盖远端编辑。专注启动／状态保存失败只重试已保存首段的后续动作，保持原运行标记识别，不能产生第二次专注。

本机整组事务不等于多设备或系统日历的原子预约。各规划继续按现有协议独立同步，远端可能分批到达；本轮不承诺云端整组锁或跨设备同时回滚。

## 5. 草稿、恢复及已有功能

- 分段编辑沿用“继续编辑／放弃修改／保留草稿并离开”和主动暂存。整组计作1份草稿，共享现有每账号／成员最多5份容量，不挤成6份，也不静默清理旧稿。
- 扩展本地草稿载荷到v2：保存单段／分段模式、各段真实起止与稳定UUID、总时长／单段上限、日期范围、共同字段、来源入口和时间偏移；不保存可用性快照、手机日历内容或追加授权。
- 复用`local_plan_editor_drafts`现有表；`target_uuid`保留组内第一个稳定目标作为摘要锚点，完整目标列表放版本化JSON；摘要显示最早／最晚日期和“2段／90分钟”，不能显示为连续跨度。计划不改数据库结构及schema58。
- 原v1单段草稿继续读取并保留原UUID。普通单段仍可写v1；分段v2必须用独立严格解析，未知／坏格式保留可管理，不当空表单。旧客户端对v2至多提示不可读，不主动清空。
- 从已有v1草稿切分时保留原目标UUID作为第一段，其余新分配。修订校验同时保护整个载荷；取消切分不覆盖原草稿。每份仍有256KiB载荷限制，超限失败保留当前编辑。
- 恢复完整时段与配置，不自动估时覆盖、不自动移到今天；时区变化提示重新核对。避让及缓冲恢复当前账号默认，旧一次性放宽不跨恢复成为长期授权；整组重新验证并重新确认追加。
- 正式保存后清理匹配修订的整组草稿。清理失败单独提示；再恢复时按全部目标UUID检查，已保存则查看，部分或变化则核对，不重复新建。
- 每段保存后就是正常独立规划，继续支持现有拖动撤销、单段改期、提醒、番茄绑定与真实投入明细；待规划清单按已有规则归类。复盘的规划数按真实块数，待办仍只有一个UUID，专注仍按记录UUID去重。
- 本轮支持普通新建入口；不批量拆改已经存在的规划，不把冲突调整／漏做恢复的原记录转换为多目标。后续可另行提案扩展，原功能保持可用。

## 7. 验收标准和交付

| 场景 | 必须证明的结果 |
| --- | --- |
| 90分钟、两处45分钟空闲 | 原连续模式无结果；分段得到完整2段，总和90，采用／取消不写正式业务数据 |
| 50分钟、上限45、下限15 | 能分配35＋15等合法组合，不漏报成无结果、不生成5分钟尾段 |
| 缓冲与段间关系 | 前10后5时相邻新段至少10分钟；允许恰好满足；双侧互换、0和午夜边界测试 |
| 午休、课程、手机事件 | 保持有效来源和避让规则；同日近午夜手机事件可影响邻日，原跨天事件不占空闲 |
| 不足、截止、范围上限 | 不提交部分总量，不自动扩天或放宽；日期截止／定时截止正确；搜索限额不冒充无空闲 |
| 身份与重复期次 | 账号／成员切换、完成／删除／冲突／正在专注拒绝；只关联原具体待办UUID |
| 原子保存 | 第2段写入或oplog故障、读后新增邻项侵入缓冲、事务内状态变化：正式规划和oplog均零新增 |
| 连点和响应丢失 | 整组只有固定的2–6个UUID；重试不重复；部分已存在或内容变化不覆盖 |
| 专注与后续处理 | 只绑定首段及该段时长；提交失败不启动；启动／状态失败重试不重复建段或专注；通知失败诚实反馈 |
