# 第十七轮方案：首页今日规划卡片对账与快捷操作

日期：2026-10-15（北京时间）。第十六轮已交付，用户要求准备下一轮。**实施、折叠与视觉优化已完成；用户于2026-10-16验收通过，要求准备第十八轮方案。**

## 1. 建议与收益

优化首页「今日规划」卡片：与规划中心、规划复盘使用相同的真实统计，优先显示今天正在进行和接下来的安排，每项可直接查看规划或投入明细。

例如上午已经完成五项，下午还有两项未开始。当前卡片固定按开始时间取最早五项，下午的安排会被挤掉；原实际投入缓存较大时，卡片还可能显示很高的“达成率”，与规划中心数字不同。本轮同时修正信息可信度和日常查看成本。

第十五轮改的是**规划中心顶部**，当时明确没有扩展首页卡片。本轮补齐首页入口，复用已有统计和操作，不再新增一套复盘页面。

## 2. 当前源码核对

| 位置 | 已确认的现状 |
| --- | --- |
| `lib/widgets/plan_block_today_section.dart` | 计划汇总所有未删除块，含取消／跳过；实际取逐块关联记录与缓存中的较大值，再算百分比 |
| `_isRecordAssociatedWithBlock`／`_blockRecordsMap` | 支持旧ID列表、同待办重叠和同标题重叠；同一记录可能进入多个块，标题匹配也不同于复盘的唯一归属 |
| `_freeRecords` | 未被上述匹配吸收的记录统一称“自由专注”；未关联规划不等于没有绑定待办，也可能存在归属待核对 |
| `_buildBlockList` | 按开始时间取最早五项；有记录或漏做时才可展开，普通未来规划的行本身没有直接查看操作 |
| `_buildRecordList`／自由专注区域 | 内联渲染全部记录，没有数量上限；历史较多时卡片变长 |
| `_loadData`／`didUpdateWidget` | 加载时整卡换骨架；没有本组件的异常展示、请求序号和午夜刷新；只因refreshTrigger变化重读，未单独处理username变化 |
| `home_dashboard_view.dart` | 通过_scheduleRevision刷新卡片，整卡点击进入规划中心；需要保留该入口及返回刷新 |
| `PlanReviewRepository`、`PlanDayOverview` | 已有共享聚合、唯一归属、账号／成员复核、详情分页及可见页面边界刷新，可复用 |

当前卡片还在加载过程中自动标记漏做；这属于既有业务维护，不能把展示口径替换进去后悄悄改变它。以上是源码调研，尚未运行本轮复现、测试或性能测量。

实施接入补充：HomeLayoutService的布局白名单缺少planBlocks，导致卡片可被布局归一化过滤。为落实已批准的真实首页入口，补齐手机主页／宽屏右栏默认项及设置页名称和图标；沿用旧布局兼容规则、保留其他相对排序和显式隐藏值，移除首页对该项强制设为可见的旧覆盖。新增展示刷新仍不额外触发漏做维护；旧维护保留判定，并用已有条件保存防止覆盖并发编辑和身份变化。

## 3. 用户看到的界面

### 一张紧凑的今日卡片

```text
今日规划                         全部 >
计划 2小时     已结束完成 1/2     有效专注 48分

论文写作       14:00–15:00       时段进行中
整理资料       16:00–16:30       未开始
复习章节       09:00–09:30       漏做
```

示例只说明信息层级。颜色使用Material 3 colorScheme，卡片沿用现有普通／玻璃外观。取消旧百分比“达成率”和实际／计划比例，不把累计缓存当成实测投入。

- 三个紧凑指标分别对应今日真实规划预算、已结束规划的完成数／总数、今日已结束有效专注。小于一分钟显示秒数；没有已结束规划显示“暂无”。有效专注包含未绑定规划的有效记录，因此不与计划时长拼成一个进度百分比。
- 点击指标进入同一天的现有对应明细；统计图标仍进入当天完整复盘。窄屏或大字体不能放下三个指标时，改为「查看今日概览」短入口，不截断数字或强塞横向滚动条。
- 有数据问题时显示简短「记录待核对」入口，进入现有明细。空闲推荐和规划保存操作不会混入该统计读取。
- 原“自由专注”长列表改为有准确含义的「未关联规划的专注」摘要与查看入口；归属竞争进入待核对，不被称作自由专注，也不在多个块中重复展示。没有相关记录时不占位。

### 最多五项，先看到接下来要做的事

列表范围仍是**今天开始的真实规划**，与统计按本地开始日归属一致。取消／跳过不占主列表名额，仍可在全部规划及复盘中查看。

1. 优先展示时段正在进行、尚未结束的有效未完成规划；「时段进行中」只描述时间位置，不凭这个标签宣称番茄已经启动。
2. 再展示未开始的有效规划，按开始时间排序。
3. 若今天存在漏做或已结束但尚未完成的规划，为“需处理”预留至少一行，最多四行用于前两类，避免操作入口完全被未来安排挤掉。
4. 不足五行时，用其余需处理项、已完成项补齐；同类按开始时间和UUID稳定排序，每项只出现一次。未来已标完成的规划属于已完成类，不误显示成待执行。
5. 列表超过五项显示「查看全部规划」，打开今天的规划中心。全天时间轴仍保留原一屏布局和拖动新建，不新增滚动时间轴。

跨午夜规划按开始日统计一次；今天开始而明天结束的行显示完整日期范围，不能只显示一对易误解的时分。前一天开始的区间继续由原时间轴按相交范围展示，不改变今天预算归属。

### 每项可展开操作

- 所有行都可以展开，包括没有专注记录的未来规划；一次只展开一项，继续使用短动画。
- 展开仅显示该块已经唯一核实的投入摘要及两个操作：「查看规划」「投入明细」。漏做项另保留已有「重新安排」。不把全部专注记录铺在首页。
- 「查看规划」按UUID读取最新块及待办，进入现有编辑器；可在里面改期、调整设置、保存并开始专注、照此新建。首页点击不直接保存或启动计时。
- 「投入明细」进入现有按planId筛选的分页明细；累计投入和今日投入明确区分，不能用累计值冒充今日总量。没有核实记录时明确为空。
- 点击子操作只执行自身动作，不同时触发外层整卡跳转。原整卡／标题进入规划中心的操作保留，返回后刷新。

## 4. 数据、刷新和失败处理

### 共享统计，有界读取

- 在现有PlanReviewRepository内增加首页卡片读取入口，复用第八／十五轮的合法性、时间归属、唯一记录归属及聚合，不能复制一份稍有不同的SQL或Dart匹配器。
- 在同一个数据库读取事务和同一时刻取得概览、列表总量、最多五项及其投入摘要。列表筛选与排序使用数据库投影，不能先读取当天或全历史全部规划，再在界面take(5)。
- 若优先类分段查询，候选总数必须有固定上限且UUID去重；查询次数不随规划数逐行增长。投入查询复用同一归属范围，不能只在五条展示项间分配记录，否则会错误抢走未展示规划的投入。
- 新展示读取不解码全部专注记录、草稿、日志详情、趋势或排行；只在点击详情后读取对应分页。新读取方法不迁移、修补或写入业务表，不新增缓存表和同步字段。
- 取消／跳过预算、零时长、损坏行、重复UUID、显式绑定冲突、同待办重叠、未关联规划但绑定待办的记录，严格按现有复盘规则归类。缓存仅在既有需要的详情中作参考，不参与新卡片实际值。

### 不改变业务状态维护

原首页加载中的漏做维护先完成，再读取新卡片快照；保留原判定、触发及写入约束，不用新“有效专注”统计去替换原维护依据。展示与业务维护分开命名、单独测试和计数。不能宣称整个首页从此只读，也不能通过点击指标、重试统计或展开行新增维护写入。

原维护目前需要读取当天规划和专注记录，该数据成本仍单独保留并在验收中报告；本轮有界读取的承诺针对新展示入口，不宣称整个首页加载已无全量读取。新增的展示边界刷新、局部重试和展开操作不重复触发这段维护；原初始化／业务刷新触发保持原行为。

规划完成仍不等于待办完成。番茄已有完成转换、漏做恢复、冲突检查、照此新建以及协作成员完成规则继续使用原服务，本轮不重新定义。

### 明确状态并控制刷新

- 首次加载用尺寸受控的占位；同账号同一天刷新保留上次内容并标记更新中，禁用旧载荷操作。失败显示局部原因和重试，不把数据库异常变成“暂无规划”或零值。
- 午夜、规划开始／结束、专注结束、已有业务刷新、返回编辑器及前台恢复时更新。只在首页实际可见、模块启用、应用在前台时安排下一次边界触发，不按秒查询；离页和后台取消计时。
- 账号或成员切换立即清除旧数据／展开项，拒绝旧行点击。用身份、所选本地日期和请求序号拒绝迟到结果；读取、刷新及点击前后都复核。
- 首页切其他标签、关闭卡片模块及销毁组件后不继续查询。遵循现有首页可见状态传递，不能只依赖路由isCurrent判断底部标签是否可见。
- 日期边界使用本地日历构造，不固定加24小时；日光节约时和时区变化后重建范围。自动维护与读取失败不能形成持续重试循环。
- 不清空或重新加载整个首页来刷新这一张卡片；同日更新不反复切骨架。验收时检查用户已滚动的首页位置，不能主动跳回顶部。

## 6. 验收标准

1. 合成数据库构造缓存大于实际、两条40秒记录、取消／跳过、坏规划、未来已完成、未关联规划及同待办归属竞争；首页概览与规划中心、复盘在同快照／范围／时刻下一致。
2. 上午五条已完成＋下午两条未开始，下午安排必须出现在首页；同时有正在进行、未来、漏做时正确预留需处理行；排序稳定、总数准确、最多五项、不重复。
3. 不因只显示五条就改变专注归属；未展示规划也参与唯一归属计算。同标题不同待办不能借旧标题匹配冒认投入；秒数先汇总再格式化。
4. 大量无关历史、当天大量规划和专注仍只返回固定上限的卡片投影；记录SQL及返回行数，确认无逐块查询和全量详情解码，不给未经测量的性能比例。
5. 所有行可展开，查看规划进入正确UUID；投入明细与今日／累计范围匹配；漏做恢复、冲突检查、照此新建、保存并开始专注保持原行为。子操作不触发外层跳转。
6. 快速刷新、读取失败、旧数据、账号／成员切换、午夜、规划起止、前后台与隐藏标签覆盖；没有持续轮询、旧身份数据闪现或离页迟到导航。
7. 跨午夜、纽约及半小时夏令时边界、已删除待办历史标题、零记录与全取消样本有定向测试。运行中的番茄不冒充已结束实测投入。
8. 对新读取、重试、展开与指标导航验证零新增业务写入；原漏做维护及实际编辑／恢复另计，证明没有被展示口径改写。
9. 浏览器从真实首页检查390／320手机、720×360横屏、桌面、深浅／玻璃和1.8倍字体；展开、回到首页、局部错误及中途滚动位置可核对，卡片不无限增长。
10. 批准后执行本轮相关回归、静态分析、正式Web构建与合成数据浏览器验收，交付截图和实际命令结果；原生真机、真实日历及多设备未测时列明，不沿用第十六轮832项作为本轮证据。
