# 第31轮方案：规划复用设置兼容与明确修复

日期：2026-10-21（北京时间）

状态：已实施，待用户验收

## 1. 建议与收益

“照此新建”应当复用原规划的可用设置，并让用户继续选择新时段。目前，来源规划的提醒、单轮番茄或轮数只要不在当前选项白名单内，复用读取就会整体失败；用户只能手动重新创建。另一个相近流程“重新安排漏做规划”会用默认值替换不受支持的设置并提示，但提示是合并文案，两个流程处理不一致。

建议统一这两个规划入口的设置修复规则：保留仍受支持的原值，只把不受支持的单项替换为当前默认值；明确展示每个被替换的字段和新值；复用来源时，要求用户确认后再进入新规划编辑。这样能继续复用原规划，而不会悄悄改变设置或触碰来源历史。

## 3. 产品行为

- 支持的来源设置保持原值，不增加额外确认；标准来源仍按原流程进入新规划编辑页。
- 如果来源的提醒、单轮番茄或番茄轮数有不受支持的值，只替换受影响的字段，其余有效值和备注照常沿用。默认值为：提醒5分钟、单轮番茄25分钟、轮数0（按规划时长）。
- 用户点击“照此新建”后，若会替换设置，先显示确认说明，逐项列出来源值和拟使用的默认值，例如“提前提醒：7分钟 → 5分钟”“番茄轮数：7轮 → 按规划时长”。用户可取消，或确认后进入整页编辑。
- 整页编辑顶部保留简短提示，明确这是新规划、哪些字段已按默认值调整；用户可在保存前自行修改新规划的值。
- 漏做规划恢复使用同一设置修复规则，显示具体字段及替换结果。确认恢复只创建一条新的规划；来源漏做记录、专注记录和历史标识不变。
- 若原规划时长无效，继续沿用现有安全边界：复用流程仍要求1–1440分钟的整分钟区间，恢复流程仍用有效计划时长、有效区间时长或30分钟，并给出明确时长提示。本轮不放宽这个边界。
- 结构性无效仍阻止复用或恢复，包括来源已删除、有同步冲突、身份缺失、时段非法、待办不可安排或数据库结构读取失败；不得用默认值掩盖这些情况。

## 4. 界面方案

- 在规划复用菜单动作之后、打开新规划编辑页之前，展示紧凑确认对话框。标题说明“部分设置需要调整”，正文逐项呈现“原设置 → 新规划将使用”，底部提供“取消”和“按建议继续”。
- 确认继续后，编辑页沿用现有“照此新建”说明样式，并用主题动态颜色的提示条说明默认替换项；不复制来源的执行进度、番茄记录关联、日历事件身份或状态。
- 恢复漏做规划时，把现有合并提示拆为具体条目，统一使用同一组字段名称和默认值。没有设置变更时不显示多余提示。
- 适配窄屏、桌面、深色模式和大字号；对话框内容可滚动，按钮始终可见。

## 5. 数据、安全与草稿边界

- 增加纯函数式的规划设置兼容策略，输入来源值、输出安全新规划值与逐字段修复说明；复用和漏做恢复共用这一规则，避免白名单与默认值继续分叉。
- 仅修复新规划草稿，不更新来源规划，不写入来源的同步日志，不继承来源的完成／漏做状态、实际专注秒数、专注记录 ID、日历事件 ID、版本或设备身份。
- “按建议继续”确认前不创建新规划或操作日志；取消时关闭确认，不留下新数据或草稿副作用。
- 账户切换、来源冲突、待办完成或删除等已有保护必须继续生效；保存时沿用现有事务内复核与目标 UUID 幂等检查。
- 被替换字段的简短说明随现有本机规划草稿一起保存；旧草稿没有该可选字段时按无提示读取，不新增数据库列或迁移。来源删除后恢复草稿仍能看到修复说明。
- 不新增数据库字段、迁移、后端接口或同步协议；不自动补造专注记录，也不改待办完成状态。
- 原有本机规划草稿功能维持隔离未保存修改规则。确认后进入编辑页仍按现有退出保护和显式保存流程执行。

## 6. 范围边界

本轮预计涉及规划设置兼容策略、`PlanReuseRepository`、漏做规划恢复提示、规划编辑器复用确认，以及对应服务和 Widget 测试。

本轮不做：

- 不扩大提醒、番茄时长或轮数的当前选项范围；不支持的值用明确列出的默认值修复。
- 不改变复用时长、时段推荐、冲突检查、待办选择或规划保存规则。
- 不回写或修复已有规划；用户必须保存一条新的规划，来源保持不变。
- 不删除仍有效的现有测试。行为契约变化时，更新对应断言并补足等价的结构性无效、来源不变和零副作用覆盖。
- 不推送代码、不部署服务。

## 7. 验收计划

1. **设置策略**：分别测试受支持值原样保留；提醒、单轮番茄、轮数单项和多项不受支持时，只替换对应字段并返回准确说明；默认值分别为5分钟、25分钟和0轮。
2. **复用确认**：标准来源不弹额外确认；有需修复字段时逐项展示原值和新值。取消后无新规划、无操作日志；确认后进入整页编辑并可调整字段。
3. **来源隔离**：确认、取消、编辑和保存前后，逐字段核对来源规划、原待办、专注记录和操作日志；仅在明确保存后创建新的规划身份。
4. **漏做恢复**：使用相同设置策略；提示精确指出被替换项。确认保存只创建新的规划，来源仍保留为漏做，执行元数据不复制。
5. **安全边界**：已删除、有冲突、无效待办、非法身份或数据库读取失败仍阻止流程；账户切换和并发来源变化保护继续有效；不受支持的时长仍按现有复用／恢复规则处理。
6. **退出与草稿**：进入新规划后，未保存修改仍受现有退出保护；草稿只保存在本机且不覆盖来源规划。
7. **界面证据**：提供手机与桌面确认提示截图，以及深色／大字号下可读性截图；验证取消、按建议继续和编辑后保存完整流程。
8. **回归验证**：运行设置策略、规划复用、漏做恢复、编辑器退出保护相关测试，定向静态分析、`git diff --check` 和 Flutter Web release 构建；按模块分批运行全量测试并记录所有失败，不删除仍有效的测试。
