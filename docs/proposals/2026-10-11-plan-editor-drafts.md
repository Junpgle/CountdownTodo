# 第九轮方案：规划草稿暂存与退出保护

日期：2026-10-11（北京时间）。第八轮已由用户回复“通过，准备第九轮方案”验收通过。本轮状态：**用户已批准实施，并于2026-10-11回复“通过，准备第十轮方案”，第九轮验收通过**。

## 1. 建议与现有依据

补齐规划编辑过程中的退出保护，并允许普通新建规划保留本机草稿、稍后继续。

前八轮已经串起待办、估时、找空闲、番茄设置、改期和复盘。现在用户可能在一页中选择待办、修改时段、填写备注、配置番茄与提醒，任何一次中途返回都可能需要重新填写。这轮直接保护这些已有操作，不再增加一套规划流程。

本次源码核查：

- `PlanBlockEditorSheet`的时间、备注、番茄和提醒配置保存在State及控制器中；`dispose`没有持久化草稿。
- 整页和底部编辑器的`PopScope`目前仅在`_busy`期间阻止退出；普通未保存修改没有离开提示。
- `_draftRevision`和`_savedDraftRevision`用于异步推荐与保存判断，不等于跨页面、跨重启的草稿存储。界面报“草稿已保留”目前指仍留在打开的编辑器中。
- 时间轴拖动、首页待办编辑和待规划清单均复用此编辑器，适合共享一套保护；漏做重排及冲突调整携带额外校验上下文，需要保持原来的保存语义。
- 现有`AiPlanDraftRepository`在确认后写入正式待办、规划及同步操作；它不是本轮所需的未提交表单暂存，不能借用它实现“保留草稿”。

以上是当前源码结论，尚未用运行时流程复现或完成新功能测试。

## 2. 用户会看到什么

### 有修改再返回

点击返回、系统返回、关闭按钮及编辑底部弹层的退出操作，统一检查是否有未保存的实际修改。

普通新建规划显示：

```text
保留这次规划？
时段、备注、番茄和提醒设置还没有保存为规划。

继续编辑      放弃修改      保留草稿并离开
```

- “继续编辑”为默认安全操作；点提示外部或取消同样继续编辑。
- “保留草稿并离开”成功后才退出，提示“已保留到本机规划草稿”。失败则停留原页并允许重试。
- “放弃修改”明确放弃本次未保存内容；如果正在恢复已有草稿，会说明也将删除这份草稿，避免下次又出现。
- 仅打开查看、自动估时或自动填入首个建议，不算用户修改；无修改返回不弹提示。修改后全部改回原值也不反复打扰。
- 保存及启动专注过程中保持原忙碌保护，不能借退出提示打断正在进行的操作。

新建页“更多”中同时提供“保留草稿”，不离开页面也能主动暂存。暂存不等于保存规划，底部“保存”和“保存并专注”的作用保持清楚。

### 稍后继续

- 规划页现有“更多”菜单增加“规划草稿”；不增加顶栏高度、常驻面板或时间轴滚动。
- 进入普通新建页时，如有同一待办的未完成草稿，显示一条紧凑提示，可主动继续；不自动把另一个待办的草稿填进来，也不拦住新的拖动操作。
- “规划草稿”进入独立短列表，显示待办标题、拟定日期／时段、上次保留时间，提供继续和删除。每个账号及当前成员最多5份，按最近更新时间排序。
- 草稿满5份时说明原因，允许去管理或继续编辑；不静默覆盖或清理最旧草稿。同一份反复暂存只更新自身。
- 恢复后沿用整页新建规划、并排配置、两个推荐结果和自定义查找弹窗；不额外展开长表单。

### 特殊编辑先保护退出

已有规划编辑、冲突改期、漏做重新安排本轮只加入“继续编辑／放弃本次修改”的退出保护，**不提供跨重启草稿恢复**。原因是这些操作绑定原规划版本、漏做来源和检查结果；暂不把这些上下文持久化成普通新建草稿，以免重新打开时失去原操作约束。

## 4. 草稿内容与恢复规则

### 保存哪些内容

保存具体待办UUID、标题快照、起止时间、备注、提醒分钟、单轮番茄分钟、轮数、入口类型、当前账号／成员、草稿ID、草稿修订号及暂存时间。来源为待规划清单时保留来源类型和具体任务，不持久化可直接放行的旧确认结果。

估时结果、推荐列表、手机日历快照、占用快照及“仍追加”确认均不作为可恢复的有效凭证。草稿也不保存运行中的专注状态、实际投入、规划完成状态或同步版本。

### 恢复时重新读取

1. 复核当前账号与成员，以具体UUID读取待办。已完成、删除、存在同步冲突或不可访问时，明确提示，不能自动换成同名待办或另一重复期次。
2. 可用时完整恢复用户字段。保留草稿中选定的时间与时长，重新估时或推荐不能悄悄覆盖它；估时仅作参考，用户仍可主动采用。
3. 起点已过去、日期已过期或时区发生变化时明确提示，不能静默挪到今天。原起止时间保留可见，用户选择新日期或时段后再提交。保存原时区偏移用于识别变化，不以固定24小时换算当地日界线。
4. 已保留的推荐结果一律作废；重新读取课程、固定日程、有效规划、旧式执行区间与手机日历，沿用现有避让记忆。全天及跨日期手机日历事项仍不占用，专注／时间日志仍不当成新预约。
5. 恢复后显示“请重新核对时段”。提交前完成最新检查，并沿用当前手动时段／推荐时段各自的确认与事务校验，不增加静默绕过冲突的路径。手机日历读取失败仍需明确选择仅检查应用内日程。
6. 待规划来源重新构建当前保存上下文。若期间已有新安排，展示最新安排，由用户再次决定是否追加；旧的追加确认不能跨恢复沿用。正在专注／暂停仍走原保护。

目标失效的草稿可查看保留内容、复制备注或删除，但不提供跳过校验直接保存。存储损坏或未来未知格式显示“草稿无法读取”，保留可删除入口，不自动转为空表单或清理其他草稿。

## 5. 保存可靠性与数据边界

### 本机独立存储

计划在账号数据库中增加一张**本地专用草稿表**，沿用现有版本迁移体系，记录当前成员ID。普通业务查询、规划统计、提醒、待规划判定均不读取该表；草稿不是正式规划，不占用空闲时段。

- 列表查询最多5份，只读取摘要，点继续再取该份完整表单；不加载全量待办、规划或专注历史。
- 新建数据库和升级迁移均测试；不从旧页面内存或AI建议自动迁入数据。
- 暂存、更新、删除通过本地事务和草稿修订号校验。两个编辑器同时恢复同一份时，后保存者发现修订变化应提示重新读取，不能覆盖先保存的内容。
- 暂存只写草稿表，不写`todos`、`todo_plan_blocks`、`op_logs`、业务审计记录，不安排通知，不请求云同步或远程AI。
- 正式业务导出、云同步和局域网同步名单不纳入草稿。完整本机数据库文件副本可能包含该表，本轮不提供“草稿跨设备恢复”承诺；实施时检查所有实际同步／导出路径是否采用明确表名单。
- 切账号或成员后隐藏并拒绝旧页面操作；重新进入原身份可以继续自己的草稿。账号删除、清除本机账号数据时随账号数据库清理，普通退出登录不把草稿显示给其他身份。
- 不自动过期删除，不静默截断备注。超出安全载荷上限时明确报错并保留页面内容，允许复制备注，不显示保留成功。

### 暂存与正式保存分开

本轮采用**用户主动暂存**，不后台自动写草稿。切到后台时，仍存活页面的表单由现有页面状态保留；系统强杀、刷新或关闭窗口前未主动保留的最新修改，不能保证恢复。浏览器标签关闭确认不在本轮承诺范围；应用内部返回应受保护。

正式保存继续复用现有保存、账号复核和事务校验，成功后清理对应草稿。为防止“正式保存已成功、草稿删除失败”或提交结果不确定后再次恢复造成重复新建，持久化草稿预留固定的新规划UUID；恢复与再次提交先核对该UUID：

- 正式规划已存在且和草稿所指待办一致：提示已保存并提供查看，不能再新建一份。
- 已存在但已删除、身份矛盾或内容已变化：明确提示核对，不覆盖也不自动另分配新UUID。
- 不存在：仍须完整执行原保存检查后创建。

草稿清理失败与规划保存失败分别呈现。清理失败不能把已成功规划显示为“保存失败”；“规划已保存、专注未启动”继续按原错误状态处理，不从草稿再次创建或重启计时。删除仅按草稿ID和匹配修订号执行，不能删掉另一个页面刚更新的草稿。

### 审批前可行性复核

2026-10-11补充核查以下现有路径，仍未改动功能代码：

- `StorageServiceFixed.savePlanBlockEdited`已经在事务内按UUID读取现有规划，并在新建时拒绝同UUID已存在的记录。固定目标UUID可衔接这个保护；恢复识别到已存在记录后只提供查看，不把它当作编辑版本继续提交。首次读取之后的并发创建仍交由事务检查拒绝，不能只依赖页面前置查询。
- `DataExportService`按导出类型读取明确业务对象，局域网确认请求按固定字段组装，云同步请求也有明确的规划变更字段。已核对的这些主要路径不会自动枚举新增草稿表；实施时仍须以实际请求／导出内容测试隔离，不能仅凭草稿不写oplog宣称所有路径都安全。
- 当前数据库已有版本迁移以及本地私密日记表的先例，新增本地表具有可落地路径。实施时基于当时最新schema版本追加迁移，不在本方案预占下一个版本号，避免覆盖共享工作区其他功能的迁移。
- 5份上限检查与新建草稿写入放在同一事务内；更新、删除必须同时匹配草稿ID、成员ID和修订号。确认放弃时删除失败，应继续留在页面提示重试，不能一边保留旧草稿一边宣称已放弃成功。

## 7. 验收方案与交付

| 场景 | 必须达到的结果 |
| --- | --- |
| 仅打开／自动估时，然后返回 | 不弹未保存提示，不产生草稿或业务写入 |
| 修改备注、时间、提醒或番茄设置后返回 | 统一出现退出确认；取消保持原表单，放弃后退出 |
| 主动保留后关闭页面／重开应用 | 相同账号与成员恢复全部用户字段；推荐须重查 |
| 暂存失败或schema初始化失败 | 留在原页面，提示失败，原输入可继续编辑与复制 |
| 同一份重复暂存、5份上限、并发修订 | 更新自身、满额不覆盖、旧修订不吞掉新内容 |
| 同名／重复待办、独立协作成员切换 | 只匹配具体UUID与当前成员，旧请求不能填入新身份 |
| 期间待办完成／删除／专注开始／新增安排 | 恢复／提交重新核对，不能绕过原约束 |
| 原时段过期、出现新冲突、时区变化 | 明确提示重新选时间／检查，不悄悄移动或保存旧推荐 |
| 保存成功但草稿未删，或返回结果中断 | 按固定目标UUID识别已存在规划，不产生第二份 |
| 保存成功但启动专注失败 | 说明规划已保存、专注未启动，不误当未保存草稿 |
| 已有规划／冲突／漏做编辑关闭 | 未保存退出受保护，原版本和来源约束保持，无跨重启恢复入口 |
| 草稿列表为空、读取失败、格式损坏 | 三种状态区分，失败不显示“暂无草稿” |

自动验收覆盖新旧数据库迁移、身份隔离、容量与修订、损坏格式、稳定目标ID、防重复、零业务写入及同步名单；Widget覆盖三种普通新建入口、退出方式、子页面返回、恢复、失效目标、失败重试、特殊编辑退出保护与小屏大字体。
