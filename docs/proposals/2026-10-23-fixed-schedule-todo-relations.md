# 第37轮方案：固定日程与待办关联闭环

日期：2026-10-23（北京时间）

状态：**实现及验收通过，待提交本轮**

## 1. 建议与收益

固定日程表示考试、预约、会议等外部确定的时间；复习、准备材料、提交报名等仍是待办。现在两类对象的数据模型已经能保存关联，但用户在固定日程详情里看不到这些待办，也不能在编辑界面手动维护关系。这样 AI 创建的关联被隐藏，手动创建的日程又无法形成“日程—准备事项”的清晰上下文。

本轮建议补齐关联待办的展示、选择、跳转和重复范围编辑。用户打开考试详情即可查看准备任务和状态，点击任务可直达原待办；编辑关联时先在选择页暂存，再应用到日程草稿，最终随日程保存。

## 2. 当前实现依据

- `FixedScheduleItem` 已有 `relatedTodoIds`，通过 `related_todo_ids` 序列化并写入 `fixed_schedules` 与操作日志，不需要新增字段或数据库迁移。
- `AiTodoActionExecutor` 创建 AI 固定日程时会把 `sourceTodoIds` 写入 `relatedTodoIds`；当前详情和编辑页没有读取或显示这个字段。
- `FixedScheduleDetailScreen` 当前展示日期、时间、地点、状态、重复、提醒、团队和备注，没有关联待办区域。
- `FixedScheduleEditorScreen` 当前可以编辑日程字段，但没有待办选择；保存的并发保护已比较完整日程快照，且字段级变化会写入现有 op log。
- `FixedScheduleEditService` 已实现“仅本次／本次及以后／整个系列”。其通用字段复制目前不会应用关联待办；重复序列重建对新实例复制关系，但对既有实例保留各自原值。本轮必须保留这种按场次独立的旧数据，只有用户明确改了关联列表时才按选择范围更新。
- 产品语义文档规定考试等事项可以关联复习、材料准备等待办；关联不代表把待办改成日程，也不应自动更改待办日期或状态。
- 当前工作区保留 Android 课程提醒相关既有修改；本提案和获批后的实现不触碰、暂存或提交这些文件。

## 3. 批准后的目标行为

### 固定日程详情

1. 增加“关联待办”区域，显示每个已关联待办的标题、当前状态和可读日期信息；状态使用应用现有待办语义，例如待完成、已完成、已跳过或已删除。
2. 点击可访问的待办后，打开现有 `TodoDetailScreen`，返回后刷新关联项状态，确保完成、跳过或恢复等操作不会继续显示过时信息。
3. 没有关联项时仍显示简洁空状态和“编辑关联”入口；已删除、不可访问或数据不完整的旧 ID 显示为不可用占位，不冒充没有关联，也不自动清理。
4. 加载失败与空列表分开呈现，并可重试；不能把读取失败伪装为“没有关联待办”。

### 关联待办选择

1. 固定日程编辑页增加“关联待办”行，显示当前数量和标题摘要，进入独立的多选页或选择面板。
2. 面板支持按标题搜索、展示状态和日期，并允许选择当前账号有权访问且未逻辑删除的待办。已完成、已跳过的未删除待办仍可被关联，因为关联是事实关系，不是待规划筛选。
3. 已有关联但已删除或无法访问的 ID 继续列出，明确标识来源不可用；只有用户明确取消该项后才从草稿移除。
4. 选择面板的勾选只保存在面板内存草稿。点“应用”后回填固定日程编辑草稿；点“取消”或系统返回则丢弃面板改动。固定日程主表单最终保存前，任何关系改动都不写入数据库。
5. 关联范围遵循可见性边界：个人日程仅可选个人可访问的待办；团队日程只可选同一团队可见的待办。若现有模型或查询不能可靠识别可见范围，先限制候选项并对旧的不可访问关联显示占位，不把个人待办标题同步到团队日程。

### 保存与重复系列

1. 新建重复日程时，编辑器中的关联列表应用到新建系列各场次，与当前新实例生成规则一致。
2. 修改既有日程时，若用户没有打开并修改关联列表，保存其他字段不得把当前场次关联复制到其他场次；既有逐场关联必须保留。
3. 用户确实修改关联列表时，既有“仅本次／本次及以后／整个系列”范围同时决定关系改动范围。保存复核中展示受影响场次数、关系新增/移除数量及保留不变的较早场次数。
4. 若当前日程来自外部日历且系列编辑被限制为“仅本次”，关系也只改当前场次，来源重复规则与外部事件身份保持不变。
5. 关系变动与固定日程其他字段一起通过现有 `saveFixedSchedulesIfUnchanged` 快照校验和本地事务写入；并发变化时整批拒绝并提示重载，不能只保存半组关联。
6. 关联只保存 ID。不会自动完成待办、改期限、创建规划块、移动日程或删除待办。删除关联日程不会级联删除待办。

## 4. 数据与安全边界

- 复用 `relatedTodoIds`、现有固定日程表、同步 op log 和数据刷新通道，不改字段格式、服务端能力版本或 Cloudflare 兼容路径。
- 详情页按 UUID 重新解析关联对象；打开页面时以及从待办详情返回时刷新，避免只依赖旧的内存对象。
- 编辑候选来自当前账号本地有权读取的数据。保存前再次确认新增 ID 仍存在且满足可见性范围；数据库读取失败必须阻止保存关系变动并保留编辑草稿。
- 删除或不可访问的旧关系不自动丢弃；只有在关系选择面板中明确取消后，才作为用户删除意图保存。
- 不新增待办到固定日程的反向外键，不要求更新待办本身。固定日程 ID 是单向关系的唯一持久化来源。
- 不触碰 `CDT-server`、财务、规划块、提醒调度、AI 提示词或 Android 当前未提交文件。

## 6. 验收标准

1. AI 创建并保存带 `sourceTodoIds` 的固定日程后，详情准确展示对应标题、状态和日期；无关联时正确显示空态。
2. 搜索、多选、取消和应用流程正确：取消面板不改编辑草稿；应用只改编辑草稿；离开或放弃主编辑器不写入持久化。
3. 已完成／跳过的待办可作为历史关系显示；逻辑删除、缺失、不可访问和数据库错误都分别有明确状态，不误报为空，也不静默删旧 ID。
4. 点击有效关联打开对应待办详情，返回后刷新状态；状态变化不创建重复待办、不改日程状态。
5. 关系编辑在 occurrence 只影响当前场次，在 future 保留较早场次，在 series 覆盖整个系列；未改关系列表时，即使修改其他系列字段也保留不同场次之间已有的关联差异。
6. 外部日历重复日程的关系编辑只影响当前场次；团队日程候选符合同团队可见范围，不显示或同步个人私有任务标题。
7. 复核文案数量与实际保存 ID 集合一致；期间固定日程或关联待办发生冲突时保留输入且拒绝错误保存。
8. 运行关联选择与详情 Widget 测试、固定日程编辑/重复范围/存储/AI创建/同步回归、定向静态分析、格式检查和 `git diff --check`。全量测试如有失败，按原样调查并报告，不删除过时或失败测试来获取通过。
9. 提供可直接查看的手机截图，至少包含关联日程详情和待办选择页；另验收窄屏、大字与深色主题。说明截图来自真实 WidgetTester、浏览器或设备，不把合成截图说成真机画面。
10. 报告区分代码测试、构建、浏览器/Widget UI 证据与真实设备/跨设备同步验收；未运行的检查明确标注。
