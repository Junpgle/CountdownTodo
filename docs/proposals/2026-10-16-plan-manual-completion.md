# 第十八轮方案：已结束规划手动确认完成与即时撤销

日期：2026-10-16（北京时间）。第十七轮连同折叠和视觉优化已获用户验收通过。**用户于2026-10-19确认第十八轮验收通过，进入第十九轮方案阶段。** 本状态记录用户确认，不补记此前未取得的浏览器或原生验收证据。

## 1. 为什么建议这一轮

补齐“安排—执行—复盘”的收尾操作。用户可能在线下完成了一段工作，却没有启动番茄钟。时段结束后，首页和规划中心仍会显示漏做或已结束待确认；当前编辑器只有照此新建、跳过和删除，没有明确的手动确认入口。

例：09:00—10:00规划“整理材料”，10:20打开时显示漏做。实际已经整理完，用户可以选择“确认规划已完成”。规划变为已完成，专注依旧是0分钟，待办本身保持原来的完成状态。点错后可在10秒内撤销。

本轮只处理**已经结束的单条真实规划**。先不支持提前完成、批量确认或自动推断，避免扩大到当前占用释放、其他预约和批量状态转换。

## 3. 用户操作与界面

入口沿用现有路径：

- 首页今日规划展开 → 查看规划 → 更多操作 → **确认规划已完成**。
- 规划中心点击已结束的真实规划 → 更多操作 → 同一项操作。

不在首页新增常驻按钮、概览卡或列表，不改刚验收的折叠、间距和视觉。映射课程、旧式待办投影、设备日历等不出现可写的确认操作。

### 确认前

点击入口先按UUID读取最新规划及对应待办，展示短确认框：

```text
确认这次规划已完成？
整理材料
10月16日 09:00—10:00

仅将这次规划标为已完成。
不会改变待办完成状态，也不会新增专注记录。

返回核对                         确认完成
```

已核实投入可以用一行摘要显示；不把旧缓存或同标题记录当作新的实际投入。确认框不提供补填时长，不混入待办完成按钮。

编辑器存在未保存修改时，先提示“请先保存修改，或放弃修改后重新打开”，保留输入；不把未保存的时段／备注一并提交，也不静默丢弃草稿。操作处理中禁用重复提交和相互竞争的菜单操作。

### 成功与撤销

- 成功后返回原首页或规划中心，局部刷新；底部显示“已确认规划完成”，提供**撤销**，有效10秒。
- 只保留本页面最近一次手动确认的撤销资格；第二次确认替换前一次，离开来源页面、身份变化或超时后清除，不做永久状态历史面板。
- 撤销仅撤回本次手动完成状态，保持时段、备注、提醒、番茄配置、缓存及关联记录原值。它不撤销真正的番茄记录，也不撤回待办完成。
- 若规划或关联执行记录已经变化，撤销拒绝覆盖，提示“规划或投入已变化，请重新查看”；已经变更的数据保持原样。
- 撤销之后继续服从既有漏做维护及番茄自动完成规则。比如原始状态是已过期的待执行，后续维护仍可能标记为漏做；本轮不冻结业务维护。
- 超时后不提供任意“取消完成”，因为当前模型没有持久记录这次完成的来源，不能猜测应恢复哪一种旧状态。

## 4. 适用与保护规则

允许操作的规划必须同时满足：

1. 当前账号数据库中的唯一真实UUID，未删除、合法时间区间，结束时刻不晚于当前时刻。
2. 当前状态为待执行、已提醒、延后或漏做。正在进行、尚未开始、已完成、跳过、取消、专注状态以及损坏行不进行本次状态转换。
3. 关联待办存在、未删除、无同步冲突；关联团队待办的规划仍属于当前用户，允许手动确认。此操作只修改规划状态，不改变团队待办或成员完成状态。保留现有成员身份核对。
4. 关联待办可以未完成，也可以已经完成；这是历史规划的确认，不是新建规划。不会新增已完成待办的规划，不改待办状态、完成覆盖或重复期次。
5. 同规划／待办没有可核实的正在专注或暂停状态。专注状态损坏、绑定矛盾或无法读取时阻止操作并引导查看专注状态，不把异常当成空闲。
6. 操作期间账号、成员、原规划、对应待办或关联执行快照变化时，要求重新核对。

已截止的个人待办不因截止时间而禁止确认历史规划；本轮不重新安排未来时间，也不延长截止。规划是否真的完成由用户确认，不根据记录时长强行决定，不要求没有任何投入才可确认。

关联团队待办的个人规划照常支持手动确认；离线设备尚未同步的动作不通过新后台轮询补齐。本轮只使用现有可读取状态与同步结果，不宣称能发现所有设备的实时活动。

## 5. 数据和同步设计

### 读取与条件写入

新增小型手动完成服务／仓库，负责准备快照、确认和撤销。读取以目标规划UUID、对应待办及明确关联执行版本为边界，不调用全量规划列表或全历史专注解码；不按标题猜测关联。快照覆盖规划完整字段、身份、关联待办资格及可能影响绑定的记录元数据，采用既有版本／更新时间和确定性指纹方法。

确认框打开、取消、资格说明全部只读。确认提交时在事务内重新核对身份、规划资格、当前时刻、待办和执行快照，再以比较版本／更新时间的方式将状态改为`finished`。除既有`version`、`updated_at`等维护字段外，不改其他业务值。

规划更新与对应oplog必须同事务：任一步失败整体回滚。复用既有条件保存接口；如需适配，仅扩展明确的状态操作入口，不使用普通全量覆盖保存，也不改变现有编辑、拖动或番茄写入协议。

### 重复提交与不确定结果

同一次确认请求只提交一次，连点和页面重复回调不产生第二份日志。重复读取发现已完成时刷新页面，不再次写完成状态。若本机返回结果不确定，先核对当前块及本次保存结果，无法确认时停止自动重写；不把“当前恰好已完成”当成自己拥有撤销资格的证据。

撤销资格只在本次提交明确成功后生成，绑定提交后快照、原状态及有效期。撤销也使用条件事务和独立oplog，版本继续递增，不把旧版本号写回。相同撤销只能成功一次。

后台同步仍走原oplog机制。界面只提示本机保存结果，不把本机成功表述为已同步到所有设备。

### 统计与提醒

完成后按原共享统计刷新：已结束完成数增加；预算、实测专注秒数和时间日志不变。由于仅允许已经结束的规划，本轮不会提前释放一个仍有未来部分的占用区间，也不需要更改空闲推荐、缓冲或每周可安排规则。

成功后仅移除该规划遗留的应用开始提醒；重试只重试提醒协调，不再次修改完成状态。提醒更新失败单独提示“规划已完成，提醒更新未成功”。撤销恢复的是历史状态，不补发已经过去的提醒。旧提醒回调仍需按数据库当前状态复核，不能把已完成规划重新改成已提醒。

设备日历导出副本、番茄提醒和其他任务提醒不删除，不宣称系统日历或其他设备已经同步撤销。

## 7. 验收标准

1. 无专注记录的已结束漏做规划，人工确认后只改状态与维护字段；实测仍0秒，待办完成状态、重复期次、时间日志、配置和关联身份均不变。
2. 有明确投入、旧缓存大于实测、同标题不同待办、独立UUID重复期次及零记录样本，完成前后共享统计可对账；不按标题吸收记录，不造时长。
3. 尚未结束、未来、取消／跳过／已完成／专注中、虚拟映射、坏时间、团队、冲突及已删除待办均不发生违规写入。已完成的个人待办仍可确认历史规划，但不会成为新规划候选。
4. 确认框期间账号／成员切换、规划改期或删除、待办资格变化、开始专注、关联执行版本变化时拒绝旧快照；保留原编辑输入，不迟到关闭别的页面。
5. 打开／取消零写入；一次成功确认恰好一条规划更新及一条oplog，日志失败回滚，连点不重复。相同请求重复处理、结果不确定和已被其他操作完成的分支有明确测试。
6. 10秒内撤销恢复原状态、其他业务字段保持不变；撤销版本递增且只有一条对应oplog。到期、离页、换身份、第二次确认替换、块或执行变化以及重复撤销均不能覆盖新数据。
7. 没有因新读取、撤销提示或打开菜单新增全量迁移／漏做维护。数据库查询按明确目标和关联元数据读取，不逐项读取无关任务历史。
8. 目标提醒更新失败可独立重试，不再写业务状态；不撤下番茄等其他来源提醒，不补发历史提醒，不因旧提醒回调恢复已完成状态。
9. 从真实首页和规划中心走到编辑器菜单，核对确认、返回、撤销、错误和刷新；保留首页折叠记忆与滚动位置。检查390／320手机、720横屏、桌面、深浅／玻璃、1.8倍字体，不增加首页常驻高度。
10. 执行批准范围的相关回归、静态分析、正式Web构建及合成数据库浏览器验收，交付实际日志、数据前后快照和截图。明确原生真机、真实提醒、日历及多设备的未测边界，不用第十七轮测试数冒充本轮结果。
