## 1. 建议与收益

第45轮让用户选择要恢复的数据域，但导入页剩下的规则提示和成功回执仍是整包导入时代的全局文案。它会把不同数据域的行为说成同一种合并规则，且团队数据选项按整个备份统计，而不是按当前选中的范围统计。

建议把恢复前的规则说明、团队选项、最终确认和完成回执都绑定到所选数据域。这样用户能在写入前看清本次会处理哪些内容，完成后也能分辨“新增／更新／跳过”和“挑战状态／偏好设置已应用”这类不同结果。

## 2. 现有行为与问题依据

- `lib/screens/settings/pages/data_import_page.dart` 的 `_buildMergeInfoCard` 在手机和宽屏布局都会显示“智能合并”，并统一声称本地不存在的导入、冲突保留最新、已删除记录也导入。挑战恢复实际会写入备份中的挑战状态及状态标记，偏好设置也有单独写入规则，因此这个全局说明不适用于所有数据域。
- `_buildImportOptionsCard` 统计 `preview.types` 中所有团队条目；即使用户只选择记账，备份中未选择的待办团队数据也可能让页面显示团队处理选项。服务端实际只在团队感知的数据段被筛选进来时查询团队列表。
- `lib/services/data_import_service.dart` 将各导入器的 `imported/updated/skipped` 数值累加为全局结果。设置导入目前固定增加 1，挑战导入返回的是挑战任务数；页面却把两者都和普通记录一起显示为“新增 N 条”。这个总数不是同一口径。
- `lib/features/thirty_day_challenge/repositories/thirty_day_challenge_repository.dart` 的 `importBackup` 将备份的挑战状态和标记写入当前账号范围。`_importSettings` 只写入备份中受支持且非敏感的键。
- 第45轮已把各数据域原有写入规则作为边界；本轮只让用户界面和结果回执准确表达规则，不改业务域的合并／覆盖逻辑。

## 3. 批准后的用户行为

### 3.1 团队选项跟随选择范围

- 实时计算当前所选数据域中会被团队策略处理的数据条目数。只将有团队策略的段纳入统计，例如待办分组、待办、倒计时、时间日志、课程和固定日程；不把番茄记录、规划区块或其他不读取团队策略的数据段算进去。
- 所选范围没有团队数据时隐藏“团队数据处理”选项；选择包含团队记录的范围时显示当前有效数量和“跳过／转为个人数据”选项。
- 勾选和取消范围后立即刷新数量和选项可见性。已有的策略值暂时保留；当团队选项重新出现时仍显示该值。

### 3.2 改写恢复规则说明

移除“智能合并”的统一承诺，改为清楚说明：恢复范围会交给相应数据域的现有导入器，不同域的行为并不完全相同；预览数量是备份文件中的条目数，不是预计写入数。

按所选域显示需要用户特别留意的说明：

- **30天挑战**：备份中的挑战状态、任务和状态标记会恢复到当前账号的挑战存储范围，可能覆盖当前挑战进度。
- **偏好设置**：仅写入备份中存在且支持的设置键；备份未包含的键保持原样，身份凭据等敏感键继续跳过。
- **其他数据域**：沿用待办、课程、习惯、记账等现有导入器的处理规则；不把备份条目数量描述为新增数、覆盖数或冲突数。
- **软删除和团队数据**：软删除数量是文件记录统计，不代表会删除同等数量的本地条目；团队策略仅适用于本次所选范围内实际支持团队处理的数据。

### 3.3 写入前最终复核

点按导入按钮后先打开确认页／对话框，列出：

- 将恢复的域名及各自的备份条目数，并明确这些是文件计数，不是冲突预测。
- 当前账号身份处理方式（保留 UUID 或跨账号重映射）。
- 本次实际纳入的团队记录数及所选跳过／转为个人策略。
- 仅在选择挑战或偏好设置时显示相应覆盖提醒。

提供“取消”和“确认恢复”。取消只关闭确认界面，不调用导入服务、不修改数据库、偏好、提醒或同步状态。确认时使用不可变的当前范围和团队策略快照调用现有导入流程。窄屏、大字号时对话框内容可滚动。

### 3.4 成功结果按数据域说明

- `ImportResult` 增加结构化的分域摘要，同时保留现有全局字段以兼容现有调用方；各普通记录域聚合实际导入器返回的新增、更新和跳过数量。
- 偏好设置不再伪装成一条“新增记录”，而显示实际写入的受支持设置项数。
- 30天挑战不再把任务数算作“新增记录”，而显示“挑战状态已恢复”及备份内任务数。
- 成功 SnackBar 使用简短的“恢复完成”；结果卡按本次所选且实际处理的数据域展示摘要。失败消息、现有回滚和提醒刷新行为保持不变。

## 4. 范围与保护

- 修改客户端导入页的团队选项可见性、规则说明、写入前确认和结果展示；在导入模型／服务中新增分域结果摘要。
- 保持第45轮的数据域映射、默认全选、空选择拒绝、JSON 筛选、UUID 重映射、团队策略、软删除数据处理和导入回滚。
- 不改变任何数据域的写入／冲突策略，不做逐条冲突扫描，不改导出格式、数据库 schema、云同步协议或团队服务。
- 不增加成功导入后的撤销功能；这需要单独设计持久化快照和生命周期。

## 6. 验收标准

1. 只选记账、挑战、偏好设置等不含团队策略的数据域时，不显示无关团队选项；选择待办或课程等含团队数据的域时，显示的团队计数只来自当前选择中实际使用团队策略的数据段。
2. 旧“智能合并”文案不再把所有数据域描述成统一的新增／更新时间合并；挑战、偏好设置和普通记录域提示分别准确。
3. 确认界面只列出选中的数据域，所有数量明确标为备份文件条目数；挑战／设置警示按选择显隐，团队策略数量及跨账号 UUID 说明正确。
4. 取消确认时导入服务不执行且无本地写入；确认时传入用户复核过的不可变选项快照。
5. 结果卡按域展示可比较的新增／更新／跳过计数；挑战与偏好设置使用各自正确的语义，不再混入普通记录的“新增条数”。
6. 选择过滤、导入失败回滚、提醒刷新和旧版整包默认导入保持现状。
7. 新增服务与页面测试、相关备份导入回归、`flutter analyze`、格式检查和 Web release 构建通过；交付手机、桌面、深色大字号截图，并注明未运行的全量或真实账号验证。
