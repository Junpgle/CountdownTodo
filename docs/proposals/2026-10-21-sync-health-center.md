# 第30轮方案：同步状态总览与按模块安全重试

日期：2026-10-21（北京时间）

状态：**已实施，等待验收**

## 1. 建议与收益

当前的同步异常提示只出现在“关于此应用”页，且只有存在带错误文本的待办操作日志时才显示。它既看不到尚未写入错误原因的待上传操作，也看不到使用独立 `pending_sync` 标记的记账数据。现有“重试全部”直接执行强制全量同步，没有检查同步返回值就刷新异常列表。用户因此无法判断哪些数据还留在本机、是否只是排队、是否需要先处理版本冲突，也无法确认重试有没有成功。

建议新增一个从“设置 → 同步与数据策略”可直接进入的“同步状态”页，按业务模块展示本地待同步数量、失败原因和冲突状态，并提供普通增量重试。这样能从一个入口看清待办、倒计时、专注、时间日志、规划、固定日程、习惯、记账和屏幕时间的同步情况，同时避免把冲突误当成网络失败反复重试。

## 3. 产品行为

- “同步状态”页展示当前登录账户、最近一次同步请求成功完成的时间，以及总体状态：已同步、等待上传、部分失败、需要处理冲突或记账云同步未开启。没有成功时间时明确显示“尚无同步记录”，不猜测为刚刚同步。文案说明请求成功不代表队列中每一条数据均已确认，具体以各模块计数为准。
- 按业务模块分组展示准确数量：待办与清单、倒计时、专注记录、时间日志、规划、固定日程、习惯、记账、屏幕时间。普通操作日志按 `target_table` 映射到用户可理解的模块名；财务以8张记账表的 `pending_sync` 合计，避免漏项或重复计算；屏幕时间以当前账户本机待上传缓存中的应用记录数展示。
- 每组区分三种状态：等待同步（尚无失败原因）、重试失败（有可读错误）、版本冲突待处理。版本冲突不提供“重试”按钮，给出前往现有冲突中心的入口；可重试错误和普通待上传操作提供对应模块的增量重试。
- 顶部“重试可同步项目”只重试具备待同步数据且当前账户允许云同步的模块。调用普通增量同步，不重置游标、不使用 `forceFullSync`，记账仍尊重用户已有的云同步开关。
- 每次重试展示进行中状态并暂时禁用重复点击；完成后检查 `success`，刷新所有模块计数并清楚反馈“已处理”“仍有 N 项待同步”或具体失败原因。失败时保留队列与原始错误，不清除或覆盖用户数据。
- 进入页面、手动刷新和重试前后均重新读取当前账户快照。账号切换或退出时取消旧账户结果，避免把另一个账户的队列显示或重试到当前页面。
- 关于页现有异常卡片收敛为摘要与“查看同步状态”入口；设置页成为完整管理入口。现有冲突中心、服务器线路选择、同步频率和各模块设置保持原位。

## 4. 界面方案

- 页面顶部用一张紧凑状态卡呈现整体状态、最近成功时间和刷新入口；下方按“待处理”“已同步”分区，默认优先显示有待同步数据的模块，零待办模块可折叠，避免空状态拉长页面。
- 每个模块卡片只显示模块名、待同步总数、失败／冲突数量和一句下一步建议。点击可展开具体记录，展示操作类型、时间和经脱敏的错误摘要；不暴露认证令牌或完整请求载荷。
- 全部正常时显示明确的空状态和最近请求成功时间；同步请求失败、本地读取失败、正在同步和记账云同步关闭分别提供独立状态文案与可操作入口。仅根据真实同步结果显示失败，不靠网络探测推断离线。
- 遵循 Material 3 动态色彩，适配窄屏、桌面、深色模式和大字号。无需长列表占满首屏，状态卡与待处理模块应在手机首屏内清晰可见。

## 5. 状态读取、重试与安全边界

- 增加只读的同步状态快照仓库／服务，使用当前账户对应的本地数据库与偏好设置；成功完成通用同步请求后沿用现有账户作用域时间键更新时间；不新增数据库列、服务端字段或迁移。该时间只表示请求完成，不表示所有操作都已被服务端确认。
- 通用队列从 `op_logs` 读取所有 `is_synced = 0` 操作，再依据 `target_table` 与 `sync_error` 分类。`server_conflict` 及已有冲突标记只导向冲突中心，不进入可重试数；无错误的待上传行也必须计数。
- 记账模块从固定白名单中的8张 `finance_*` 表统计 `pending_sync = 1`。当用户关闭记账云同步时保留本地待同步数量，并说明数据仍只留在本机；不得为了重试而自动开启同步或传输记账数据。
- 屏幕时间仅统计账户作用域的待上传缓存；重试时使用已有屏幕时间同步链路，按原有成功确认规则清除缓存。
- 模块重试映射到 `syncData` 现有开关：待办（含分组）、倒计时、专注、时间日志、规划、固定日程、习惯和记账分别只启用对应域。冲突行不会因为同一模块的增量同步而被 UI 宣称为已解决；同步后需重新读取并保留冲突状态。
- 调用前后验证账户会话；调用结果为 `success != true` 时视为失败，即便 Future 正常返回也不能显示成功。并发时尊重 `syncData` 现有同步锁，不排队重复请求。
- 错误文案只做展示脱敏和长度限制，保留本地原始 `sync_error` 供现有诊断；不提供清空失败、删除队列、强制覆盖云端或一键解决冲突的操作。

## 6. 范围边界

本轮预计涉及同步状态页面、同步状态快照查询、设置入口、关于页摘要入口和对应测试。

本轮不做：

- 不改 Alibaba 云端服务、Cloudflare Worker 或同步协议，不部署。
- 不调整版本冲突解决策略，不将冲突自动重试或自动判胜；继续使用现有冲突中心。
- 不默认执行强制全量同步，不重置任何游标，不删除或清空待同步记录。
- 不改记账云同步默认设置，不代用户开启隐私相关的记账上传。
- 不新增持久化历史事件、数据库迁移、后台常驻监控或网络探测服务；页面展示本地队列快照和现有同步时间。
- 不把没有用户待上传记录的同步协议状态误报成“有错误”或“已同步”。

## 7. 验收计划

1. **队列覆盖与分类**：使用各 `target_table` 建立待办、倒计时、专注、时间日志、规划、固定日程和习惯待同步日志，验证逐模块计数与总数一致；无错误日志必须计入等待同步；`server_conflict` 必须单独归类且不计入可重试数。
2. **记账队列**：在8张记账表中分别建立 `pending_sync = 1` 和 `0` 的数据，验证只计入待同步行；关闭记账云同步时仍显示本地保留数量，触发其他模块重试也不得上传记账数据。
3. **屏幕时间与账户隔离**：验证当前账户的待上传缓存能被计数并经既有同步链路确认清除；切换账户或页面加载迟到时不串号、不展示旧账户数据。
4. **安全重试**：分别验证按模块只调用对应同步开关；不使用全量同步、不重置水位线；同步进行中重复点击被阻止；服务端／网络失败后数据和错误保留，最近请求成功时间不前移；成功后只清除本次被确认的数据并更新请求完成时间。
5. **结果反馈**：验证 `success: false` 不显示成功；成功但仍有冲突或新并发写入时，刷新后如实保留待处理数量；错误摘要脱敏并在长文本下可读。
6. **界面验收**：测试全正常、待上传、失败、冲突、记账同步关闭、同步请求失败和本地读取失败状态；覆盖窄屏、桌面、深色与大字模式，并提供手机和桌面截图。
7. 运行同步状态服务测试、同步设置与关于页入口 Widget 测试、相关同步服务回归、定向静态分析、`git diff --check` 和 Flutter Web release 构建；全量测试分批执行并记录未通过的既有边界，不删减仍有效的测试。
