# 第28轮方案：回收站系列清理与彻底删除保护

日期：2026-10-20（北京时间）

状态：**已验收通过（2026-10-21）**

## 1. 建议与收益

第27轮已经让完整重复系列可以一次恢复。相反方向的清理目前仍需展开系列逐期永久删除；如果系列较长，操作重复，也容易漏掉记录。现有单条永久删除和清空全部回收站还没有在删除事务里复核用户确认时看到的记录状态。

建议补齐“清理一个重复系列的回收站记录”，并让单条、系列和清空全部这三种不可逆操作采用一致的事务保护。用户可以明确只清理一个系列，误删时仍不会把已恢复的活动待办一并删除；确认后若数据已变化，则整次操作停止，不留下部分删除。

## 3. 产品行为与操作流程

### 系列级清理

1. 回收站折叠系列卡片保留现有展开与“恢复整组”操作；增加一个“更多”菜单，在其中放置红色语义的“清理该系列回收站记录”，不在卡片上增加第三个常驻主按钮。
2. 清理范围严格限定为该系列**当前仍在回收站的记录**。如果系列仍有活动期次，只清理回收站期次，活动期次和活动重复规则保持不变；如果系列全部现存期次都在回收站，则确认页明确说明将清理该系列全部现存记录。
3. 操作前从本地数据库按系列 ID 读取完整目标，不使用当前页、分页或搜索命中数推断范围。确认页显示记录条数、不同日期期数、日期范围、已完成数和已跳过数，并说明永久删除后无法恢复。
4. 搜索只命中该系列部分期次时，菜单仍代表清理该系列回收站中的全部记录；确认页完整列出实际范围，避免把搜索结果误当作删除范围。

### 单条与清空全部

- 保留现有单条彻底删除入口与清空全部入口，但两者在执行时都必须核对确认所针对的记录仍处于回收站。
- 清空全部确认前读取精确总数，包括尚未分页加载和被搜索隐藏的记录；继续说明这是整个回收站，不受当前搜索过滤影响。
- 用户取消不写数据库、不写 oplog、不清缓存。

### 保存反馈

- 执行期间禁用所有回收站破坏性操作，防止连点。
- 成功后刷新回收站并给出对应范围反馈；失败或数据变化时，列表保留最新数据并提示刷新后重试，不先行移除卡片。

## 4. 原子删除与并发保护

- 新增回收站删除预览／计划，保存目标 UUID 集合和必要的版本基线。系列计划读取该系列全部现存成员，再单独确定 `is_deleted = 1` 的清理目标；活动成员不属于目标。
- 确认后在 SQLite 事务内重新读取目标。单条操作要求 UUID 仍存在、仍已删除且版本与预览一致；系列操作要求回收站成员 UUID 集合及版本与预览完全一致；清空全部要求当前回收站 UUID 集合与确认前预览一致。任何成员恢复、修改、新增或删除都会让整组操作拒绝，不部分提交。
- 同一事务内删除目标行并为每个 UUID 写一条现有格式的 `DELETE` oplog。某一行删除或 oplog 写入失败时全部回滚，避免本地消失而同步删除操作未排队。
- SQLite 事务成功后再清理待办偏好镜像，刷新受影响的日程冲突日期并触发现有 `DataRefreshDomain.todos` 刷新链路。偏好镜像清理失败不能谎报数据库回滚；应重新从 SQLite 读取并反馈实际保存结果。
- 不修改服务端协议、数据库 schema 或 Cloudflare Worker；同步沿用现有删除 oplog。验收只证明本机数据库和同步队列写入，不代表云端或另一台设备已验证。

## 5. 界面与兼容边界

- 系列动作放在折叠卡片的“更多”菜单，危险操作必须经过单独确认；确认按钮使用 `colorScheme.error`，并用清楚的“永久删除”文案。
- 对部分删除系列明确写“仅删除回收站中的 N 条记录，活动期次会保留”；不使用含糊的“删除整个系列”标题。
- 整组恢复、逐期恢复、逐期彻底删除和清空全部原有语义保持可用；若系列 ID 缺失或归属不明确，不显示批量入口，仍可按现有单条处理。
- 只删除待办记录本身；不额外删除关联规划块、番茄记录、时间日志、日历副本、附件文件或其他系列数据，也不增加撤销能力。
- 不增加任意待办多选、不改变普通待办移入回收站、完成／跳过状态、重复规则、团队权限和 AI 删除范围。

## 6. 实施范围

预计改动回收站系列卡片与确认流程、StorageService 删除预览及事务入口、对应 contract、少量回收站删除服务／纯计划，以及服务、SQLite、Widget 测试与验收文档。是否调整 `getTodos` 分页补齐，以实现调查为准；无论如何，用户确认的数量和实际删除范围必须来自按数据库重新查询的完整集合。

## 7. 验收标准

1. **完整删除系列**：确认页的记录数、期数、日期范围、完成／跳过数与 SQLite 实际目标一致；确认后所有回收站记录被删除，每条各有一条 `DELETE` oplog；活动系列不被误创建或复活。
2. **部分删除系列**：仅删除当前在回收站的记录；活动期次、唯一活动规则及后续生成均保持原样。
3. **逐条删除保护**：取消没有副作用；记录已被恢复、编辑或删除时，确认后的过期请求被拒绝，不会物理删除活动待办。
4. **清空全部**：精确计数覆盖所有分页和搜索隐藏行；确认后清理同一确认快照中的全部记录；若快照发生变化则无部分写入并要求刷新。
5. **事务失败**：目标删除或任一 oplog 写入故障时，所有待办行和 oplog 保持操作前状态；重复点击只执行一次。
6. **分页、搜索和旧数据**：超过一页的长系列仍能给出完整预览；仅命中系列部分期次时文案与实际整组删除边界一致；缺失或混乱系列 ID 不提供批量清理。
7. **联动**：已删除行不在重复维护后意外复活；关联规划、专注、时间日志和有效活动规则均不变化；完成后回收站、日程冲突和待办刷新状态一致。
8. **界面验收**：覆盖折叠菜单、完整系列确认、部分删除系列确认、清空全部确认和成功反馈；验证手机窄屏、桌面、深色和大字体，无操作溢出或误导文案。
9. 运行重复待办删除／恢复、回收站存储、oplog、历史待办 Widget 回归和相关静态分析；执行 Flutter Web release 构建与 `git diff --check`。提供实际界面截图并清楚列出未验证的平台边界。
