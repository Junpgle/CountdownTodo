# 第十五轮方案：规划首页真实概览与明细直达

日期：2026-10-13（北京时间）。第十四轮及追加UI优化已由用户确认通过。**实现与技术验收已完成，用户于2026-10-14确认通过。** 结果见[第十五轮验收报告](../reports/2026-10-14-plan-day-overview-acceptance.md)。

## 1. 建议与理由

把规划首页顶部的「计划／实际／达成／完成漏做」改成可核对、可点击的当日概览，与第八轮规划复盘使用同一套规则。这连接现有待办规划、番茄、时间日志、复盘与拖动日历，优先修正同一项目里两处页面数字含义不同的问题。

例如一项60分钟规划只有48分钟投入、状态尚未完成，首页目前可能按80%推断完成，复盘页则只认真实完成状态。又如同一条无显式规划绑定的专注同时与两个同待办规划重叠，旧首页可以逐块重复累计，复盘会将归属竞争单独列为待核对。本轮让首页与复盘一致，也让用户直接点数字查来源。

## 2. 本次源码核对

| 当前位置 | 已确认行为与本轮缺口 |
| --- | --- |
| `todo_plan_screen.dart`的`_PlanDaySummary` | 汇总所有传入真实规划的计划分钟，包括取消／跳过；没有复盘页的合法性及冲突筛选。直接使用旧完成推断、投入比例和完成／漏做组合值 |
| `_actualSecondsForPlanBlock`及重叠匹配 | 取原累计缓存与关联记录累计的最大值；无显式绑定的同待办记录可以匹配多个重叠规划，各块转整分钟后再累加，可能重复和损失秒数 |
| `_PlanDaySummary`的「实际」 | 只从已有规划推导，未绑定规划的有效专注可能不计入；与复盘页「有效专注」含义不同 |
| `PlanReviewRepository` | 已具备真实规划、实际秒数、唯一归属、待核对、日志裁剪和日界线规则，但完整`read`还查询趋势、排行和漏做列表，不宜整份搬到日历首页 |
| `PlanExecutionSummary`／时间轴 | 展示与所选日相交的执行区间；其条数可含昨天开始的跨午夜专注，与按开始日统计的复盘条数不是同一范围 |
| `PlanBlockStatsScreen`／`PlanReviewDetailScreen` | 已有按日初始日期参数、类型筛选、分页、账号身份复核及原记录详情；首页数字尚未直接接入 |

课程与旧待办映射只传入时间轴，并未传入当前顶部汇总；本方案不把它们误报成现有顶部重复统计问题。以上是源码调研，尚未运行本轮复现测试或性能检查。

## 3. 用户看到的界面

### 紧凑的当日概览

在当前顶部区域替换旧四格，不增加新的常驻展开面板：

```text
真实规划      有效专注      已结束完成      时间日志
  90分          40分           1/2            20分
```

示例数字仅说明排版，不是运行结果。

- 普通手机和宽屏使用四个轻量可点击区域，主题色、数字字重和间距沿用第十四轮；移除硬编码紫／绿／蓝／橙及含义模糊的「达成率」。
- 数字用紧凑单位显示，秒数先汇总再格式化；小于一分钟显示秒数，不能显示成0分钟。完整时长及说明在点击后的明细中展示，提供完整语义标签。
- 根据可用宽度、字体比例和实际数字宽度判断能否放下四项。窄屏大字体改为一个紧凑的「当日概览 · 查看」入口，进入所选日期的现有复盘页，不强塞四列、截断数字或堆成高面板。
- 本轮不增加日历的纵向滚动，不新增横向滚动统计条。全天24小时仍在现有可用区域内布局，拖选、移动、缩放和撤销保留。常规尺寸概览占高不超过被替换区域；大字体模式也要给时间轴保留实际可用高度。
- 概览若有旧记录或归属问题，使用同一区域的简短「有记录待核对」入口，点击进入已有待核对明细；不把完整问题清单铺到时间轴上。

### 点数字直达来源

| 操作 | 打开的内容 |
| --- | --- |
| 点真实规划 | 所选日期的真实规划明细 |
| 点有效专注 | 所选日期已核实的专注明细，包含未绑定规划的记录 |
| 点已结束完成 | 所选日期已结束规划明细，能核对完成与未完成状态 |
| 点时间日志 | 所选日期裁剪后的有效日志明细 |
| 点待核对 | 同日旧时长、坏数据或归属竞争等已有明细 |

直接复用第八轮分页与详情；进入前复核账号／成员，返回时保留日历日期，数据变化则刷新概览。原「更多→规划统计」改为打开当前选择日，避免查看历史日期时跳回今天。

### 明确时间轴记录和统计的区别

保留现有规划／专注／日志图例和记录列表，将入口表述为「时间轴记录」，明确是与所选日相交的区间；去掉容易与概览混淆的无范围条数。跨午夜专注仍在两天时间轴按区间展示，统计完整实际秒数只归开始日一次。运行中专注仍按现有时间轴展示，不冒充已结束的核实投入。

移除时间轴块内旧的「缓存或匹配分钟／计划分钟」比例角标，保留标题、时段、状态及拖动操作；需要投入细节时从概览和已有复盘明细查看。不在绘制每个块时追加统计查询。

## 4. 数字规则

严格复用第八轮已有规则，不重新定义完成或投入：

1. **真实规划**：按规划开始的本地日期归属，使用合法、未删除、无冲突的数据库规划；取消／跳过不进入执行预算。映射课程、手机日历和旧式执行区间不伪造为真实规划。
2. **有效专注**：按记录开始日归属，只计已结束且状态、起止、实际秒数合法的记录。中断和切换保留真实投入，零秒不回退计划时长，未绑定规划的合法记录也计入总量；原累计缓存不补入实际。
3. **唯一归属**：一个记录UUID只计一次；同待办多个重叠候选不重复摊入。实际记录有效但归属有竞争时，总量仍只计一次，归属列入待核对。
4. **已结束完成**：分母是本期已结束且未取消／跳过的有效规划，分子只认真实`finished`状态。没有分母显示「暂无」，不显示0%评价；规划完成不等于待办完成。
5. **时间日志**：按与所选日交集裁剪，汇总毫秒后转秒；与专注独立显示，不相加成总工作量。未来结束的日志按既有规则待核对。
6. **时区和边界**：本地日历构造起止，不固定加24小时；保持跨午夜、夏令时和月份边界规则。完整数字与复盘在同账号、同范围、同数据快照与同一时刻下逐项一致。

## 5. 读取、刷新及失败状态

- 在`PlanReviewRepository`新增轻量概览读取，抽取与完整复盘共享的聚合及待核对逻辑；仅返回四项指标、身份、范围、待核对数量和下一边界，不读取趋势、排行或完整明细，不新建第二套SQL判定。
- 在同一读取事务内取得概览，查询次数不随规划数量逐条增长。先复用现有账号初始化顺序，再读取概览；新的统计读取不迁移、修补或写入业务数据。
- 与时间轴分别管理加载结果。概览首次加载显示占位，失败显示「概览加载失败 · 重试」，不得显示0或阻止时间轴操作；失败重试仅重新读取概览。
- 切日期／账号／成员立即废弃旧概览与点击载荷；请求序号、选定日期、身份和前台状态共同保护迟到结果。相同日期刷新期间可保留旧值，但标明更新中并禁用旧明细点击；切日期不展示上一日数字。
- 保存、改期、撤销、完成、记录修改、同步刷新和专注结束后更新概览。结束边界、日志结束、午夜及前台恢复采用可见页面的单次计时和现有事件；后台、离页和被详情页覆盖时停止，不按秒轮询。
- 统计读取在原页面既有状态维护完成后启动，避免读到维护前的状态。原`_loadData`中的漏做标记及专注业务完成转换保持原行为；不将展示用的统计方法替换到这些写入判断中。
- 进入明细后按最新数据读取。若记录已变化，提示刷新；身份切换则阻止继续查看旧账号。原记录详情仍走已有复核。

## 7. 验收标准

1. 隔离SQLite构造取消／跳过、未来已标完成、80%投入未完成、坏规划、冲突、缓存大于实际等样本；轻量概览与完整复盘同快照逐项一致。
2. 一条专注匹配两个同待办规划、矛盾显式绑定、未绑定专注、零秒、缺失旧时长、合法中断／切换、删除记录均有定向断言；例如两条40秒记录应合计80秒，不逐条截成0分钟。
3. 跨午夜规划／专注只按开始日统计一次，时间轴仍按相交区间展示；日志跨日裁剪、重叠日志、未来结束、纽约和半小时夏令时边界按既有语义测试。
4. 概览查询与原复盘方法对比，验证没有排行／趋势／完整记录查询，没有按规划逐行读取；大量无关历史数据不进入完整解码。不给出未经测量的提速比例。
5. 快速切日、日期边界、账号／成员切换、离页迟到、同步刷新和前台恢复不会混用旧概览；隐藏页面不持续查询。
6. 统计读取故障只显示局部错误，时间轴依旧可拖选、改期和撤销；重试不将旧数字伪装成新数据。原时间轴本身故障继续沿用原错误处理。
7. 四项数字、待核对和统计菜单进入正确日期／类型，分页与详情可用，返回保留日期；零值和没有已结束规划有明确文案。
8. 320／390手机、720×360横屏、桌面、深浅色、普通／玻璃及1.8／2.0倍字体实际检查；概览不增加日历滚动、数字不截断，记录图例仍可识别，拖动区域有可用高度。
9. 新统计查询、重试及明细导航路径验证零业务写入；原日历加载已有漏做维护单独计数说明，不能宣称整个规划页从此只读。原完成、漏做、拖动保存和撤销行为保持回归通过。
10. 交付本轮实际运行的测试、静态分析、Web构建及浏览器截图；原生真机、真实日历、多设备同步和全仓测试未执行时明确列出，不沿用第十四轮763项充作新验收。
