# 第44轮方案：未来手工账单纳入收支一览

日期：2026-10-24（北京时间）

状态：**已实施并完成本地验收；等待用户验收确认。**

## 1. 建议与收益

第43轮新增的“未来固定收支”目前汇总周期账单和未还贷款计划，但不纳入用户已录入的未来日期账单。用户需要把某笔已知的一次性账单提前记入账本时，它仍不会出现在这页，未来收支合计也会少算。

本轮建议把这些已保存的未来账单纳入同一日历和金额汇总，并以单独来源标记与周期账单、贷款计划区分。完全复用现有账单记录，不增加一套重复的“未来账单”数据。

## 2. 现有实现依据

- `FinanceTransaction` 已保存账单日期、类型、分币金额、币种、发生时刻、来源、删除状态及同步字段。
- `FinanceRepository.getTransactions(from:, to:)` 支持按半开日期区间读取未删除账单；按现有事务表读取即可，不需要新字段或迁移。
- 第43轮的 `FinanceFutureCommitmentsService` 已负责周期规则、未还贷款、自然月范围、币种汇总和稳定 UUID 去重。
- 自动生成的周期账单可用“规则 UUID + 周期键”计算稳定 UUID。已物化项目应显示为账单记录本身，不能再同时显示一个重复的规则预测项。
- 账单详情页已有编辑入口；未来收支页已有加载、刷新、返回重载和错误状态处理。

## 3. 批准后的行为

1. 在当前选定的3、6或12个月范围内，读取已保存且未删除的未来日期账单。按 `transactionDate` 本地账单日归组，不把日期范围扩展到所选窗口之外。
2. 今天已发生的普通账单不进入“未来”合计；今天的账单只有在保存的发生时刻仍晚于当前时刻时才作为待发生项目显示。明日及之后的账单按账单日纳入，即使缺少可用的发生时刻。
3. 支出计入流出，收入和退款计入流入；继续使用整数分和分币种统计。手工未来账单显示独立来源标签、分类／商户／备注、日期及金额，并计入对应月份和范围合计。
4. 已物化的周期账单只显示一次：若其 UUID 对应当前范围内的启用周期规则，则显示真实账单记录，不重复显示规则预测。规则已停用或已不存在的其他未来账单仍按真实账单行展示。
5. 如果手工账单与周期账单或未还贷款期在日期、币种、方向和金额上完全相同，显示“可能与计划重复”的提示，但不自动合并或删除任一项目。这个匹配只用于提示，不代表系统认定两笔记录重复。
6. 点击手工账单进入已有账单详情；从详情编辑并返回后，重新加载列表和汇总。页面保留当前期限选择。
7. 继续明确标注“已登记／预计收支”，不同币种分别汇总；不推算账户余额，也不把预计金额写入历史累计结余、预算实际支出或付款方式余额。

## 4. 边界和保护

- 只读取 `transactionDate` 落在所选范围内、未删除的现有账单；退款按已有类型作为流入呈现。
- “今天是否待发生”使用账单保存的时区和发生时间判断；如果今天的记录缺少有效未来时刻，则不列入未来预测，避免把已经发生的今天流水算作未来开销。
- 手工账单和计划的相似度不能证明它们是同一笔。除稳定 UUID 能确认的自动周期账单外，不因相同日期、金额或备注而静默去重。
- 数据查询失败时整页明确报错并提供重试，不把账单查询失败伪装成零条或部分合计。
- 不新增 SQLite 字段、schema 版本、同步能力、备份格式、网络请求、权限或定时器；不改变现有账单、预算、余额快照、累计结余和自动记账语义。

## 6. 验收标准

1. 只显示所选范围内的未删除未来账单；排除范围外、已删除及今天已发生的记录，今天晚些时候才发生的账单正确显示。
2. 支出、收入和退款方向正确，金额按整数分累加，不同币种不会相加；月度金额与范围合计一致。
3. 与规则周期 UUID 相同的已生成账单只显示一次；规则停用或规则不存在时，独立的真实未来账单仍可显示。
4. 对日期、币种、方向和金额全部一致的账单与规则／贷款计划显示提示；任一关键字段不同则不提示。所有候选项目均保留，绝不静默去重。
5. 点击未来账单可打开正确详情；修改或删除后返回，列表与总额刷新且当前3／6／12个月选择保持不变。
6. 读取失败不会显示成空状态或部分金额；刷新错误后可重试恢复。
7. 测试覆盖只读、时间及时区边界、重复提示和导航；运行新增及相关财务测试、静态分析、格式检查、`git diff --check` 和 Web release 构建。若全量测试受既有问题阻断，逐项报告，不通过删测规避。
8. 验收报告附手机截图，并区分自动化截图、浏览器预览和真机证据；不声称验证了银行实时余额。
