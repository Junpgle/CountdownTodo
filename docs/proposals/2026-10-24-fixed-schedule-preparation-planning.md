# 第42轮方案：为固定日程关联待办推荐日程前的准备时间

日期：2026-10-24（北京时间）

状态：**已实施；259 项定向测试、静态分析、Web release 构建和差异检查通过；待用户确认验收。详见 [验收报告](../reports/2026-10-24-fixed-schedule-preparation-acceptance.md)。**

## 1. 问题与建议

第41轮已支持从固定日程详情直接新建“准备待办”，并且只关联当前场次。新待办保存后，用户仍需自行找到规划中心、估算时长、搜索日程前的空闲时段，再返回创建规划块。待办和固定日程关系已经建立，但从“需要准备”到“安排何时准备”仍有明显的跨页步骤。

建议在固定日程详情的关联待办行增加“安排准备时间”。进入独立整页后，使用当前待办的既有完成时长估算，在固定日程开始前查找最多五个可用时段。用户选择候选后仍进入现有规划块编辑器确认保存；用户也能直接进入时间轴拖动安排。

固定日程开始时刻只作为这一次查找的结束边界，不写入待办期限，也不自动创建规划块。这样继续保留待办期限语义、用户确认和拖动新建习惯。

## 2. 当前项目依据

- `FixedScheduleDetailScreen` 已显示当前固定日程和关联待办；第41轮新增了只关联当前场次的新建待办入口。
- `TimeEstimationService.estimate` 已用本地历史完成数据估算待办时长，并在历史不足时返回启发式估算和参考等级。规划编辑器也会在选择待办后预填估算时长。
- `PlanAvailabilityQuery`、`PlanAvailabilityService` 与 `PlanAvailabilityRepository` 已处理应用内课程、固定日程、规划块、手机日历、账号校验和冲突复核。
- `PlanWeeklyAvailabilityPreferences` 和 `PlanAvailabilityPreferences` 已提供每周可安排时间、避让时段和前后缓冲；可用时段查找默认最多五项。
- `TodoPlanScreen` 支持 `initialDate`、`initialTodoId` 和现有拖动安排；`PlanBlockEditorSheet` 负责最终确认和保存，已有草稿、退出保护与保存前复核。
- `PlanAvailabilityQuery` 目前按待办自己的期限限制查找。本轮要增加独立的“固定日程前置边界”，不可借此修改或伪造 `TodoItem.dueDate`。

## 3. 批准后的用户流程

### 入口

1. 在固定日程详情的关联待办行增加“安排准备时间”。只对当前场次关联、未完成、未跳过、未删除的待办显示。
2. 当前固定日程已取消、已结束或没有已知开始时刻时，不提供“日程前推荐”操作。已有计划仍可照常从规划中心查看和拖动编辑。
3. 重复固定日程只使用当前详情中的场次及其开始时刻，不对同系列其他日期批量安排。

### 推荐页

1. 从详情进入整页“安排准备时间”，顶部展示固定日程标题、日期和开始时间，并标明“只用于本次时段推荐，不修改待办期限”。
2. 默认时长来自 `TimeEstimationService`；展示估算来源和参考等级，用户可以先修改时长再查找。不得退回固定30分钟默认值。
3. 以当前时间到固定日程开始时刻为查找边界，按日期逐段检索，最多展示五个最早可用候选。超过七天的范围分周翻页；不能搜索到日程开始之后。
4. 继续应用用户现有的每周可安排规则、避让时间、前后缓冲、手机日历和应用内占用校验。已有规划块继续作为忙碌区间。
5. 用户点选候选后，打开现有规划块整页编辑器，预填待办、日期、开始/结束时间和估算时长；用户可以调整并明确点击完成保存。
6. 提供“到时间轴拖动安排”，以当前待办为预选项打开 `TodoPlanScreen`。保留用户偏好的拖动新建方式，不强制采用推荐结果。
7. 如果时长没有合适的完整时段，显示原因、修改时长入口和拖动安排入口，不自动拆分或压缩时长。
8. 待办已有规划时，推荐页先列出当前规划摘要；新建的每个时间块仍需用户显式确认，不因重复打开入口而自动产生重复规划。

### 保存与并发保护

1. 进入候选页、调整时长、选择候选、编辑规划块和恢复本地规划草稿时，都携带当前固定日程场次身份与已知开始时刻作为临时上下文。
2. 保存前重新读取待办、固定日程和忙碌快照。待办已完成/跳过/删除、固定日程已取消/改期/转范围、候选已被占用或已越过开始时刻时，拒绝保存，保留编辑内容并让用户重新查找。
3. 规划草稿须保存可恢复的日程前置上下文；恢复草稿时重新读取固定日程并重新校验，不把陈旧的截止边界当作仍有效的安排。
4. 保存仍复用 `PlanBlockEditorSheet` 现有写入与冲突保护；本轮不改待办期限、固定日程、日程关系、专注记录或投入日志。

## 4. 语义与范围边界

- 固定日程开始时刻仅是查找和保存复核的临时边界，不等同于待办截止时间，不写回数据库。
- 推荐是只读计算。用户必须选候选、检查规划块并显式保存，打开页面或返回页面不会落库。
- 只处理用户从单个固定日程详情进入的当前场次；不批量生成整个重复系列的准备待办或规划块。
- 不改动时间估算算法、每周可安排设置、避让/缓冲偏好、手机日历权限和服务端同步协议；只在新上下文中复用其结果。
- 时间待定日程不猜测开始时间；用户仍可自由打开时间轴并手动拖动安排。
- 若可用性来源读取失败，继续遵循现有 fail-closed 提示及“仅检查应用内日程”确认流程，不把读取失败当成空闲。
- 当前工作区另有 Android 到课提醒、财务、帮助/功能引导、版本和测试改动。本轮未批准前不触碰这些内容。

## 5. 预计实施范围

- `lib/screens/fixed_schedule_detail_screen.dart`：关联待办的“安排准备时间”入口、已有规划提示、当前场次上下文传递。
- `lib/screens/plan_preparation_screen.dart`（新建）：整页估算时长、按事件开始时刻搜索候选、按周浏览和拖动安排入口。
- `lib/models/plan_availability.dart`、`lib/services/plan_availability_service.dart`、`lib/services/plan_availability_repository.dart`：加入独立的临时固定日程边界，确保逐日查询和跨日期候选均不超过事件开始时刻。
- `lib/widgets/plan_block_editor_sheet.dart`、`lib/screens/plan_editor_drafts_screen.dart` 或其草稿模型：候选信息、固定日程快照与边界进入编辑器，并在保存和恢复草稿时重新校验。
- `lib/screens/todo_plan_screen.dart`：从拖动安排入口预选目标待办和初始日期，不改变现有拖动操作。
- `test/services/`：估算边界、同日/跨日裁剪、每周规则、忙碌占用、边界更新和过期候选拒绝。
- `test/screens/`、`test/widgets/`：入口条件、推荐卡片、候选选择零写入、保存后规划、退出/草稿恢复、窄屏/深色/大字及拖动入口。
- 更新 `docs/features/todo-semantics.md` 并提交本轮验收报告和 WidgetTester 截图。

## 6. 验收标准

1. 只有合适的关联未完成待办显示该入口；取消、结束、时间待定和不可见关联项不会错误开放日程前推荐。
2. 推荐使用现有完成时长估算，显示估算来源和参考等级；用户可修改时长，默认最多五个候选。
3. 候选覆盖当前时刻至目标场次开始前，边界精确到分钟，跨日不越界；每周规则、避让、缓冲、手机日历和应用内忙碌时段均有效。
4. 选择候选后只预填编辑器；关闭或返回不写规划。显式保存后只创建当前待办的一条规划块，待办 `dueDate`、固定日程和关系字段保持不变。
5. 固定日程变化、账号切换、待办状态变化或候选被占用时，过期候选/草稿不能保存，编辑输入仍可恢复并重新查找。
6. 已有规划块可见且占用时段仍参与冲突检测；用户可以追加规划，不会因页面重开自动创建副本。
7. “到时间轴拖动安排”预选同一待办，现有的拖动、撤销和保存失败保护继续工作。
8. 自动化服务和 Widget 测试、变更文件静态分析、格式检查、`git diff --check` 与 Web release 构建通过；报告说明是否运行全量测试及任何既有失败。
9. 提供固定日程详情入口、推荐结果、候选编辑器、保存后规划和深色/大字/窄屏的可见截图，并注明 WidgetTester/浏览器/真机来源。
10. 区分本地可用性测试、SQLite 规划保存、真实手机日历读取、系统通知以及跨设备同步的验收范围。
