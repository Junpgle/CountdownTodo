# 第八轮方案：规划复盘与真实投入明细

日期：2026-10-11。状态：用户回复“确认”批准本轮，正在实施与验收；尚未提交第八轮验收结果。

## 1. 为什么选择这一轮

前七轮已经串起“估时 → 找空闲 → 创建规划 → 冲突改期 → 拖动撤销 → 待规划清单”。结合现有待办、番茄、时间日志和个人统计，本轮补足“做完后看清结果”这一环，优化原有**规划统计**，不另造一个重复的复盘中心。

当前代码核查发现：

- `PlanBlockStatsScreen._buildMappedBlocks`将课程及旧式待办时间区间转换为虚拟规划，随后和真实规划共同参与总量，课程也会扩大规划分母。
- `_recordBelongsToBlock`允许没有规划ID的同一条待办专注按时间重叠匹配多个规划；随后逐块相加，存在重复计算的条件。
- `_actualSecondsForBlock`取规划累计缓存与所选范围内记录之和的较大值，混用了累计值和范围值；`effectiveDuration`还会将缺失的实际秒数回退成计划秒数。
- 总“达成率”用投入时长除以计划时长，另将达到80%的规划计作完成；这容易把“投入了多久”理解成“任务完成了多少”。
- “AI建议”由固定条件拼接，不调用AI；未来未开始规划也可能进入“无投入”建议判断。加载缺少明确的失败和重试页面。

这些是根据现有实现确认的计算路径，不代表所有用户历史数据都已经发生错误。本轮会用隔离数据重现并修复，不直接改写历史记录。

## 2. 用户最终看到什么

继续从首页今日规划、规划页更多菜单进入**规划统计**，保留日／周／月切换和前后日期导航。

页面顺序：

1. **紧凑概览**：真实规划时长、已结束规划完成情况、已记录有效专注、时间日志时长。手机两列，宽屏并排；数字可点开明细。
2. **投入趋势**：日视图显示当天汇总，周／月显示逐日计划与专注。默认概览，不把整月记录直接铺满。
3. **待办投入排行**：按具体待办UUID汇总已核实的专注，点击查看其记录；同名不同待办不合并。
4. **需要处理**：漏做规划保留现有重新安排入口；旧记录时长缺失、身份矛盾或同步冲突单独提示核对。
5. **复盘提示**：根据已结束规划和可核实记录给出本地规则提示，标为“复盘提示”，并能查看触发依据。

顶部用一个“统计口径”入口解释范围、计数和旧数据情况。明细进入独立页面，首屏50项、加载更多，保持筛选与返回位置。原规划时间轴仍保持24小时一屏和拖动新建。

## 3. 计算规则先约定清楚

### 3.1 真实规划

统计对象为当前账号数据库中未删除、无同步冲突、时间与状态合法且计划分钟数为正整数的真实规划UUID；不把课程、手机日历或旧式待办映射伪造成真实规划。时间／状态／计划时长非法或有同步冲突的规划单独进入待核对，不进入已核实预算与完成分母，不自动补值。原时间轴中的这些日程展示与占用规则保持。

规划归属所选范围，按**规划开始的本地日期**判断。跨午夜规划计一次，完整计划时长归开始日；明细注明跨日，不假装它完全发生在当天。日／周／月边界使用本地日历构造，不能用固定24小时推算日界线。

| 指标 | 规则 |
| --- | --- |
| 规划时长 | 范围内有效真实规划的计划分钟数；取消、跳过不进入执行预算，另显示数量 |
| 已结束规划完成情况 | 同一范围内结束时间不晚于现在、且未取消／跳过的有效规划；以真实`finished`状态计完成，显示“完成X／已结束Y”及比例 |
| 尚未结束 | 独立显示数量，不进入完成比例，也不因暂时无专注记录判漏做 |
| 漏做 | 仅依据现有`missed`状态，不把“已结束但仍planned”等状态自行改成漏做；后者显示待核对 |
| 任务完成 | 不从时长或规划状态推算；待办完成继续遵循原业务规则 |

分母为零显示“暂无已结束规划”，不显示0%评价。取消／跳过后曾经产生的专注仍是实际投入，不能随规划状态一起消失。

### 3.2 实际专注及唯一归属

- 范围内专注按**记录开始的本地日期**归属，和现有番茄范围读取保持相同日期边界；跨午夜记录完整秒数归开始日，并明确标注“按记录开始日统计”。暂停后的有效秒数不能凭墙钟跨度均匀分摊到两天。
- 已核实有效专注来自未删除、已结束、状态合法、无同步冲突且实际秒数为合法非负整数的记录；`completed`、`interrupted`、`switched`均可产生真实投入。零秒保留为零，不回退到计划时长。无结束时间、非法值等列入待核对，不当作仍在运行的实时计时器。
- 旧记录缺失`actual_duration`时，不把`planned_duration`计入“已记录有效专注”。单独显示“旧记录时长待核对”的数量及记录原值，保证数字不伪装成精确实际投入。现有番茄统计采用的兼容回退不在本轮改写；口径说明明确两页在旧记录上的差异。
- 每个记录UUID只参与本期实际总量一次。实际总量独立于规划匹配，包含未绑定待办／规划的合法记录。
- 规划归属优先核对显式`plan_block_id`和规划记录ID列表；一致时只认一个真实规划。显式ID缺失时，只有具体待办UUID一致且唯一时间重叠的真实规划才允许兼容关联。判断候选不能仅限所选日期范围，避免漏掉前一天开始的跨午夜规划；取消／跳过的历史真实规划仍可解释其已有投入。候选本身已删除、存在同步冲突或身份不可确认时只显示归属待核对。
- 多规划竞争、显式身份矛盾、悬空规划ID均显示“归属待核对”；不按同名标题猜测，不把一条记录重复记给多个规划。合法记录本身的实际秒数仍只进入总量一次，待核对的是其归属；记录本身有冲突或非法时长则不进入已核实总量。
- 范围实际明细可按“已关联规划／未关联规划／归属待核对”筛选。三类互斥且相加等于本期已核实专注总量。
- 规划累计缓存`actualFocusSeconds`仅在该规划的只读详情中作为“原累计参考”展示；不与记录取较大值，不补入本期实际，也不修复缓存。
- 规划详情分别标明“本期记录投入”与“累计记录投入”，不能将范围外记录悄悄加进本期数字。累计值同样来自有效记录并遵循唯一归属规则。

### 3.3 时间日志

单独统计范围内相交的未删除、合法、无冲突时间日志，按本地日期裁剪墙钟区间，按秒汇总后再格式化。不同日志可能重叠，标为“日志记录时长”，不宣称是去重后的工作时长。跨日明细保留原始起止时间。

时间日志不与专注相加为“总工作时长”，也不增加规划实际专注或完成率。点开记录进入既有详情；本轮不增加补录、编辑或自动关联操作。

### 3.4 复盘提示

只使用上述可核实数据：例如已结束漏做较多、有效真实规划预算较满。每条可展开查看触发数量及相关规划，不将未来尚未开始、取消或跳过的规划评价为未完成。

数据不足时明确提示，不输出“当前节奏稳定”等没有依据的评价；不调用远程AI，不消耗模型额度，不自动调整规划或待办。

## 5. 读取、刷新与安全边界

- 新增账号限定的只读统计仓储和纯计算／归属逻辑，页面只负责展示。账号及当前成员身份在请求前后复核；快速切换日期、维度、账号及离页后，旧请求不能覆盖新状态。
- SQL按范围和相关UUID批量投影、聚合；只读必要列。普通概览不加载全量待办、课程和番茄历史，不逐规划发起查询。关联名单分批读取，不能每一行分别查询。
- 涉及累计记录明细时按选中的具体规划／待办限定读取，采用稳定时间与UUID排序、50项游标分页。翻页期间数据变化废弃旧游标，刷新同一筛选下首屏；数字和明细保持同一读取口径。
- 复用现有存储刷新、前台恢复通知；页面可见时仅在下一规划结束或本地午夜做一次边界刷新，不后台轮询。专注未形成结束记录前不假报实时有效秒数。
- 旧Prefs迁移仍由原存储初始化完成。本轮只读查询不迁移、修补或清理数据；未初始化则提示先完成原初始化并重试。
- 加载中、真实空数据、筛选无结果、读取失败和存在待核对数据分别展示。来源失败不显示零值成功页；重试保留日期与维度。
- 只读明细不经过会自动维护规划状态的时间轴初始化；记录详情复用原入口。漏做重新安排仍走已验收的原流程，并在显式保存时保持原事务校验。
- 协作待办历史不以当前成员完成状态过滤掉真实记录；标题只作为展示，成员切换不串身份。历史待办已删除／找不到时保留记录标题快照和来源说明。
- 使用Material 3主题色，浅／深色及现有玻璃设置兼容；手机概览不再将五个指标硬塞一行，大字体可换行。减少动画设置沿用现有约定。
