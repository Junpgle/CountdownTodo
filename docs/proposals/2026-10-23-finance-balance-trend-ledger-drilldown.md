# 第36轮方案：月度结余趋势直达当月账单

日期：2026-10-23（北京时间）

状态：**已批准并实施；验收完成**

## 1. 建议与收益

第35轮已在财务概览末尾加入月度累计结余趋势。选中月份后，用户能读到该月月末（当前月为截至今天）的累计结余，但若想确认哪些账单构成当月变化，还要离开概览、手动切到流水并重新选日期。

本轮建议在趋势的选中月份说明旁增加明确的「查看当月账单」操作。点击后进入现有账单列表，并预先筛选到所选月份；用户可继续使用既有分类、关键词、收支类型、详情和编辑操作，快速核对趋势背后的流水。

## 2. 当前实现依据

- `lib/features/finance/widgets/finance_widgets.dart` 中的趋势卡已经让用户点选月份，并同步更新月份和累计金额；图表本身目前只负责选月，没有账单入口。
- `lib/features/finance/services/finance_repository.dart` 的月度点计算已经区分历史月末与当前时刻，并遵守期初结余起算日期。因此打开流水时可以复用选中点所属的月份，不需要新增余额口径。
- `FinanceLedgerPanel` 已支持 `DateTimeRange` 日期过滤；财务首页已有带日期范围打开账单的路径和「待发生」标记。可在此基础上补一个不带分类限制的月份入口。
- 当前工作区在 Android 课程提醒相关文件有既存未提交改动。本轮提案与后续实现不会覆盖、暂存或提交这些文件。

## 3. 批准后的目标行为

1. 趋势点仍只负责选择月份并更新累计金额；不会将普通点按改成直接跳页，避免用户误触后丢失图表上下文。
2. 选中月份的金额旁提供清晰可见的「查看当月账单」按钮。无可用趋势点时不显示该按钮。
3. 点击按钮打开财务账单列表，日期范围自动设为所选月份第一天至最后一天；若为当前月，则截至今天。账单列表保持所有收支类型，不附加类别筛选。
4. 账单列表仍按现有规则显示该日期范围内的实际账单和待发生项目。尤其当前月的今天若有尚未发生的计划账单，列表会保留既有「待发生」状态标记；趋势本身仍只代表当前时刻已计入的累计金额。
5. 关闭账单页后返回原概览，保留当时选择的月份和图表位置；账单页中的日期筛选独立于概览状态，不把临时月份筛选带回其他财务入口。
6. 历史月份无账单时，仍打开已选定日期范围的空列表，用户可看到准确月份并使用日期筛选清除或调整范围。
7. 窄屏、深色主题和大字号下入口可辨识、可触达，并使用主题色和现有财务页面样式。

## 5. 验收标准

1. Widget 测试验证点选月份后月份说明和金额同步更新，「查看当月账单」带出正确年份和月份；入口激活后调用正确月份，不由图表普通点按意外触发。
2. 导航测试验证历史月的范围为整月，当前月范围截止今天，账单页不附带类别或收支类型过滤；没有流水时仍显示对应日期范围的空状态。
3. 验证返回后概览仍停留在原选中月份，重复进入不同月份不会沿用上一次账单筛选；现有账单查看、筛选和详情路径继续工作。
4. 对当前日的待发生账单保留已有状态标记，不将其描述成已经影响当前累计结余；趋势金额和期初起算日期算法保持不变。
5. 运行新增测试、相关财务导航及账单测试、财务模块测试、受影响 Dart 静态分析、格式检查和 `git diff --check`；尝试正式 Web 构建。失败项逐项报告，不删掉有效测试来换取全绿。
6. 提供手机尺寸真实浏览器画面，展示趋势选月和月份流水入口，再展示筛选后的账单页；使用合成流水，不读取个人财务数据。另验证深色与大字号布局；真机验证仅在设备实际可用时报告。
