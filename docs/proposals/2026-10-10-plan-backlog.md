# 第七轮方案：待规划清单与快速安排

日期：2026-10-10（北京时间）。第六轮已由用户回复“确认通过”。本轮状态：**完整方案，等待批准；尚未实施**。

## 1. 建议与当前依据

增加一个“待规划”入口，集中找出尚未安排执行时间的未完成待办。选中一项后，直接进入已有的整页新建规划：先按第六轮的预计专注用时查找，显示两个推荐，再由用户调整并显式保存。

这轮解决的是“先找出还没安排什么”。你已经可以拖动空白新建、找可用时段、改期、撤销，也能从待办编辑页进入规划，但待办多时仍需要往返首页和规划页逐项查找。

本次检查了当前源码：

| 现有能力／限制 | 本轮如何使用或补齐 |
| --- | --- |
| `TodoPlanScreen`展示选中日期的时间轴、执行记录和统计，没有集中查看未安排任务的入口 | 增加按需打开的清单，时间轴不增加常驻列表 |
| 规划编辑器能选择未完成待办，但选择器不说明其他日期是否已经安排 | 清单查询未来有效安排，减少重复新建 |
| `getPlanBlocksByDay`只读取起点在当天的规划，`getPlanBlocksByTodo`可查看单项关联安排 | 待规划判定使用独立跨日／跨日期查询，不能仅凭当天没有规划就判为未安排 |
| `TodoItem`的日期、截止与旧式执行区间有不同含义 | 有截止时间不等于已规划；沿用已有旧式执行区间兼容规则 |
| 重复待办已有真实期次选择工具 | 按目标日期选真实未完成期次，不按标题或系列合并实际安排 |
| 独立协作完成状态由`todo_completions`和当前用户投影 | 清单和保存复核使用同一当前用户完成口径，避免把别人的完成状态套给自己 |
| 第六轮已提供本地估时、参考程度与依据弹层 | 进入编辑器时复用，不在清单中为几十项任务逐项估时 |

以上是当前源码调研结论。本轮尚未建立失败用例、运行新功能测试或构建预览，不预先承诺性能提升比例。

## 2. 用户操作与界面

### 入口

规划页顶栏增加“待规划”图标按钮，点击进入独立页面，保留当前规划日期作为目标日期。顶栏保留冲突入口，统计与刷新收进“更多”，控制手机宽度下的按钮数量；不增加顶栏高度、时间轴滚动或常驻面板。

新页面示意：

```text
← 待规划                              目标：10月11日 ▾
搜索待办…                             文件夹：全部 ▾
[待安排] [已有安排]

今天到期
复习高数             学习 · 今天20:00前完成     安排 →
整理笔记             学习 · 今天内完成         安排 →

未设截止
整理书桌             生活                    安排 →

                       加载更多
```

日期和任务仅为示意。分组以所选目标日期为参照；实际文案使用真实日期，避免查看明天时仍将明天误标为今天。

- 默认显示“待安排”，支持标题搜索与文件夹筛选；切换“已有安排”保留筛选条件。
- 日期只决定准备安排到哪天以及重复任务的代表期次，不把其他日期已有安排隐去。已安排到后天的任务不会因为查看明天就被当成没有安排。
- 每行只展示标题、文件夹、截止概况和必要状态，不添加估时详情、专注记录列表或额外设置表单。
- 点击“安排”进入正式整页编辑器，预选真实待办UUID、继承目标日期，等待估时后展示两个推荐并填入第一个。自定义弹窗仍默认五个、沿用避让记忆。
- 返回清单时保留搜索、文件夹与目标日期；取消编辑不改变安排状态。成功保存后刷新，该任务出现在“已有安排”。
- “已有安排”显示最近一个有效执行时段和额外安排数量。主要操作是“查看安排”，通过现有待办关联规划入口查看；确需多次投入时，可显式选择“追加规划”，不禁止一个待办对应多个规划。
- 正在专注的任务明确显示“正在专注／已暂停”，引导查看当前专注，不默认再次安排。
- 目标日期不可落在过去；从历史规划日打开时明确切到今天并说明。当天已过去的时段仍由原查找规则排除。
- 原截止已早于目标日期的任务保留在清单中提示“截止早于目标日期”，提供查看／编辑待办，不静默延长截止，也不忽略截止强行推荐。

只让清单和编辑页按现有规则滚动。全天24小时一屏、空白拖选新建、长按移动和边缘缩放保持现状。

## 3. 什么叫“待安排”

### 先确定可规划的真实待办

- 当前账号、未删除、当前用户视角未完成、UUID与标题有效的待办；同步冲突任务不能直接安排，提供回原待办处理的提示。
- 共同协作与独立协作沿用项目现有完成语义。独立协作按当前用户的完成覆盖值判断，不能只读原始`todos.is_completed`；读取期间账号或当前用户身份变化即废弃结果。
- 同名不同UUID独立。重复系列先在所有合格期次中按目标日期选择代表，再判断该期次是否有安排；不能先分页或先过滤已安排期次，导致另一未来期次冒充本期。
- 一个期次的规划只影响该UUID，不能使整个重复系列都显示已安排。已完成期次也不能遮住未完成代表。

### 再判断是否存在有效安排

| 情况 | 显示规则 |
| --- | --- |
| 存在未删除、真实规划，状态为planned／reminded／delayed／focusing，区间有效且结束晚于当前时刻 | 已有安排；查询所有日期，跨午夜也有效 |
| 本机专注运行状态仍在focusing阶段，包括暂停，明确绑定该待办或其真实规划 | 正在专注／已暂停；即使原计划时段已结束也不默认为待安排 |
| 只有finished／cancelled／missed／skipped规划，或所有有效时段均已结束 | 待安排；历史投入和历史规划保留 |
| 只有日期待办、截止时刻、物理创建时间或跨日截止 | 不构成占用，仍可待安排 |
| 存在合法、尚未结束的旧式同日执行区间 | 显示“旧式时间安排”，归入已有安排；用原有兼容规则核对业务起点、非全天、同日有效区间及去重，不能将普通截止误算进去 |
| 课程／手机日历／映射伪规划 | 不凭标题关联待办；不作为该待办已有真实规划，仍在查找时按原规则约束占用 |
| 关联规划存在坏时间、坏状态或无法确认的专注身份 | 显示“安排需检查”，提供查看；不能用读取失败或坏数据得出“没有安排” |

“待安排”表示没有有效的未来执行安排，不表示从未做过，也不表示剩余工作量。第六轮估时仍不减去已投入专注；不根据记录时长自动判定任务完成。

## 4. 查询与刷新

- 新增账号限定的只读清单查询服务。点入口才加载，不在打开时间轴时预热整份清单，也不为顶栏常驻计数额外扫描全部任务。
- 在SQL层筛选任务及有效规划，批量关联最近安排与数量；只投影清单所需字段，不逐条调用`getPlanBlocksByTodo`、不加载全部番茄历史、不逐项估时。
- 首屏50项，提供“加载更多”。在筛选及重复期次选择之后分页，使用明确、稳定的截止分组／日期／UUID排序与游标；搜索命中字面标题，参数化转义`%`、`_`，避免它们扩大为通配匹配。
- 不引入仅新SQLite才支持的语法。重复期次选择如需轻量元数据，分批读取并与现有选择规则做等价测试，不能退化成解码所有完整待办后假分页。
- 同一读取快照返回本页及同口径数量；数量不混入另一筛选条件。多页之间数据变化或日界线跨越时刷新首屏，废弃旧游标，不显示重复项或混合账号数据。
- 查询绑定账号、当前用户ID、目标日期、关键词、文件夹、状态和递增请求序号。快速切换、切账号、离页后，旧页不能覆盖新列表。
- 完成／删除待办、规划保存／改期／取消、同步刷新、专注开始／停止或前台恢复时复核。使用现有刷新通知和前台生命周期；页面可见时最多在下一规划结束／本地日界线做一次边界刷新，不后台轮询。
- 保留搜索与文件夹条件；数据确实为空、筛选无结果、读取失败分别显示。失败给重试，不能提示“全部安排好了”。
- 旧Prefs迁移继续由现有存储初始化路径负责；本轮不让清单查询自动迁移、修补或清理历史。如果初始化未完成，明确提示重试，不把Prefs遗漏误判成空清单。

## 5. 保存与操作边界

- 打开清单、搜索、切筛选、翻页、查看安排和进入／取消草稿均不新增待办、规划或oplog，不改完成状态或截止时间。
- 选中行进入编辑器前重新读取具体待办，复核有效性与当前用户完成状态；目标失效则刷新提示，不偷偷替换成另一项。
- 保存仍走原编辑器的显式保存、最新占用和事务校验，保留午休／用餐偏好、日历降级选择、冲突提示及失败保留草稿。当前用户完成投影复核会在关联待办的新建保存路径补齐，并让手动与推荐保存使用同一判断；不改团队协议。
- 若其他设备在编辑期间为同一待办新增未来规划，保存前明确提示已有安排，供用户“查看已有安排／仍追加这次规划”；追加是用户的显式选择。复核不通过时不产生半条规划或oplog，重新选择候选不绕过此检查。
- 多规划仍然允许，不按同名或整系列做禁止重复规则。当前正在专注、同步冲突、已完成／删除等失效状态不以“仍追加”绕过。
- 连击只打开一份编辑器、只提交一次保存；保存失败保留本次草稿，返回清单也不会假装已安排成功。

本轮不批量安排，不后台自动找时段，不自动新建任务／重复期次，不自动延长截止、不自动完成或改期，不新增系统日历读写。选择候选后的保存继续使用原有同步与日历协议。

## 7. 验收标准

1. 无规划、只有历史／取消／漏做规划的合格未完成任务进入待安排；其他日期或跨午夜有效安排不会被遗漏。多块按同一UUID聚合，最近时段和数量正确。
2. 本机仍在专注／暂停的任务不重复作为默认待安排。课程、同名、普通截止、日期待办、映射伪块不冒充任务绑定；旧式有效执行区间按既有规则显示。
3. 共同／独立协作、两名用户、账号切换、已完成／删除／冲突、空标题／坏规划、过期截止都有对应读取和正式操作测试。
4. 重复代表先筛有效未完成期次、按目标日期选定，再检查安排并分页；本期有安排时不能换成别期冒充待安排；不同系列和同名任务独立。
5. 50项分页、51／500／1000任务、搜索与文件夹组合、字面`%`／`_`、稳定排序、无重复／漏页、数据刷新清游标。验证查询次数和返回字段边界，不预先承诺绝对耗时。
6. 进入正式编辑器先按估时查询且只显示两个推荐；自定义默认五个，避让记忆、迟到估时与手动配置保护沿用。取消零写入，成功只保存一次并更新清单。
7. 编辑时他端新增安排需明确选择追加；完成／删除／冲突／切账号／正在专注拒绝旧操作；保存失败保留草稿，事务故障无半条数据。
8. 320／390窄屏、720×360横屏、桌面，大字体与键盘、深浅色／普通／玻璃可操作无溢出。时间轴仍全天24小时一屏，拖动新建、慢拖吸附、撤销可用。
9. 清单读取与取消路径的业务表逐字段不变；不触发新日历访问、远程估时或后台轮询。查看已有安排进入原页面后原有行为单独核对，不将原页面的既有状态维护误报为新清单查询写入。
10. 完成新服务／正式界面测试及第三至第六轮聚焦回归，相关分析／格式／差异检查通过，交付真实合成数据浏览器操作截图及报告。全仓、真实账号同步和各平台实机验证分别说明证据边界。

## 8. 批准后的执行顺序

先建立未安排／他日安排／重复代表／协作完成／读取失败及分页边界用例，再实现只读查询和清单，接入现有整页规划与保存前复核，最后完成回归、视觉验收及报告。实施中发现范围外的结构问题先说明，不擅自扩展到后台自动规划或大规模迁移。
