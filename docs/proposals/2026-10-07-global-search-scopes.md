# 第一轮方案：全局搜索范围筛选

日期：2026-10-07。状态：第一轮实施与本地验收完成；用户于 2026-10-07 回复“没问题”，已通过本轮验收。

实际交付与证据见[第一轮验收报告](../reports/2026-10-07-global-search-scopes-acceptance.md)。

## 1. 建议与依据

将全局搜索中的“支持搜索”说明标签升级为可操作的范围选择，让用户可以直接“只搜记账”“只搜日程”“只搜待办”。范围同时约束结果展示与本轮本地数据源查询。

本轮阅读了项目架构、功能清单、待办语义、规划块说明，以及全局搜索的界面、查询服务、扩展适配器和现有测试。项目已有丰富的业务模块与统一搜索入口，因此这一操作优化能够服务多个模块，且可以独立交付和验收。

方案调研时的源码依据（以下为改动前状态）：

- `lib/widgets/global_search_overlay.dart` 的 `_buildSearchScopeHint` 使用 `Container` 和 `Text` 显示标签，没有选择回调。
- `SearchService.search` 对非空关键词启动习惯/挑战、核心数据库和扩展数据源查询，没有范围参数。
- `GlobalSearchExtraService.search` 查询记账、日记、日程、打卡、挑战任务、AI 对话和本地团队。
- 搜索结果已有分组、每组初始三条、展开更多、详情跳转和容器变换动画，可在这些能力上增加范围选择。
- 当前界面仅以关键词判断异步返回是否仍有效；新增范围后，需要一起校验请求序号、关键词和范围。

调研阶段的这些结论来自源码检查；实施后的验证与测量见验收报告。根 README 中的版本记录较旧；本轮以 `pubspec.yaml` 的 6.6.117 和当前源码为准。

## 2. 用户收益

示例：输入“午餐”时，可能同时出现相关待办、账单、日记和对话。选择“记账”后，列表只保留记账结果，直接打开账单；切回“全部”后，用同一个关键词搜索所有来源。

输入“今天”并选择“日程”，可集中查看课程、固定日程和规划块；选择“专注与时间”则查看番茄钟、时间日志和标签中的适用结果。日期匹配沿用各来源现有规则，范围切换不会把所有日期含义强行统一。

可验证的收益是减少无关结果及无关本地来源查询。响应耗时是否下降须以实施后的测量为准，本方案不预先承诺加速比例。

## 3. 交互设计

搜索面板示意，方括号表示可选择项，星号表示当前选中：

```text
搜索：午餐                                   清空
[全部] [待办] [日程] [记账*] [专注与时间] [更多 ▾]
搜索范围：记账

记账 · 3 项
  午餐     支出 · CNY 28.50 · 2026-10-07
  ……
```

金额与记录仅为示意数据。

- 常用范围固定为“全部、待办、日程、记账、专注与时间”。“更多”展示其余范围；选择后，范围名称在主面板明确可见。
- 单选范围，默认“全部”；本轮不增加多个范围的组合规则。
- 窄屏使用可横向滚动的范围栏，宽屏完整展示；更多范围使用适配屏幕的选择面板。
- 点击范围保留关键词，立即发起对应查询；等待期间不得继续将旧范围的结果呈现为新范围结果。
- 清空输入保留所选范围。关闭并重新打开搜索时恢复“全部”，避免下次搜索因隐含范围漏掉结果。
- “全部”范围的空输入沿用搜索建议和历史。其他范围的空输入显示“输入关键词，在记账中搜索”等提示，不自动列出全部账单或其他业务数据。
- 有关键词但没有结果时，显示“在记账中未找到‘午餐’”，提供“搜索全部”按钮。该按钮保留关键词并切换范围。
- 已存在的分组、每组三条、展开更多继续生效。范围栏不展示其他范围的结果数量，避免为了计数仍查询所有模块。
- 打开结果后返回，保留关键词和所选范围，并刷新该范围；仍使用现有打开/返回动画。
- 动态取色、深色模式、液态玻璃开关沿用项目主题；范围选择不能依赖颜色作为唯一状态提示。

## 4. 范围与覆盖关系

| 范围 | 搜索内容 | 当前结果类型 |
| --- | --- | --- |
| 全部 | 当前所有可搜索来源、设置和快捷操作 | 全部类型 |
| 待办 | 待办事项、待办文件夹 | todo、todoGroup |
| 日程 | 课程、固定日程、规划块 | course、fixedSchedule、planBlock |
| 记账 | 账单、分类、付款方式、预算、周期规则、模板、贷款与分期 | finance |
| 专注与时间 | 番茄钟、时间日志、专注标签 | log、tag |
| 倒计时 | 倒计时记录 | countdown |
| 习惯 | 习惯、习惯打卡 | habit、habitCheckIn |
| 挑战 | 当前挑战、挑战任务及其记录、云端模板 | challenge、challengeTask、challengeTemplate |
| 屏幕时间 | 屏幕使用记录 | app |
| 团队 | 团队、公告、团队系统消息 | team |
| 日记 | 本地私密日记 | journal |
| AI 对话 | 会话标题、对话消息 | chat |
| 设置与操作 | 现有设置索引、快捷操作 | setting、action |

`recommend` 和 `history` 是空输入的辅助内容，只在“全部”的建议区显示。范围覆盖按已有结果类型定义；例如“记账”范围主要搜索记账记录，不额外混入标记为 setting 的设置入口。日期查询继续遵守现有来源的适用性。

## 5. 实现方案与边界

### 查询与模型

- 新增集中维护的 `SearchScope` 定义，包含名称、对应结果类型和数据源选择规则，避免界面与服务各维护一套映射。
- 给 `SearchService.search` 增加可选范围参数，默认全部，兼容已有调用。
- 将范围下传到核心数据库查询与 `GlobalSearchExtraService`，在启动查询前跳过不相关本地来源；不能只在所有查询结束后过滤展示结果。
- 组合适配器内部也做选择：例如“日程”查询课程、固定日程和规划块；“习惯”查询习惯与打卡，但不加载挑战。
- 保留最终结果类型过滤作为防线，保留匹配、相关度排序、去重及备注命中的既有规则。
- 设置索引、动态快捷操作按范围过滤。搜索历史仍记录关键词，切换范围和结果页返回刷新不重复新增同一次搜索记录。

### 异步与远端数据

- 界面使用递增请求序号，并绑定关键词和范围。只有最新请求可以更新结果和加载状态。
- 覆盖 A → B → A 范围切换、关键词快速修改、清空输入，以及详情返回时的刷新，避免仅比较字符串导致旧结果重新被接受。
- 网络缓存沿用现有账号隔离、预热及五分钟有效期；读取缓存后的结果仍受范围约束。
- 本轮不重构远端缓存和预热协议，因此不承诺减少打开搜索时的远端请求数。断网继续使用现有本地查询和可用缓存，搜索不会新增网络依赖。

### 本轮范围

- Flutter 客户端的统一搜索入口覆盖 Android、Windows、macOS 和 Flutter Web；iOS 可复用同一界面，运行验证依设备条件执行。
- 本轮不需要数据库迁移、服务端接口、原生权限或业务数据变更。
- 不添加新的日期语法、记账专用筛选器、全局快捷键或分页重构。
- 不改变 React 介绍站、手环应用、MCP 服务、Cloudflare Worker 或生产后端。
- 不调用外部 AI 服务分析用户数据，私密日记继续使用当前本地来源。

## 6. 风险与控制

1. **范围漏掉来源**：用完整类型映射测试覆盖枚举，特别验证习惯/打卡、挑战/模板、贷款/分期和团队消息等子类型。
2. **快速切换覆盖结果**：用可控制完成顺序的异步测试验证，不依赖真实请求耗时碰运气。
3. **筛选后出现错误空态**：关键词、当前范围、请求序号和加载状态一起更新；旧请求不能清空当前结果或结束当前加载。
4. **详情返回与动画退化**：运行现有导航测试，并验证范围与关键词在返回后仍一致。
5. **手机键盘挤压结果区**：验证窄屏、横屏、键盘弹出和较大字体；范围栏控制高度，更多选项不堆满主面板。
6. **工作区混入已有改动**：调研时发现首页、待办编辑、AI 对话和玻璃组件等已有未提交修改；计划修改的搜索主体文件当时没有本地差异。实施前重新核对状态，保留所有已有工作。

## 7. 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 同一关键词命中多个模块 | 选“记账”只展示 finance；切回“全部”恢复其他类型 |
| 日程复合范围 | 课程、固定日程、规划块均可命中，没有待办或账单混入 |
| 子类型覆盖 | 习惯打卡、挑战任务/模板、贷款/分期、团队消息遵循映射 |
| 空输入与无结果 | 专属提示准确；“搜索全部”保留关键词；重新打开默认全部 |
| 来源调度 | 记账查询不调用日记、AI 对话、习惯等不相关本地来源；全部仍调用原有来源 |
| 快速切换 | 故意打乱异步完成顺序后，仍只显示最新关键词和范围的结果 |
| 日期、中文、备注、多词 | 与原搜索规则一致，不因范围选择漏掉已有合法命中 |
| 打开与返回 | 原有结果目的页与容器变换继续工作，返回后范围和关键词保留 |
| 显示与主题 | 窄屏、宽屏、深浅色、较大字体及键盘弹出无溢出，状态可识别 |
| 查询量与耗时 | 用合成跨模块数据报告实际来源调用数与耗时；不访问用户实际账本或日记作为测试样本 |
