# 第32轮方案：固定日程重复系列按范围编辑与单期状态保护

日期：2026-10-22（北京时间）

状态：**待用户确认；批准前不修改实现代码**

## 1. 建议与收益

固定日程按每个日期保存成独立记录，但编辑器现在把重复系列整体重建和保存。用户不能只改当前场次或从当前场次起调整规则；编辑一个已结束场次时，保存还可能把该场次的“已结束／已取消”状态、关联待办或外部日历身份复制到系列其他日期。

建议为手动编辑的固定日程增加三种明确范围：“仅本次”“本次及以后”“整个系列”。每次日程仍是独立记录：范围外的历史、状态、关联与来源不受影响；系列拆分、冲突检查和本机写入均按实际受影响的 UUID 执行。默认选中“整个系列”，保持当前编辑行为，同时在保存前展示范围与影响数量。

这补齐产品语义文档已定义、但固定日程编辑器尚未提供的三种修改范围，并让固定日程的操作与重复待办的编辑范围保持一致。

## 3. 用户操作与界面

1. 仅对有至少两个未删除实例、由应用管理的重复固定日程显示“修改范围”。单次固定日程继续按当前方式编辑；导入／日历来源或绑定外部事件 ID 的记录不提供系列拆分，以免复制或破坏外部身份。
2. 编辑页在重复规则附近显示紧凑范围卡片。选项为：
   - **仅本次**：只影响当前场次，副文案显示场次数和日期。
   - **本次及以后**：保留此前场次，从当前场次建立后续系列；副文案显示此前保留数与本次起影响数。
   - **整个系列**：影响所有未删除场次；副文案显示总数、首末日期。
3. 默认选中“整个系列”，明确标记“当前行为”；打开编辑器时仍记录用户实际点击的场次日期。选“仅本次”或“本次及以后”后，日期字段以该场次为基准；选“整个系列”时，重复规则字段以系列首场为基准。
4. “仅本次”不允许改重复频率或系列结束范围；“本次及以后”允许修改规则，并以当前场次作为新规则起点；“整个系列”沿用整组编辑和规则设置。
5. 保存前显示影响确认：范围名称、场次数、首末日期、此前保留数，以及是否新建独立场次、截短或延长后续系列。仅本次改动仍经过确认，但使用紧凑摘要。
6. 所有入口使用相同范围选择、保存复核和错误处理。窄屏可滚动查看摘要，主确认操作固定可见；颜色使用现有主题色。

## 4. 范围语义与记录保护

### 仅本次

- 标题、地点、备注、提醒和时间只修改当前记录；取消状态始终只属于当前场次，并在控件旁标明“仅影响本次”。其他期次的状态、ID、日期和字段不变。
- 不改变重复规则。若日期未移动，保留当前记录 ID 和系列归属，只更新当前记录字段。
- 若日期移到系列原日期之外，原系列场次保留原 UUID／日期并标记为已取消；新日期创建一条独立固定日程（新 UUID、无重复规则、无系列 ID）。这样当前重复规则和锚点不变，且不会在原日期留下一个看似仍有效的重复场次。
- 本轮不复制外部日历事件身份。导入或外部绑定事件已在界面上限制系列范围；保存前再验证来源，避免陈旧界面绕过限制。

### 本次及以后

- 当前场次作为新系列起点；此前场次及其字段、UUID、系列归属与状态原样保留。
- 当前及未来记录按新规则生成或调整，组成新的 `recurrenceSeriesId`（以当前场次 UUID 为系列 ID）。当前场次日期变化时，新规则锚定到保存后的日期；已有当前／未来记录按期次顺序稳定复用 UUID，超出范围的旧记录写逻辑删除，新生成的额外期次分配新 UUID。
- 默认保留原系列剩余时间范围；用户明确更改重复结束日期时按新值执行。确认摘要同时显示旧结束日期和新结束日期。

### 整个系列

- 当前系列全部未删除记录按完整新规则重建；历史、当前、未来的数量在确认页明确显示。
- 同一逻辑期次尽可能保留原 UUID；新增日期使用新 UUID，移除的日期写逻辑删除。重复规则缩短不能仅隐藏行，也不能留下可被同步恢复的有效旧实例。
- 只在用户显式修改“日程已取消”时更新当前场次状态；普通内容编辑不会把所选场次的已结束、已取消或待安排状态批量复制给其他期次。团队归属仅在用户有权限且显式更改时应用到所选范围。

### 各场次字段

- 已有场次始终保留自己的状态、UUID、创建时间、来源、设备 ID、外部来源／事件 ID 和关联待办；整组内容编辑不得把某一场的这些记录身份复制到其他场次。
- 用户有权限且主动更改团队归属时，仅对范围内记录应用新团队；保存时逐条校验创建者／团队权限。
- 新建的重复实例继承所选系列的标题、时间、地点、备注、提醒、时区与团队设置；不复制外部事件 ID。关联待办按现有系列规则处理，并以测试确认同一系列生成实例的一致行为。
- 任何范围变化都不修改规划块、专注、时间日志、系统日历中的其他事件或待办完成状态。

## 5. 保存、冲突与同步边界

1. 将范围选择与纯数据变更构造放入独立服务，输入当前系列快照、选中实例、目标范围和编辑结果，输出本次变更、受影响活动实例及说明摘要。避免 UI 临时筛行造成范围不一致。
2. 保存前重读当前账号下的系列，逐 UUID 核对成员集合、版本、更新时间、删除／取消状态和团队权限。编辑期间若同步或其他窗口改变了成员或记录，整批拒绝保存，页面保留输入并提示重新载入。
3. 通过固定日程存储层在本地 SQLite 事务／batch 中一次写入所有变更与对应 `op_logs`；本地校验失败不写入部分期次。网络同步仍沿用现有逐记录 LWW 与 `fixed_schedules v1` 能力，不宣称云端跨多条记录原子提交；同步过程中其他设备可能短暂看到部分变更，最终依赖现有队列收敛。
4. 新建单次例外与原场次取消必须作为同一个本地保存批次。冲突读取或保存失败时不留下孤立的例外记录或取消行。
5. 只对本轮受影响的活动场次运行现有课程／固定日程／规划冲突检测；冲突确认中区分原有冲突与本次新增冲突，并展示日期、时间和来源。取消确认不写数据。
6. 不新增数据库字段、服务端接口或能力版本，不改 Alibaba 生产目录；使用当前 `FixedScheduleItem` 字段与逐记录同步协议。实现中继续遵守只修改 CDT-server `debug/` 的仓库规则；本提案预期无需改服务端代码。

## 6. 实施范围与明确不做

预计涉及固定日程范围变更服务、固定日程编辑页、存储层基线复核、产品语义文档及对应单测／组件测试。AI 的 `update_schedule` 范围解释保持现有语义，只增加防止单场状态或来源字段串到整个系列的回归覆盖。

本轮不做：

- 不改变固定日程删除行为；编辑器当前“删除整个重复系列”的明确确认保持不变。
- 不改变课程、手机日历源记录、待办、规划、提醒服务或日历读写权限。
- 不批量取消整系列；“已取消”状态仍是单场状态。后续若需要整组取消，另行设计明确操作与恢复方式。
- 不改变 AI 工具协议、生产服务、数据库字段、同步能力版本，不部署、不发布、不推送。
- 不删除仍有效的测试。若现有断言与本方案新契约冲突，只调整该断言并增加对应的旧行为保护覆盖。

## 7. 验收计划

1. **范围入口**：普通固定日程不显示范围；重复系列在详情、首页、搜索进入的编辑器均展示三种选择，默认整组；每种范围显示正确数量和日期。
2. **本次编辑**：仅改当前场次的标题、时间、地点、提醒或状态；其他 UUID、内容、日期及状态逐字段保持。移动日期后旧期次取消、新独立场次出现，重启和同步往返后不重复、不丢失。
3. **本次及以后**：此前记录逐字段不变；当前和之后记录使用新的系列 ID／规则，日期、首末日期、UUID、状态及新增／移除实例准确；月末、闰年、自定义间隔和跨夏令时均覆盖。
4. **整个系列与状态**：混合“已结束、已取消、未开始”状态的系列修改标题、时间、提醒和团队归属后，场次状态和记录身份保持；只有显式操作单场取消时改变该场状态。
5. **来源与关联**：`externalSource`／`externalId` 不会跨实例复制；关联待办按方案策略保存；导入／外部绑定来源不提供会复制外部事件的范围操作；规划、专注和时间日志不变。
6. **冲突与并发**：确认页只列实际受影响的冲突；取消不写入；模拟编辑期间另一窗口／同步改动系列成员或版本时，整批拒绝且输入保留；SQLite 写入失败时没有部分 `fixed_schedules` 或 `op_logs`。
7. **同步与权限**：验证每条记录使用既有 oplog 和 `fixed_schedules v1` 字段；未授权的跨团队修改在保存前拒绝；只报告本地／协议测试结果，不以构建替代真实多设备验证。
8. **视觉证据**：提供手机和桌面三种范围的真实界面截图，至少覆盖系列范围选择、影响确认和单场移动后的结果；另检查深色与大字号可读性。验收报告内嵌或链接截图，不用示意图替代运行截图。
9. **代码检查**：运行固定日程 recurrence、编辑器、冲突、存储／同步及 AI schedule 定向测试；运行 `flutter analyze`、Web release 构建、浏览器流程和 `git diff --check`。全量测试分模块执行并报告所有失败，保留有效测试。
