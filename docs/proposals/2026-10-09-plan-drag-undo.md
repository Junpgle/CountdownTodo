## 1. 为什么建议做这个

当前源码中，`TodoPlanScreen` 的 `_PlanGridViewState` 通过长按移动、左右边缘缩放既有规划：

- 手势更新直接修改传入的 `TodoPlanBlock` 对象，尚未保存的预览会进入页面共享数据。
- 松手调用 `savePlanBlocks`，没有本次操作的版本条件，也没有失败回弹和撤销入口。长按但未改变时间也会递增版本并保存。
- 整块移动先裁剪开始时间，再裁剪结束时间；例如22:30–23:30向后移动45分钟，会变成23:15–24:00，原60分钟缩短为45分钟。
- 缩放按每一帧的增量取整，未累计完整位移；多次小于取整阈值的移动可能没有效果。
- 映射来源已禁止拖动，但真实规划的手势入口没有统一按状态区分专注中、历史与可调整记录。

项目已有 `savePlanBlockEdited` 的条件事务、oplog、原身份与实际数据保留机制，以及第四轮的只读冲突入口，可以复用。当前规划相关源码没有拖动撤销记录或按钮。

以上为批准前的源码调研结论。实施时已先用正式界面手势复现午夜截短和无变化仍写入，再完成修复及回归。

## 2. 用户看到的行为

### 正常移动与缩放

仍然长按整块移动，拖左右边缘改变开始／结束时间。时间轴不增加滚动，不改变全天24小时一屏。空白处拖选仍进入现有整页新建界面，取消草稿不写入。

拖动只做本地预览，松手后保存一次。预览显示准确的起止时间和分钟数；仅凭块中窄小文字看不清时，用不遮挡手指的紧凑提示辅助。提示使用动态主题色，避免占用额外常驻区域。

整块移动始终保留原时长。接近午夜时限制可移动的开始位置：60分钟规划最多移动到23:00–24:00，不会变成更短的规划。左右缩放才改变计划时长，最小长度沿用当前时间粒度；累计手势位移后统一吸附，慢慢拖也能正确变化。

### 一步撤销

例如把“复习高数”从19:00–19:45移动到20:00–20:45，保存成功后显示：

```text
已调整「复习高数」
19:00–19:45 → 20:00–20:45                 撤销
```

提示短暂显示约6秒，标题过长时合理截断。在当前日期页面内，提示消失后仍可点工具区“撤销上次调整”图标；有可撤销操作才显示图标，窄屏使用图标和说明，不增加一整行常驻卡片。

点击撤销后，恢复这一次移动／缩放前的起止时间和计划分钟数，保留同一UUID、配置和实际记录。成功后提示“已恢复原时段”，清除本次撤销入口。

只保留最近一次成功移动／缩放；后续成功调整替换它。失败、无变化、取消的手势不覆盖上一条。切换日期、账号、离开页面或重启应用后清除，不提供多步历史或重做。本轮不把新建／删除、普通编辑器保存、第四轮改期纳入撤销，按钮文字明确为“撤销上次调整”。

### 保存失败或记录已变

保存期间禁止重复操作同一调整流程，显示轻量保存状态。失败后结束预览并重新读取真实记录，简短提示原因；不得把未保存的位置当作已经成功。

如果另一设备修改了同一规划、待办完成或原规划进入专注，拒绝过期操作，刷新最新内容。撤销也遵循这一规则，不用旧快照覆盖后来发生的修改。

## 3. 手势与状态规则

| 场景 | 处理 |
| --- | --- |
| 未结束的 planned／reminded／delayed 真实规划 | 可移动／缩放；保存前再检查资格 |
| focusing 或存在与该规划关联的当前专注运行标记 | 保持查看当前专注能力，不通过拖动更改时间 |
| finished／missed／skipped／cancelled、已删除、已结束 | 不提供时间调整手势；已有详情与第三轮重新安排继续可用 |
| 映射课程、兼容旧待办投影 | 保持只读来源导航，不转成真实规划 |
| 专注和时间日志 | 保持实际记录只读，不能被当作规划拖动 |
| 无位移、移回原区间、手势取消 | 取消预览；不写规划、不递增版本、不生成oplog |
| 多个小时分段属于同一规划 | 统一同一预览与保存上下文，不重复写入 |
| 调整途中切日／离页 | 取消尚未提交的预览；已提交保存按捕获的账号、UUID和条件完成，过期页面不显示旧结果 |
| 切换账号 | 写入前校验当前账号；旧请求不能更新新账号界面或数据 |
| 后台恢复或来源刷新 | 未提交预览失效时清除；读取真实记录，重新核对撤销资格 |

时间采用本地日期边界，允许结束恰好为次日00:00，不通过固定24小时毫秒数假定所有本地日期长度相同。目标／恢复时段必须有效、结束时间仍在未来，不把调整后的记录直接落入已结束历史。原规划无法完整放入所选单日时，不悄悄截短，提示用编辑器调整日期。

## 4. 保存与撤销的数据保护

手势开始捕获不可变原快照，拖动中的候选单独存放，不直接改传入对象。松手时仅提交用户确认的起止时间和对应计划分钟数。

保存使用现有条件事务：严格读取当前账号和真实UUID，校验原版本、更新时间及内容、关联待办有效性、状态和当前专注，再更新。关联待办不能已完成、删除或处于同步冲突。结果保留原备注、番茄、提醒、来源、实际专注、番茄关联、日历与设备身份。其他规划、课程、固定日程、待办和实际记录不变。

撤销记录包含原时段和本次保存返回的真实记录身份。撤销前要求当前记录仍与本次保存结果匹配；期间的任何内容变化都停止撤销，并清除过期入口。原时段已结束或无法有效恢复时也不倒改历史，提示读取最新安排。数据库读取失败保留可重试提示，不把失败误判成记录不存在。

撤销是一笔新的受校验更新：同一UUID、版本继续递增、写一条对应oplog；不把旧版本写回，不删除已生成同步日志。一次调整与一次撤销各自原子提交。oplog写入失败时该次完整回滚；连续点击只执行一次。

只恢复时间和计划分钟数，不恢复旧状态、不回退实际投入、不切换关联待办，也不复制或重建系统日历事件。沿用项目已有同步路径，不新增手机日历写入权限或专门的外部事务。

条件校验依据本地当前记录，能阻止已经同步到本机的修改被旧操作覆盖；不宣称锁住其他设备尚未同步的变更，后台同步继续遵守既有冲突处理规则。

## 5. 与第四轮及避让规则的关系

直接拖动仍表达用户手动指定时间。午休／用餐避让是查找偏好，不作为拖动或撤销的硬限制。

本轮不在每次松手后增加占用确认弹窗，也不让每帧手势触发日历／数据库查询。移动或恢复原时段后，第四轮按现有刷新机制重新检查冲突；即使恢复后的原时段与后来新增的会议重叠，也正常恢复并展示冲突，由用户决定是否改期。

主动查找推荐或从第四轮整页改期进入，仍沿用原严格占用、截止和避让校验。两条路径各自保持清晰行为，本轮不改动空闲推荐算法、已记住偏好、两个默认推荐或自定义查找弹窗。

## 7. 验收标准

1. 正式规划日视图保留全天一屏、空白拖选新建、长按移动和左右缩放；实际记录和映射来源不误触新建或调整。
2. 整块移动始终保持时长；午夜边界、慢速小位移、不同时间粒度、左右缩放最小长度和跨小时分段正确，手势取消恢复预览。
3. 无变化操作零写入；有效松手仅一次保存、一条oplog；失败回弹到真实数据，不保留假成功位置。
4. 撤销提示与工具图标可达；提示消失后仍能撤销最近一次；切日、账号和离页正确清除；失败或取消的下一次手势不替换已有撤销机会。
5. 撤销后原UUID、配置、实际与关联字段不变，仅恢复原时间／计划分钟数并产生新版本和oplog；其他记录逐字段不变。
6. 保存与撤销期间原记录变化、状态／专注变化、待办完成／删除／冲突及账号切换均阻止过期写入；事务失败完整回滚；连击不重复执行。
7. 产生或消除重叠后第四轮入口刷新；没有额外确认弹窗或自动改期；第三轮恢复、整页新建、两个推荐、自定义查找及避让记忆回归通过。
8. 320／390窄屏、桌面、横屏、大字体、普通／玻璃、深浅色均无溢出，撤销提示不遮挡主要操作；不增加时间轴纵向滚动。
