# 可用时段的前后缓冲

第十轮，2026-10-11。入口：新建规划块 → **自定义寻找时段 → 安排衔接（可选）**；已有规划的“找可用时间”展开面板使用相同控件。

## 操作

- 开始前、结束后分别设置。不留空为0；快捷值为5、10、15、30分钟，自定义接受0–120的整数。
- 初次均为0，修改后按账号记在本机。旧版避让设置保留，升级后缓冲均为0；不同账号独立。
- 普通新建页只显示推荐及条件摘要。控件在自定义弹窗中，空间充足时并排，窄屏大字体纵向排列。
- 修改条件使旧候选失效，已填入时间、备注及番茄配置保留。取消弹窗不自动采用结果；默认设置未变化时保留原选择。
- 无结果时可主动点“本次不留缓冲再查找”，仅当前查询使用0/0，不改变记住的默认值，也不自动选用结果。“恢复记住的缓冲”恢复默认。
- 保存设置失败时提示“本次查找已使用，默认设置未能记住”，当前参数继续用于本次查询。坏设置须主动重置缓冲；有效避让选项保留。

## 规则

任务前留B分钟、后留A分钟时，真实占用`[u,v)`在计算中扩为`[u-A,v+B)`。查找及保存共用该规则；恰好满足间隔可用。例如课程10:00结束、下项11:00开始，前10后5时可安排范围为10:10–10:55，30分钟首个推荐是10:10–10:40。

课程、固定日程、有效规划、兼容旧执行区间及同日有时刻手机事件参与。读取邻日范围并保留原始边界后计算，处理午夜附近的缓冲；原本全天、跨日期手机日历事项仍不占空闲。午休、用餐及自定义避让按原区间避开，不额外扩张。只读专注、时间日志不变为预约来源。

保存前刷新来源并校验当前默认值；SQLite写事务再查本地占用。新安排即使与任务未重叠，只要挤占所需缓冲，也拒绝保存且不启动专注。草稿恢复、冲突改期、漏做重新安排及显式应用内日历降级传递同样参数。

只保存任务真实起止时间与时长，不创建缓冲规划、提醒或日志，不增加番茄预算和复盘投入。没有数据库迁移、后端、依赖、权限或同步字段变化。手动拖动和全局冲突仍沿用既有行为；本机查询不构成多设备或系统日历的原子预约。
