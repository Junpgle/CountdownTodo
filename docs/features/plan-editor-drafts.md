# 规划草稿与退出保护

核对日期：2026-10-11。第九轮方案见[规划草稿暂存与退出保护](../proposals/2026-10-11-plan-editor-drafts.md)。

## 使用

- 规划页“更多 → 规划草稿”查看本机草稿；新建规划页“更多操作 → 保留草稿”主动暂存，继续留在编辑器中。
- 修改时间、待办、备注、番茄或提醒后返回，选择继续编辑、放弃修改或保留草稿并离开。打开查看、自动填入建议及全部改回原值不触发确认。
- 普通新建支持时间轴拖动、首页待办编辑、待规划清单三个入口。相同待办有草稿时显示提示，需主动继续，不覆盖其他待办输入；替换尚未保留的表单会确认。
- 草稿按账号数据库和当前成员隔离，最多5份。满额报错并保留当前输入，不清理旧草稿。更新及删除核对修订号，旧页面不能覆盖另一页面的更新。
- 已有规划编辑、冲突调整、漏做重排只提供退出保护，不提供跨重启草稿。编辑底部弹层关闭直接下滑退出，关闭按钮、系统返回和遮罩点击仍走保护；时间轴拖动操作保持。

## 恢复与正式保存

草稿恢复待办UUID、日期时段、完整备注、单轮番茄、轮数及提醒。推荐、日历快照和追加确认不持久化。再次保存前重新核对身份、待办和占用；过期时段可修改日期，时区变化需确认当前显示的时间。手机日历失败仅在显式选择后使用应用内检查。

待办失效不按同名替换，草稿列表仍可查看保留内容、复制备注或删除。恢复失败不出现可提交的空表单，提供重试。待规划来源重新检查现有安排并要求重新确认追加。真实保存事务再次核对草稿修订与原业务约束。

每份草稿预留一个新规划UUID。正式保存成功后删除匹配修订的草稿；清理失败单独提示成功与清理状态。再次恢复时按该UUID识别已保存规划，只查看，不生成第二份；目标已变化／删除时明确提示。保存规划成功但专注未启动沿用原错误状态，不重复创建规划或启动计时。

## 存储和限制

schema 58新增`local_plan_editor_drafts`及成员排序索引。新建、升级和打开数据库均确保该本地表存在，不迁入历史表单或AI建议。

暂存只写本地草稿表，不产生正式规划、待办、业务审计或oplog，不占时间、不发提醒、不调用AI、不触发同步。业务导出和云／局域网同步的明确对象名单不包含草稿；完整本机数据库文件副本可能包含本地草稿。

仅支持**主动暂存**。未主动保留的最新修改在系统强杀、网页刷新或关闭窗口后可能丢失；没有浏览器关闭标签拦截承诺。单份载荷上限256KiB，超限明确失败，不截断备注。普通退出登录关闭数据库、移除当前身份，草稿保留在原账号数据库；删除整个账号数据库会随文件移除草稿，本轮没有新增账号删除操作。
